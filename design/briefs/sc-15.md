## 0. 창업자 지시: 하드 제약 (모든 화면에 적용, 2026-11-10, #33 승인 코멘트)

```text
첫 조건: 기능은 빠짐없이, 화면은 단순하게, 인지부하는 최소로.
- 이 화면이 맡은 기능은 하나도 빼지 않는다. 빼는 것은 "보이는 양"이지 기능이 아니다.
- 기본 화면에는 주 행동 하나와 지금 필요한 정보만 보인다.
- 나머지 기능은 단계적으로 드러낸다(진행형 공개). 숨은 기능마다 어디서 어떻게 여는지(단추, 접힘, 메뉴, 단축키)를 화면에 그리고 기능 목록과 화면 위치 대응표를 함께 낸다.
```

어긴 아트보드는 승인하지 않는다.

1. **기능을 빼서 단순하게 만들지 않는다.** 3절의 기능 전부가 최대 2단계 안에서 닿는다. **정직성 요소(L0 문구, 배지, 가정, "스케줄 없음" 문구, 막음/알림 글자)는 단순함을 이유로 줄이지 않는다**(V1). 충돌해 보이면 접되 이름과 개수는 항상 보인다.
2. **기본 화면(S1)의 상시 조작 요소는 9개**이고 5.1절에 이름을 못 박았다. 다른 아트보드도 10개 이하다. 세는 법(SC-01·SC-02와 같다): 버튼, 입력, 선택 컨트롤(분할 컨트롤은 하나), 접기·펼치기 머리, 누를 수 있는 값·증거 배지, 누를 수 있는 목록 행이 각각 1. 읽기 전용 글자, 단위, 구분선, 행 안의 읽기 전용 `L0` 칩은 세지 않는다. 패널 바깥(상단바 등)은 세지 않는다.
3. **패널·카드·도구줄 안에 `primary` 버튼은 없다.** `primary`는 상단바의 모드 주 행동 하나(조립 모드 `실행하기`)뿐이다. 이 화면의 행동(`적용`, `다시 연결`, `점검 보기`)은 `secondary`·`ghost`, 지우기는 `danger`다.
4. **한 번에 한 수준만 연다.** 패널의 열린 머리는 하나(아코디언)이고 뷰포트 위 카드는 한 번에 하나다. 같은 정보를 두 곳에 반복하지 않는다.
5. **뷰포트가 주인공이다.** 뷰포트 위 2D 요소는 불투명 `color.bg.panel` 면의 작은 칩·카드이고 가운데를 가리지 않는다. 부품 선택도 끌기도 없을 때는 하나도 없다.
6. **색은 성공·실패를 뜻하지 않는다**(5.2절). "실행을 막음"과 "알림"은 색이 아니라 **글자 + 모양**으로 가른다. `color.status.*`는 시스템 오류와 입력·검증 거부 테두리에만 쓴다.

## 1. 대목표와 핵심 가치

대목표 G1: 창업자가 세 행성 어디서든 상상한 물건을 만들어 정직한 판정이 붙은 Halo로 내보낸다. 이 화면이 없으면 B-08, B-09, B-10, B-11, B-13, B-14, B-16, X-09, X-11, C-07의 구현이 참조할 승인본이 없다.

> **V3 한 번에 100%** — 작은 단위를 증거와 함께 완전히 끝낸다. 부분 완성은 미완성이다.

> **V1 정직한 판정** — 판정은 시뮬과 몬테카를로만 한다. 확률, 가정, 한계를 숨기지 않는다. 1회 미리보기 실행을 판정이라 부르지 않는다.

V1은 조립 단계의 모든 값이 **L0 해석 계산이고 판정이 아니라는 표시**, 배지, 가정으로, V3은 DoD의 상태를 하나도 빠뜨리지 않고 그리는 것으로 나타난다.

|---|---|---|

| ② 오른쪽 패널 `인스펙터` | SC-02에 머리 `배치 · 표시`(자세 수치와 표시 색 한 행), 분리기 선택 때의 분리 항목, "정의 없음" 변형이 더해진다 | 부품 선택 시 자동(SC-01 공개 지도 그대로) |
| ③ 뷰포트 위 2D | **도구줄**(왼쪽 위): 각도 스냅, 대칭. **배치 안내 카드**(위 가운데): 붙을 위치, 거부 사유 | 도구줄은 부품을 선택했거나 끌 때만. 카드는 끄는 중·거부 때만. 아래쪽은 SC-03 변경안 카드 자리라 비운다 [제안] |

- 패널 틀은 SC-01·SC-02 그대로다: 제목 하나, 열린 머리 하나, 필드 행(라벨 · 값(`type.mono`) · 단위 · 값 배지, 높이 `size.control.md`), 값은 Enter 확정·Esc 취소, 확정 뒤 "이전 → 새 값"과 `되돌리기`, 검증 거부는 `color.status.danger` 테두리 + 이유 한 줄. 새 행 변형을 만들지 않는다.
- `조립 보조` 패널 머리에는 증거 칩 `▮▯▯▯ L0 해석 계산`(`color.evidence.l0`)이 있고 누르면 근거 팝오버가 열린다: "L0 조립: 질량, 무게중심, 정역학 경고, 추력중심·추력선, 행성별 추력 대 중량비와 연소 시간 · 해석 계산 · 판정이 아닙니다".
- 실행을 막는 점검이 있으면 상단바 `실행하기`는 `aria-disabled`(포커스 가능)이고 누르면 이유 팝오버가 열린다(S16). 진짜 `disabled`로 이유를 못 읽게 하지 않는다 [제안].

## 4. 정직성 규칙

### 4.1 공통

- 이 화면의 계산값은 **모두 L0 해석 계산이고 판정이 아니다.** 패널 머리의 L0 칩과 "판정이 아닙니다"를 접거나 숨기지 않는다. 확률·`p_success`는 이 화면에 없다.
- 모든 수치는 값 · 단위 · 값 배지. 무차원은 단위 `–`. 예시 수치는 `design-system.md` 10절의 값(1.3 t `사용자 선언`, 8.9 N `인용`, 노즐당 8 kN `카탈로그 밖 · 사용자 선언`)과 `예시` 꼬리표가 붙은 것만 쓴다. 각도 스냅 단위, 대칭 상한, 임계 하중, 추력 대 중량비, 좌표는 모두 `예시`다.
- **추력 대 중량비(B-14)의 배지는 가장 약한 입력의 배지**다. 추력 읽기 값(B-13)은 `시뮬` 값 아래 한 줄에 입력 추력의 배지를 따로 보인다. 입력 배지 강도의 순서는 정해지지 않았다 [확인 필요: X-07]. 팝오버에 입력별 배지를 모두 적는다.
- 에이전트는 점검·추력·추력 대 중량비를 판정하지 않는다("L0 점검: …", "시뮬 계산: …"). 엔진이 끊기면 `시뮬` 값에 "오래됨 · 마지막 계산 시각 [예시]"를 붙이고 가짜 값으로 채우지 않는다.

### 4.2 금지 사항: 다른 제품에서 가져오지 않는다 (`kerbal-space-program.md` 5절)

- 표식의 **기능**(무게중심, 추력중심, 대칭, 스냅)은 일반 개념이라 배운다. **다른 제품의 이름·화면 이름·메뉴 문구·고유 용어·아이콘·로고, 스냅 노드와 표식의 모양과 색(초록 공, 체크무늬 구 등), 색 구성, 수치(각도 스냅 단위 포함)는 쓰지 않는다.** 5절이 든 예: 천체·종족·부품·제조사 이름, 시설·화면 이름, "Engineer's Report", "Action Groups", "Staging", "Time warp". 우리 용어만 쓴다: 조립 보조, 실행 전 점검, 무게중심, 추력중심, 추력선, 방사 대칭, 분리기, 정의 없음.
- 각도 스냅 단위와 대칭 개수 상한은 우리가 정하는 `기본값`이다(B-09, B-11). 시안의 값은 `예시`다. 패널 안 글리프는 디자인 시스템 아이콘이나 단순 도형(점, 선, 십자, 사각)만 쓴다. 3D 표식의 모양과 색은 이 브리프가 정하지 않는다.
- **색은 성공·실패를 뜻하지 않는다.** 점검 줄은 모두 `color.evidence.l0` 계열이고 막음/알림은 글자 `실행을 막음`/`알림` + 모양(막음 ■, 알림 ○) + 정렬(막음이 먼저)로 가른다. 추력 대 중량비가 1보다 커도 모양·문구가 같고 "뜬다/못 뜬다"고 쓰지 않는다. 걸린 항목이 없어도 초록 확인 표시를 그리지 않는다.

### 4.3 화면별 규칙

- **배치 안내**: 거부는 아이콘(⊘) + 라벨 `붙지 않음` + 사유 문장(색만으로 알리지 않는다). `color.status.danger`는 카드 테두리에만. 붙을 수 있을 때는 중립 `color.accent.primary` 선택 표시이고 성공색이 아니다. 파단 임계는 항상 "단순화 모델"과 함께, 필드가 비면 `임계 없음`만 쓴다.
- **추력**: 켜진 추력기만으로 계산한다(전부 더하지 않는다). 합력 0인 짝힘은 추력중심 없이 토크만. 추력기가 없으면 "추력기 없음"(0·가짜 값 없음). 스케줄이 없으면 정확히 **"스케줄 없음: 모든 추력기 최대 추력 기준"**, 소모에 따른 무게중심 이동을 반영하지 않으면 "추진제 가득 기준"(X-06) [확인 필요: X-01c].
- **추력 대 중량비**: 지구·화성·달 세 값을 항상 이 순서로 동시에, 읽기 전용. 현재 행성은 글자 `현재`(색이 아니다). 추력기가 없으면 머리 없이 "추력기 없음". 연소 시간은 한 번만, 추진제나 소모율이 없으면 값 없이 사유. 가정: 추진제 가득, 최대 추력, 대기에 따른 추력 변화 없음, 평지의 균일 중력("근사: 균일 중력(행성별 g 하나)", W-06).
- **실행 전 점검**: 같은 원인은 한 줄(대상 수 `×2`). 줄 순서는 `L0` 칩 → `실행을 막음`/`알림` → 문구 → 대상. 줄을 누르면 부품·결합이 뷰포트에서 강조된다(패널은 "뷰포트에서 강조 중" 한 줄만). 자동 수정 없이 해결 안내 한 줄. 걸린 게 없으면 "이 점검이 보는 범위에서 걸린 항목이 없습니다. 판정이 아닙니다". 컴파일 오류(X-01d)와 정의 없음은 `실행을 막음`, 정역학 경고·추력 점검·분리기와 추력기의 같은 시점 작동(X-09)은 `알림` [제안: 분류는 X-11].
- **자세 입력**: 겹치는 값은 저장하지 않고 검증기의 사유를 필드에 보인다. 스냅 결합 부품은 허용된 자유도만 고치고 나머지는 잠금 + "스냅 결합으로 고정". 기준 좌표계를 읽기 전용 글자로 쓴다(SC-02 수정 2와 같은 표기). 수치 입력이 각도 스냅을 따르는지는 정해지지 않았다 [확인 필요: B-09, B-10]. 시안은 따르지 않는 것으로 그린다 [제안].
- **시각 전용 색**: 재질 물성과 다른 필드이고 `시각 전용` 태그가 항상 붙는다. 증거 색(`color.evidence.*`)과 같은 색은 견본에 없고 직접 입력하면 사유와 함께 거부된다. 견본은 사용자 데이터라 새 색 토큰이 아니다.
- **분리**: 사양은 질량, 치수, **선언 분리 충격량 [N·s]**(0 허용)뿐이고 `사용자 선언`/`기본값` 배지가 붙는다. 에너지원(화약, 가스, 스프링 등) 필드와 문구는 없다. "단순화 모델: 선언 분리 충격량"이 항상 붙는다. 분리 항목은 제어 스케줄의 한 줄이고 단 번호 목록은 없다. 같은 분리기의 두 번째 분리는 거부된다.
- **정의 없음**: 형상·질량·관성을 지어내지 않는다(칸은 `–`와 "정의 없음"). 자세와 결합 참조는 읽기 전용으로 보인다 [확인 필요: 배지는 C-06]. 하나라도 있으면 `실행하기`·`판정 실행`·`내보내기`가 빠진 정의 ID 목록과 함께 막힌다. 공유 플레이 페이지(SC-09)는 같은 표시에 편집·재연결·지우기가 없고 기록된 궤적 재생은 막지 않으며 다시 실행만 막는다.

## 6. 규칙

- 이 화면은 증거 색으로 `color.evidence.l0` 칩만 쓴다. 패널은 `elevation.1`, 뷰포트 위 칩·카드는 불투명 `color.bg.panel` + `color.border.default`.
- 모든 텍스트 대비 4.5:1, 비문자 3:1, 누르는 영역 24×24 px 이상, 포커스 링 2 px `color.focus.ring` + 2 px 간격. `prefers-reduced-motion`이면 머리 접힘·카드 등장은 불투명도 전환만. 카드는 저절로 사라지지 않고 닫을 때까지 남는다.
- 키보드로 모든 행동: 머리·줄은 Enter/Space, `Esc`는 팝오버·편집·카드를 닫는다. 점검 목록은 화살표 키로 줄을 옮긴다. 배치 안내 카드는 `aria-live="polite"`로 읽어 주고 포커스를 옮기지 않는다. 막음/알림은 모양이 아니라 글자로도 읽힌다.
- 색은 `tokens.json`의 값만. 새 색 토큰 금지. 초록 성공·빨강 실패 금지.
- 금지 문구: `design-system.md` 9절 전체. 특히 "현실과 동일", "검증됨", "보장", 점검·추력 대 중량비를 "판정"·"통과"·"뜬다/못 뜬다"로 부르기, 에이전트의 판정 선언.

## 7. 이 브리프가 정하지 않는 것

3D 안의 고스트·스냅 표식·추력중심·추력선·무게중심 표식·"정의 없음" 자리표시의 모양과 색(코드 프로토타입), 각도 스냅 단위와 대칭 상한의 값과 단축키(B-09, B-11), 점검 항목의 전체 종류와 막음/알림 분류(X-11), 추력·추력 대 중량비 계산(X-06, X-07), 정의 없음의 코어 규칙(C-06), 평면 대칭의 평면 고르기(B-05c), 분리 표식(SC-06), 공유 플레이 페이지 전체(SC-09), 에이전트의 빠진 구성 안내(G-09).

**[확인 필요] SC-02와의 상한:** SC-02 S1은 차체(관절 2, 액추에이터 1) 선택에서 상시 조작 요소가 이미 10개다. 여기에 패널 전환기 1개와 `배치 · 표시` 머리 1개가 더해지면 12개가 되어 창업자 지시(10 이하)를 넘는다. 이 브리프는 S12를 관절·액추에이터 없는 부품(빔)으로 그려 10개를 맞췄다(S12 (a)의 조작 요소 10개 = 접기, 패널 전환기, 질량 입력, 질량 배지, 재질 선택, 재질 배지, 질량중심 배지, 관성 보기, 재질 세부, `배치 · 표시`). 차체처럼 관절·액추에이터가 있는 부품에서 어느 머리를 합칠지는 SC-02 승인 때 창업자가 정한다.
