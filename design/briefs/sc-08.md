## 0. 창업자 지시: 하드 제약 (모든 화면에 적용, 2026-11-10, #33 승인 코멘트)

> **첫 조건: 기능은 빠짐없이, 화면은 단순하게, 인지부하는 최소로.**
> - 이 화면이 맡은 기능은 하나도 빼지 않는다. 빼는 것은 "보이는 양"이지 기능이 아니다.
> - 기본 화면에는 주 행동 하나와 지금 필요한 정보만 보인다.
> - 나머지 기능은 단계적으로 드러낸다(진행형 공개). 숨은 기능마다 어디서 어떻게 여는지(단추, 접힘, 메뉴, 단축키)를 화면에 그리고 기능 목록과 화면 위치 대응표를 함께 낸다.

어긴 아트보드는 승인하지 않는다. 이 브리프에서는:

1. **기능을 빼서 단순하게 만들지 않는다.** 3절 표의 모든 행이 닿는 곳이 있어야 한다.
2. **주 행동은 화면마다 하나이고 끝까지 같다.** SC-08은 상단바 `내보내기`(SC-01의 Halo 모드 `primary`). SC-09는 `▶ 재생` 하나이고 상태에 따라 라벨만 바뀐다. 카드·팝오버 안의 버튼은 `secondary`나 `ghost`다.
3. **기본 화면의 상시 조작 요소는 SC-08 10개, SC-09 10개 이하**이고 5.1절에 이름을 못 박았다. 세는 법은 SC-01·SC-04 브리프와 같다.
4. **한 번에 한 수준만 연다.** 자막 줄, 시도 고르기, 카메라 세부, 내레이션은 접힌 머리 뒤에 있고 한 번에 하나만 열린다(아코디언) [제안].
5. **정직성 요소는 단순함을 이유로 줄이지 않는다**(V1). 판정 자막은 끌 수 없고, 판정이 없으면 "판정 없음: 1회 실행"이 남는다. 충돌해 보이면 편집 도구(길이, 카메라)를 접고 정직성 줄은 접지 않는다.
6. **같은 정보를 두 곳에 반복하지 않는다.** 확률은 SC-08에서 판정 공개 자막 한 곳, SC-09에서 판정 카드 한 곳에만 큰 글자로 나온다.
7. **증거 색은 증거의 강도다.** 초록 성공·빨강 실패, 신호등, 히트맵 없음. 실패한 시도는 ▲ + 원인 문구 + 증거 단계 색이고, 선택 표시는 `color.accent.primary`다.

## 1. 대목표와 핵심 가치

대목표 G1: 창업자가 세 행성 어디서든 상상한 물건을 만들어 정직한 판정이 붙은 Halo로 내보낸다. 이 두 화면은 판정이 영상과 링크로 **밖으로 나가는** 자리다. 없으면 H-02, H-02a, H-03b가 참조할 승인된 디자인이 없다.

> **V3 한 번에 100%** — 작은 단위를 증거와 함께 완전히 끝낸다. 부분 완성은 미완성이다.

> **V1 정직한 판정** — 판정은 시뮬과 몬테카를로만 한다. 확률, 가정, 한계를 숨기지 않는다. 1회 미리보기 실행을 판정이라 부르지 않는다.

V1은 끌 수 없는 판정·가정 자막, "판정 없음: 1회 실행", "표본 중 하나", 엔드카드의 시도 횟수로 나타난다(계획 위험 4: 확률 0.8%짜리 장면을 성공 영상으로 내고 싶어진다). 이 화면이 지키는 V4(연출은 카메라·조명·편집만 바꾸고 궤적은 바꾸지 않는다)는 "궤적 해시 같음" 표시로 나타난다.

### 2.1 SC-08: Halo 모드 (SC-01 셸 안)

```
┌ 상단바 48: 프로젝트명 │ 행성 │ [조립|실행|판정|Halo] │ 증거 배지 │ …… │ [내보내기] 공유 ⋯ ┐
├──────────┬────────────────────────────────────────────┬──────────────────────┤
│ 라이브러리 │ 미리보기 16:9 (장면 자리 표시 + 자막 판)       │ 구간 편집 (320)       │
│ (접힘 40) │                                            │ 질문                  │
│          │  [▶ 미리보기]                               │ 길이 [5.0] s 기본값   │
│          │                                            │ 카메라 [추적|고정|…]  │
│          │                                            │ ▸ 자막 · 3줄         │
│          │                                            │ ▸ 더 보기            │
├──────────┴────────────────────────────────────────────┴──────────────────────┤
│ 궤적 해시 같음 · 편집은 길이·카메라·자막만 바꿉니다                              │
│ 구간 줄 120: [질문 5 s][시도 12 s · 3건][판정 공개 6 s][엔드카드 4 s]      ▶    │
└──────────────────────────────────────────────────────────────────────────────┘
```

- **구간은 네 개로 고정**(질문 → 시도 → 판정 공개 → 엔드카드). 추가·삭제·순서 바꾸기는 없다(자유 편집은 범위 밖). 폭은 길이에 비례. 숫자는 모두 `예시`.
- 구간 줄은 SC-01의 타임라인(Halo 모드에서 펼침) 자리다. 오른쪽 패널은 선택한 구간 하나를 편집한다. SC-01은 Halo 모드의 오른쪽 패널을 레일로 두었으나 **이 화면이 구간 편집 패널로 연다**(폭 320 그대로) [제안].
- 미리보기는 `color.bg.app` 위 장면 자리 표시와 라벨 "장면은 코드 프로토타입 · 기록된 궤적 재생"뿐이다. 자막은 불투명한 `color.bg.panel` 판 위에 올린다. 증거 배지(상단바)는 영상에 담긴 판정의 단계이고, 판정이 없으면 "판정 없음: 1회 실행"이다.

- 설치도 계정도 없다. **다시 시뮬하지 않고 기록된 궤적을 재생**한다(5절 결정론 [확인 필요]). 이 한 줄은 상시 보인다.

## 4. 정직성 규칙

- **판정 자막은 끌 수 없다.** `FEASIBLE_FOUND`는 p_success + 95% CI + 표본 수(`시뮬`) + 핵심 가정, 나머지 셋은 판정별 문구와 "확률 미산출 · 이유"와 가정이다. 끄는 스위치가 없고 `자막` 머리 안 해당 줄에 잠금 + "판정의 한계를 영상에서 뺄 수 없습니다". 핵심 가정을 고르는 규칙은 H-02b가 정한다 [확인 필요]: 디자인은 2~3줄 자리와 줄마다 값·단위·배지(`카탈로그 밖 · 사용자 선언` 등)를 그린다.
- **판정이 없으면** 판정 공개 구간은 사라지지 않고 내용이 "판정 없음: 1회 실행"이 된다 [제안]. 확률·CI·가정표 자리에 숫자나 빈칸이 없다. "된다/안 된다", "성공 확인"을 쓰지 않고 "이번 실행에서는 …"(`design-system.md` 9절).
- **성공 장면에는 "표본 중 하나"가 붙는다**(판정 유무와 무관, H-02b, H-06).
- **실패한 시도는 J-06의 원인과 시점으로 말한다**: 전복, 슬립, 토크 부족, 추진제 고갈, 파단("단순화 모델"), 분류되지 않음. 시점은 s + `시뮬`. 에이전트가 판정이나 원인을 선언하는 문구가 없다. ▲(파단 ✕) + 증거 단계 색이고 `color.status.*`를 쓰지 않는다.
- **무효 판정은 자막으로 쓰지 않는다.** `color.evidence.none` + "무효: 다시 판정해야 합니다"이고 이전 확률을 큰 글자로 남기지 않는다.
- **편집은 궤적을 바꾸지 않는다.** 길이, 카메라, 자막, 내레이션만. 내보내기 전후 궤적 해시가 다르면 내보내기를 막는다(H-04, S14). 예시 수치는 `design-system.md` 10절의 값뿐이고 나머지(길이, 시도 수, 시점, 해시)는 `예시` 꼬리표를 붙인다.

## 6. 규칙

- 증거 색은 5.2절 그대로다. 같은 L2면 15.2%든 0.8%든 같은 색. 판정 4종의 구분은 코드, 문구, 모양으로.
- 모든 수치는 `값 · 단위 · 값 배지`(길이 `5.0 s` `기본값`/`사용자 선언`, 시점 `3.2 s` `시뮬`, 건수는 "건" + `시뮬`).
- 대비 4.5:1(비문자 3:1), 24×24 px 이상, 포커스 링 2 px + 2 px 간격, `prefers-reduced-motion`이면 불투명도 전환만. 미리보기·리플레이는 자동 재생하지 않고 멈춤 수단(`⏸`)을 둔다(WCAG 2.2.2) [제안]. 키보드로 모든 행동, `Esc`는 팝오버·편집을 닫는다.
- 새 색 토큰, 로고, 일러스트, 마케팅 문구, 음악, 효과음 없음. 금지 문구는 `design-system.md` 9절 전체.

## 7. 엔드카드 상태: 시도 횟수 (H-06, PC-02)

엔드카드(16:9, 불투명 판)의 순서: 증거 단계 → 판정 코드와 한 줄(판정 없음이면 "판정 없음: 1회 실행") → **시도 횟수 줄** → L3 "실물 검증 없음" → 프로젝트·행성 라벨. 확률은 판정 공개 구간에 이미 나왔으므로 엔드카드에 반복하지 않는다 [제안].

| 상태 | 시도 구간 | 엔드카드 시도 횟수 줄(수치는 `예시`) |
|---|---|---|
| E1 | 실패한 시도를 **넣어서** 내보냄 | "기록된 시도 성공 1 / 전체 3 · 영상에 3건 모두 있음" [제안: 같은 줄을 유지] |
| E2 | 실패한 시도가 있는데 **빼고** 내보냄 | **"기록된 시도 성공 1 / 전체 3 · 영상에는 1건만 있음"**. 필수, 끌 수 없음(H-06 DoD) |
| E3 | 판정 없음(1회 실행)에서 위 두 경우 | "판정 없음: 1회 실행" + 위와 같은 줄 |

- n은 성공 조건을 충족한 기록된 시도, m은 기록된 시도 전체이고 **단위는 "건", 배지는 `시뮬`**이다. 라벨 "기록된 시도"가 몬테카를로 표본(n = 500)과 구별되게 하고, 둘을 한 줄에 섞지 않는다 [제안]. n·m의 범위(이 설계 버전의 기록된 실행 전부인지 탐색 롤아웃 전부인지)는 H-06 구현에서 정한다 [확인 필요]. 디자인은 라벨과 자리만 그린다.
- 줄에는 끄는 컨트롤이 없고 잠금 + "빠진 시도를 영상에서 숨길 수 없습니다". 편집 중에는 엔드카드 구간 카드에 "시도 횟수 표시됨"이 보인다.
- 실패한 시도가 없는 프로젝트에서 줄을 둘지는 [확인 필요]. 계획은 "빼면 엔드카드에 시도 횟수가 남는다"만 말한다.

## 8. 이 브리프가 정하지 않는 것

구간 길이의 범위와 의미(H-02a), 핵심 가정 선택 규칙(H-02b), 시도 n·m의 범위(H-06), 3D 장면과 카메라 조작, 영상 렌더링, 번들 형식·크기(H-03a, A0-02c), 전환 계측 고지(H-03c), 공유 링크 도메인·만료, 대결 모드 고정 문구 자리(S2, CB-07), 의도 인터뷰의 질문(H-05), "정의 없음" 표시 자체(SC-15), 판정 카드 내부(SC-04), Studio 셸(SC-01), 3행성 비교(SC-07).

## 9. `/design`에 붙여 넣을 프롬프트

```text
Kinetra Studio의 화면 SC-08 "Halo 편집기"와 SC-09 "공유 플레이 페이지"를 한 프로젝트로 디자인해 줘. 규격은 저장소의 design/briefs/sc-08.md 전문이다. 규격과 이 요약이 다르면 규격이 이긴다. 토큰과 컴포넌트는 design/exports/design-system/(tokens.css, tokens.json, source/*.dc.html)을, 셸(상단바, 모드 전환기, 타임라인 자리)은 design/exports/sc-01/을, 플레이 페이지의 판정 카드는 design-system의 VerdictCards와 design/briefs/sc-04.md의 카드를 그대로 쓴다. 판정 카드를 다시 정의하지 않고 새 색·새 컴포넌트를 만들지 않는다.

첫 조건: 기능은 빠짐없이, 화면은 단순하게, 인지부하는 최소로.
- 이 화면이 맡은 기능은 하나도 빼지 않는다. 빼는 것은 "보이는 양"이지 기능이 아니다.
- 기본 화면에는 주 행동 하나와 지금 필요한 정보만 보인다.
- 나머지 기능은 단계적으로 드러낸다(진행형 공개). 숨은 기능마다 어디서 어떻게 여는지(단추, 접힘, 메뉴, 단축키)를 화면에 그리고 기능 목록과 화면 위치 대응표를 함께 낸다.
sc-08.md 0절의 하드 제약을 지킨다. 주 행동은 화면마다 하나이고 상수다(SC-08은 상단바 "내보내기", SC-09는 "재생" 계열 하나). 기본 화면(SC-08 S1, SC-09 P1)의 상시 조작 요소는 5.1절의 10개이고 이름이 일치한다.

규칙: 정직성 요소는 줄이지 않는다. 판정 자막은 끌 수 없다(끄는 컨트롤 없음, 잠금 + 이유). 판정이 없으면 판정 공개 구간·엔드카드·플레이 페이지에 "판정 없음: 1회 실행"(빈칸·0%·– 금지). 성공 장면에는 "표본 중 하나". 빼고 내보내면 엔드카드에 "기록된 시도 성공 n / 전체 m"이 남는다(E1~E3). 판정 4종의 확률·민감도 자리는 design-system.md 5.1절 표 그대로. 편집은 궤적을 바꾸지 않는다. 증거 색은 증거의 강도다(초록=성공/빨강=실패, 신호등, 히트맵 금지). 모든 수치는 값·단위·값 배지, 예시 수치는 design-system.md 10절의 값뿐이고 나머지는 "예시". 플레이 페이지는 기록을 재생하고 다시 시뮬하지 않으며 값 편집은 막고 배지 근거 조회는 막지 않는다. 금지 문구: "현실과 동일", "검증됨", "보장", 1회 실행을 판정이라 부르기, NOT_FOUND_IN_BUDGET/모델 밖을 "불가능"이라 쓰기, 에이전트의 판정 선언. WCAG 2.2 AA, 키보드로 모든 조작, 자동 재생 없음 + 멈춤 수단. 브라우저 측정은 /tmp 아래 임시 --user-data-dir를 쓴 헤드리스 Chrome으로만 한다.

만들 것: sc-08.md 5절의 아트보드 SC-08 S1~S18(1440×940), SC-09 P1~P10(P9만 390×844). 엔드카드 E1~E3는 S8에. S1·S3·S5·S8·P1·P3를 가장 정확히.
만들지 않을 것: 3D 장면, 영상 렌더링, 판정 카드 내부 재정의, 밝은 테마, 로고, 마케팅, 음악·효과음.

내보내기: ./design/exports/sc-08/ 에 독립 실행 HTML(index.html, 외부 요청 없음)과 source/(*.dc.html, canvas.json, 내보내기 스크립트), NOTES.md(artifact URL, 아트보드 목록, 자기 점검 표, 브리프에서 벗어난 곳).
끝나면 자기 점검을 표로 보고해 줘(sc-08.md 0절 표 + 3절 기능 단계 + 엔드카드 E1~E3 + 판정 없음 표시 위치).
```
