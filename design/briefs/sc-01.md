# 화면 브리프 SC-01: Studio 셸

> 이슈 #36 [D0-03a]. 근거는 `docs/plan/studio-plan.md` 3절, 4.1절(화면 구조), 4.5절(증거), 4.6절(행성 전환), 7절이다. 토큰과 공통 컴포넌트는 승인된 `design/exports/design-system/`(v0)을 그대로 쓴다. 이 브리프는 그 위에 **화면 배치**를 정한다.
>
> 표기: **[제안]** 이 브리프가 새로 내는 기준(치수, 문구 포함)이다. 창업자와 Claude Design이 고칠 수 있다. **[확인 필요]** 채택 전에 확인할 사실이다. 값 배지 5종, 증거 4단계와 고정 문구, 금지 문구는 디자인 시스템 브리프(`design-system.md` 4·5·9절)가 정한 대로이고 여기서 바꾸지 않는다.
>
> 범위: Studio 셸의 배치와 상태다. 3D 뷰포트 **안**의 상호작용(기즈모, 스냅, 고스트)은 Claude Design이 아니라 코드 프로토타입으로 검증한다(4.7). 인스펙터 내부(SC-02), 에이전트 바와 변경안 카드 내부(SC-03), 판정 카드 내부(SC-04)는 각 브리프가 정한다. 이 화면은 그것들이 들어갈 **자리와 열리는 방식**까지만 정한다.

## 0. 창업자 지시: 하드 제약 (모든 화면에 적용, 2026-11-10, #33 승인 코멘트)

> **기능은 빠짐없이, 화면은 단순하게.** 기본 화면에는 주 행동 하나와 필요한 정보만 보이고, 나머지 기능은 단계적으로 드러낸다(진행형 공개). 인지부하를 최소로 한다.

이 지시를 이 브리프의 첫 조건으로 두고, 아래를 **하드 제약**으로 푼다. 어긴 아트보드는 승인하지 않는다.

1. **기능을 빼서 단순하게 만들지 않는다.** 3절의 기능 목록 전부가 어느 화면에서든 최대 2단계(클릭이나 키 입력 2번) 안에서 닿는다. 기능이 없어 보이게 하는 것은 실패다.
2. **기본 화면의 상시 조작 요소는 14개 이하다.** 세는 법: 버튼, 입력 필드, 전환기(분할 컨트롤·탭 묶음은 **하나**), 목록(**하나**), 누를 수 있는 배지가 각각 1이다. 읽기 전용 글자, 단위, 구분선, 레일 아이콘 장식은 세지 않는다. 기본 화면은 "조립 모드, 아무것도 선택하지 않음, 변경안 없음" 상태(아트보드 S1)다. 5.1절에 14개의 이름을 못 박았다.
3. **`primary` 버튼은 한 화면에 하나다.** 모드가 바뀌면 그 하나가 모드의 주 행동으로 바뀐다(2절).
4. **진행형 공개:** 숨긴 것은 3절 "공개 지도"의 방법으로만 드러난다. 설명 없이 사라지는 요소, 호버로만 보이는 필수 요소는 없다. 모든 공개는 키보드로 된다.
5. **한 번에 하나의 수준의 정보만 말한다.** 한 패널에 제목 하나, 섹션은 3개를 넘기지 않는다. 같은 정보를 두 곳에 반복하지 않는다.
6. **정직성 표시는 단순함을 이유로 줄이지 않는다.** 증거 배지, L1 고정 문구, L3 "실물 검증 없음", 수치의 단위와 배지는 항상 보인다. 이것들은 "필요한 정보"다(V1).

| 점검 | 기준 |
|---|---|
| 상시 조작 요소 수 | 아트보드 S1~S9 각각의 수를 적는다. S1은 14 이하이고 5.1절의 이름과 일치 |
| `primary` 버튼 수 | 모든 아트보드에서 정확히 1 (엔진 오프라인에서는 비활성이지만 1개 남는다) |

| 기능 도달 단계 | 3절 기능 목록의 모든 행이 0·1·2단계 중 어디서 닿는지 적고 2 초과가 없다 |

| 금지 | 새 색 토큰이 없다. 초록 성공·빨강 실패가 없다. 금지 문구가 없다(`design-system.md` 9절) |

## 1. 대목표와 핵심 가치

대목표 G0: 모든 작업이 대목표·핵심 가치·계획에 묶여 한 번에 100% 끝나는 루프를 만든다. 이 셸은 G1(창업자가 세 행성 어디서든 상상한 물건을 만들어 정직한 판정이 붙은 Halo로 내보낸다)의 모든 작업이 일어나는 화면이다. 이 화면이 없으면 UI 구현 이슈(C-04)가 참조할 승인된 배치가 없다.

> **V1 정직한 판정** — 판정은 시뮬과 몬테카를로만 한다. 확률, 가정, 한계를 숨기지 않는다. 1회 미리보기 실행을 판정이라 부르지 않는다.

> **V2 상상에서 현실까지** — 모든 기능은 생각 → 상상 → 실제 물리 세계의 거리를 줄여야 한다.

V1은 증거 배지와 L1·L3 고정 문구가 모든 모드에서 보이는 것으로, V2는 생각(에이전트 입력) → 상상(뷰포트, 고스트) → 현실에 가까운 판정(증거 단계)이 한 화면 안에서 끊기지 않고 이어지는 것으로 나타난다.

## 2. 구조와 방향

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ 상단바 48px: 프로젝트명 │ 행성 │ 모드 │ 증거 배지 │ …공간… │ [주 행동] 공유 ⋯ │
├────────┬─────────────────────────────────────────────┬───────────────────────┤
│라이브러리│                                             │ 인스펙터 / 판정 (선택·│
│ 240px  │            3D 뷰포트 (자리 표시)             │ 모드에 따라 열림) 320 │
│ (접힘 40)│                                             │       (접힘 40)       │
├────────┴─────────────────────────────────────────────┴───────────────────────┤
│ 에이전트 바 56px: [🎤] 입력창 ………… (변경안 카드는 이 바 위로 올라온다)        │
│ 타임라인 32px(접힘) / 120px(펼침): ▶ ⏸ ↺ │ 표식 │ 판정 카드 열기 │ L3 줄       │
└──────────────────────────────────────────────────────────────────────────────┘
```

- 뷰포트가 가장 넓고 가장 눈에 띈다. 이 화면에서 Claude Design이 그리는 것은 **자리 표시**다: `color.bg.app` 위의 평지 선과 라벨 "3D 뷰포트 · 코드 프로토타입으로 검증"뿐이다. 가짜 부품, 가짜 3D 그림, 일러스트는 그리지 않는다.
- 패널 치수 [제안]: 왼쪽 240, 오른쪽 320, 접힌 레일 40, 상단바 48, 에이전트 바 56, 타임라인 접힘 32 / 펼침 120(px). 기준 화면은 1440×900이다. 패널 너비 조절 중 상태는 그리지 않고 6절에 말만 한다.
- 상단바 안의 순서와 간격: 왼쪽에 `프로젝트명 · 행성 전환기 · 모드 전환기 · 증거 배지`, 오른쪽 끝에 `주 행동 · 공유 · 더보기`다 [제안].
- **모드는 네 개다:** 조립(물리 꺼짐), 실행(미리보기 1회), 판정(탐색 + 몬테카를로), Halo(카메라·자막·내보내기). 모드마다 `primary` 하나가 바뀐다.

| 모드 | 증거 배지 | `primary` 문구 | 타임라인 | 오른쪽 패널 |
|---|---|---|---|---|
| 조립 | L0 조립 | `실행하기` | 접힘 | 선택 있으면 인스펙터, 없으면 레일 |
| 실행 | L1 미리보기, 문구 "1회 실행. 판정이 아닙니다" | `▶ 1회 실행` | 펼침 | 인스펙터(읽기 전용 값 포함) |
| 판정 | 판정이 있으면 L2, 없으면 "판정 없음" | `판정 실행` | 펼침 | 판정 카드(SC-04) |
| Halo | 담긴 판정의 단계. 판정이 없으면 "판정 없음: 1회 실행" | `내보내기` | 펼침 | 레일 |

## 3. 기능 목록과 공개 지도

| 기능 | 단계 | 닿는 방법 |

### 3.2 공개 지도: 숨긴 것이 드러나는 때

| 숨긴 것 | 드러나는 때와 방법 | 닫을 때 |
|---|---|---|
| 인스펙터 | 부품을 선택하면 오른쪽 패널이 펼쳐진다(`motion.duration.base`) | 선택을 풀면 레일로. 사용자가 직접 접으면 다음 선택 때까지 접힌 채 |
| 타임라인 | 실행·판정·Halo 모드로 들어가면 펼쳐진다. 조립 모드에서는 32px 한 줄 | 조립으로 돌아오면 접힘 |
| 변경안 카드 | 에이전트가 변경안을 내면 에이전트 바 위로 올라온다 | 수락·거절·`Esc` |
| 판정 카드 | 판정 모드 진입, 또는 타임라인 `판정 카드 열기` | 다른 모드로 가거나 접기 |
| 증거 배지 근거 | 배지를 누르면 팝오버 | `Esc` |
| 더보기·공유 | 버튼을 누르면 메뉴·팝오버 | `Esc`, 바깥 클릭 |
| 부품 검색 | `/` 또는 목록을 누르면 필드가 나타남 | `Esc` |
| 가져오기 | "내 것" 탭 | 탭 이동 |
| 행성 전환 뒤 안내 | 행성을 바꾸면 상단바 아래에 한 줄 안내가 생김 | 닫기 또는 다음 판정 실행 |

## 4. 증거 표시 (정직성 고정 요소)

- **증거 배지**는 상단바에 상시 있다. 구성은 강도 막대 4칸 + 단계 코드 + 이름이다(`design-system.md` 5.1절). 누르면 팝오버에 그 단계의 화면 문구, 근거, 그리고 **L3 "실물 검증 없음"(현재 0건)** 이 보인다.
- **L1 문구**: 실행 모드에서 "1회 실행. 판정이 아닙니다"가 상단바 배지 옆과 타임라인에 접히지 않고 남는다. 좁아지면 `1회 실행 · 판정 아님`으로 줄이되 없애지 않는다.
- **L3 줄**: 타임라인 줄(접힘 상태 포함) 오른쪽 끝에 읽기 전용 글자로 `L3 실물 검증 없음`을 모든 모드에서 보인다. 실측이 0건이어도 숨기지 않는다. 이 글자는 조작 요소가 아니라서 14개에 세지 않는다.
- **판정이 없으면 "판정 없음"** 이라고 쓴다. 가짜 확률을 넣지 않는다. 조립·실행 모드에는 `p_success`를 그리지 않는다.
- 행성을 바꾸면 이전 판정은 **무효**: 배지를 `color.evidence.none`으로 내리고 "무효: 다시 판정해야 합니다"를 붙이며 한 줄 안내가 뜬다(`design-system.md` 5.1절, 6절 행성 전환기).
- 증거 색은 성공·실패가 아니라 증거의 강도다(`design-system.md` 5.2절). 이 화면의 어떤 요소도 초록·빨강으로 결과를 말하지 않는다. 판정 모드의 L2 예시는 아래 7절의 값만 쓴다.

## 5. 상태: 그려야 할 아트보드

기준 화면 1440×900, 어두운 테마 하나. 아트보드마다 위쪽에 이름을 적고, 한국어 UI다. 컴포넌트는 디자인 시스템(`design/exports/design-system/`의 `tokens.css`와 `source/*.dc.html`)의 것을 쓰고 새 컴포넌트를 만들지 않는다. 새 값이 꼭 필요하면 목록으로 보고한다.

### 5.1 S1 기본: 조립 모드, 선택 없음, 변경안 없음

상시 조작 요소 14개(이름 고정):

| # | 요소 | 위치 |
|---|---|---|
| 1 | 프로젝트 이름 | 상단바 |
| 2 | 행성 전환기(지구·화성·달, 하나로 센다) | 상단바 |
| 3 | 모드 전환기(조립·실행·판정·Halo) | 상단바 |
| 4 | 증거 배지(L0 조립) | 상단바 |

| 9 | 라이브러리 탭(기본 부품·내 것) | 왼쪽 패널 |

| 13 | 마이크 | 에이전트 바 |

- 오른쪽 패널은 접힌 레일(40px)이고 안내 글자는 없다. 뷰포트가 그만큼 넓다.
- 타임라인은 32px 한 줄: 왼쪽에 `타임라인`, 가운데는 비어 있고 "조립 중에는 물리가 꺼져 있습니다", 오른쪽 끝에 `L3 실물 검증 없음`.
- 부품 목록의 항목은 카탈로그 부품의 이름과 한 줄 사양이다. 사양 수치에는 단위와 `인용` 배지가 붙는다. 수치는 10절 값(`design-system.md`)만 쓰고, 다른 수치에는 `예시`를 붙인다.

### 5.2 나머지 아트보드

| ID | 상태 | 보여줄 것 |
|---|---|---|
| S2 | 조립, 부품 하나 선택 | 오른쪽 패널이 열려 있다(내용은 SC-02 자리 표시: 제목 "인스펙터", 선택 이름, 질량 `1.3 t` · `사용자 선언`, 행 하나뿐인 요약). 상시 조작 요소 수와 증가분을 적는다 |
| S3 | 실행 모드, 1회 실행 뒤 | `primary`는 `▶ 1회 실행`. 배지 L1, "1회 실행. 판정이 아닙니다" 상시. 타임라인 펼침: `▶ ⏸ ↺`, 시간 눈금, 실패 표식 ▲ 하나(원인 라벨은 `전복`처럼 모양 + 글자, `예시`), `판정 카드 열기`. 판정을 암시하는 글자는 없다 |

| S5 | 판정 모드, L2 `FEASIBLE_FOUND` | 오른쪽 패널에 판정 카드 요약(내용은 SC-04 자리 표시): 배지 L2, 판정 코드와 한 줄, `15.2%` `[12.3, 18.6]` `n = 500` `시뮬`, 민감도 1위 한 줄 "노즐별 추력 잡음" + "가정표 · 이 모델이 보지 않는 것" 열기 링크. 같은 수치만 쓰고 색은 L2 보라다 |
| S6 | Halo 모드, 판정 없음 | `primary`는 `내보내기`. 패널은 레일. 캡션 "판정 없음: 1회 실행"이 미리보기 자리 아래에 보인다. 자막 편집은 SC-08이라 그리지 않는다 |
| S7 | 패널 접힘 변형 | 위 5개 중 하나를 골라 (a) 왼쪽만 접힘 (b) 오른쪽 열림 + 왼쪽 접힘 (c) 모두 접힘(뷰포트 최대, 에이전트 바와 상단바는 남는다)을 나란히 보여 준다. 접힌 레일은 아이콘 + 툴팁 이름 + 키보드 포커스 |

변경안 카드가 올라온 상태는 SC-03 브리프가 그린다. 이 화면은 카드가 에이전트 바 **위로** 올라오고 뷰포트를 가리는 높이 상한이 있다는 것만 정한다: 카드 영역의 최대 높이는 뷰포트 높이의 40% [제안].

## 6. 규칙

- **뷰포트가 주인공이다.** 패널은 뷰포트보다 조용하다(`elevation.1`). 장식, 그라디언트, 히어로, 마케팅 느낌 없음.
- **좁은 화면:** 너비 1280 미만이면 오른쪽 패널이 자동으로 레일이 되고 선택 시 뷰포트 위에 겹쳐 열린다(불투명 `color.bg.panel`). 1024 미만은 지원하지 않는다 [확인 필요].
- 패널 너비는 끌어서 조절할 수 있고(조절 중 상태는 디자인 시스템 패널 컴포넌트와 같다) 접힘 상태는 프로젝트마다 기억한다 [제안].
- 숫자에는 단위와 배지가 항상 붙는다. 이 화면에 새로 지어낸 수치는 `예시`를 붙인다.
- 모든 텍스트 대비 4.5:1, 비문자 3:1, 누르는 영역 24×24 px 이상. 포커스 링은 2 px `color.focus.ring` + 2 px 간격. `prefers-reduced-motion`이면 패널 접힘·펼침은 불투명도 전환만(디자인 시스템 3.7절).
- 스크린리더: 증거 단계가 바뀌면 문구를 읽어 준다("L1 미리보기. 1회 실행. 판정이 아닙니다"). 모드 전환기는 탭 목록, 행성 전환기는 라디오 그룹이다.
- 금지 문구: `design-system.md` 9절 전체. 특히 "현실과 동일", L1을 "판정/성공/통과"로 부르기, 에이전트가 판정을 선언하는 문구, `NOT_FOUND_IN_BUDGET`을 "불가능"으로 쓰기.

## 7. 예시 데이터

`design-system.md` 10절의 값만 쓴다: 차체 질량 1.3 t(`사용자 선언`), 냉가스 추력기 카탈로그 최대 추력 8.9 N(`인용`), 노즐당 추력 8 kN(`카탈로그 밖 · 사용자 선언`), `p_success` 15.2% [12.3, 18.6] n = 500 (L2, `시뮬`, 노즐당 8 kN, 추력 잡음 없음), 0.8% [0.3, 2.0] n = 500 (노즐별 추력 잡음 ±10%). 이 표에 없는 수치는 `예시`를 붙인다. 부품 이름은 상표 없는 일반 이름(차체, 바퀴, 냉가스 추력기, 빔, 모터, 점프대)만 쓴다.

## 8. 이 브리프가 정하지 않는 것

인스펙터 필드 상세(SC-02), 에이전트 바 상태와 변경안 카드(SC-03), 판정 카드·가정표·민감도(SC-04), 라이브러리와 가져오기 마법사(SC-05), 실행 HUD와 실패 리포트(SC-06), 3행성 비교(SC-07), Halo 편집기(SC-08), 공유 플레이 페이지(SC-09), 시작 화면(SC-10), XR(SC-11). 3D 뷰포트 안의 상호작용. 공유 팝오버의 세부(D1).
