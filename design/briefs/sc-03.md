# 화면 브리프 SC-03: 에이전트 바와 변경안 카드

> 이슈 #38 [D0-03c]. 근거는 `docs/plan/studio-plan.md` 4.3절(입력 모드, 음성), 4.4절(에이전트와의 협업), 4.2절 플로우 A(변경안 카드 넷), 12절의 G-01(LLM 예산), G-03(변경안)이다. 토큰과 공통 컴포넌트(에이전트 바, 변경안 카드)는 승인된 `design/exports/design-system/`(v0)을, 셸 안의 자리(하단 에이전트 바 56 px, 변경안 카드 영역은 바 위로 올라오며 최대 높이는 뷰포트 높이의 40%)는 승인된 `design/exports/sc-01/`을 그대로 쓴다.
>
> 표기: **[제안]** 이 브리프가 새로 내는 기준이다. **[확인 필요]** 채택 전에 확인할 사실이다. 값 배지 5종과 이름, 증거 4단계, 금지 문구는 `design-system.md` 4·5·9절 그대로이고 여기서 바꾸지 않는다.
>
> 범위: 에이전트 바와 변경안 카드의 배치와 상태다. 3D 뷰포트 안의 고스트와 질량·무게중심 오버레이는 코드 프로토타입이 맡는다(4.7). 이 화면은 카드가 말하는 "고스트가 뷰포트에 뜬다"는 사실을 글로만 적고 그리지 않는다.

## 0. 창업자 지시: 하드 제약 (모든 화면에 적용, 2026-11-10, #33 승인 코멘트)

> **기능은 빠짐없이, 화면은 단순하게.** 기본 화면에는 주 행동 하나와 필요한 정보만 보이고, 나머지 기능은 단계적으로 드러낸다(진행형 공개). 인지부하를 최소로 한다.

어긴 아트보드는 승인하지 않는다.

1. **기능을 빼서 단순하게 만들지 않는다.** 3절의 기능 목록 전부가 최대 2단계 안에서 닿는다. 특히 변경안 카드의 [미리보기] [수락] [부분 수락] [거절] 네 행동과 되돌리기가 모두 있다.
2. **기본 화면(S1: 입력 대기)의 상시 조작 요소는 2개**: 마이크, 입력창이다. 문맥 칩은 부품을 선택했을 때만 생기고, 보내기는 Enter이며 `보내기` 버튼은 글자를 입력하면 나타난다 [제안]. 5.1절에 이름을 못 박았다. 세는 법은 SC-01 브리프 0절 2번과 같다(버튼, 입력, 선택 컨트롤, 누를 수 있는 배지가 각각 1. 읽기 전용 글자는 세지 않음).
3. **한 시점에 카드 영역에는 변경안 카드 1장만 펼쳐 보인다.** 변경안이 여러 건이면(플로우 A는 4건) 한 줄 요약 탭으로 이어 보고 한 번에 한 장만 연다(진행형 공개). 카드 안의 `primary` 버튼은 없다(`design-system.md` 6절: [수락]은 `secondary`). 이 화면의 `primary`는 상단바의 모드 주 행동 하나뿐이다.
4. **진행형 공개:** 기본은 요약(제목, 한 줄 설명, 수치 변화 3행)까지만 보이고, 명령 목록·검증기 상세·비용 내역은 접힌 머리 뒤에 있다. 숨은 것은 접힌 머리의 이름과 개수("명령 7개")로 존재가 보인다.
5. **같은 정보를 두 곳에 반복하지 않는다.** 한 카드에 제목 하나.
6. **정직성 표시는 줄이지 않는다.** 에이전트가 낸 수치에도 값 배지(`추정` 등)가 붙고, 카탈로그 밖 값은 "카탈로그 밖 · 사용자 선언"이 붙는다. 에이전트는 판정을 선언하지 않는다.

### 자기 점검 (Claude Design이 끝에 표로 보고)

| 점검 | 기준 |
|---|---|
| 상시 조작 요소 수 | 아트보드마다. S1은 2개이고 5.1절의 이름과 일치 |
| `primary` 버튼 수 | 카드와 에이전트 바 안에 0. 상단바가 그려진 아트보드에서는 정확히 1 |
| 기능 도달 단계 | 3절 표의 모든 행이 0·1·2단계 중 어디서 닿는지. 2 초과 없음 |
| 상태 | 5절의 상태 아트보드 전부. 변경안 카드 4행동과 되돌리기가 모두 어느 아트보드에 있는지 |
| 정직성 | 단위·배지 없는 수치 0건. 에이전트가 판정을 선언하는 문구 0건. 금지 문구 0건 |
| 금지 | 새 색 토큰 0. 초록 성공·빨강 실패 없음(`status.danger`는 오류·검증 거부에만) |

## 1. 대목표와 핵심 가치

대목표 G0: 모든 작업이 대목표·핵심 가치·계획에 묶여 한 번에 100% 끝나는 루프를 만든다. 에이전트 바는 G1에서 "생각 → 상상"의 입구이고 변경안 카드는 그 제안을 사람이 미리 보고 수락하는 자리다. 이 화면이 없으면 G-07 에이전트 바 UI가 참조할 승인된 디자인이 없다.

> **V1 정직한 판정** — 판정은 시뮬과 몬테카를로만 한다. 확률, 가정, 한계를 숨기지 않는다. 1회 미리보기 실행을 판정이라 부르지 않는다.

> **V2 상상에서 현실까지** — 모든 기능은 생각 → 상상 → 실제 물리 세계의 거리를 줄여야 한다.

V1은 에이전트가 판정을 선언하지 않고 수치에 배지가 붙는 것으로, V2는 말 한마디가 고스트와 수치 변화가 있는 미리보기로 이어지는 것으로 나타난다.

## 2. 구조

```
┌ 변경안 카드 영역(있을 때만, 바 위로 올라옴, 최대 높이 = 뷰포트의 40%) ───────────┐
│ [1 차체와 바퀴] [2 추력기 배치] [3 점프대] [4 성공 조건]      ← 요약 탭(한 장만 펼침) │
│ 제목 · 한 줄 설명 · 명령 n개 ▸                                                    │
│ 질량 1.3 t → 1.8 t [사용자 선언]  무게중심 …  부품 수 …    ← 수치 변화 3행        │
│ [미리보기] [수락] [부분 수락] [거절]                                              │
├──────────────────────────────────────────────────────────────────────────────────┤
│ [🎤] 입력창 …………………………………………………………  (글자를 쓰면 [보내기])   [상태 한 줄] │  56 px
└──────────────────────────────────────────────────────────────────────────────────┘
```

- 카드 영역은 SC-01의 셸에서 바 위로 올라온다. 높이 상한(뷰포트의 40%)을 넘으면 카드 본문이 스크롤된다. 카드가 3D 뷰포트를 전부 가리지 않는다.
- 에이전트 상태 한 줄은 바의 오른쪽 끝(읽기 전용 글자): 대기 / 생각 중 / 검증기 재시도 n/N / 변경안 n건 / 실패. 상태 글자는 조작 요소가 아니다.
- 문맥 칩("선택: 차체")은 사용자가 뷰포트에서 부품을 고른 경우에만 입력창 앞에 생긴다. 칩은 누르면 선택을 푸는 조작 요소 하나다.
- 입력은 모두 같은 편집 명령(Command)이 된다(4.3절). 텍스트와 음성은 같은 경로이고 음성은 인식문을 확인한 뒤에만 전송된다.

## 3. 기능 목록: 어디서 닿는가 (0 = 기본 화면에 보임, 1 = 한 번, 2 = 두 번)

| 기능 | 단계 | 닿는 방법 |
|---|---|---|
| 텍스트로 요청 | 0 | 입력창, Enter |
| 음성으로 요청 | 0 | 마이크 버튼 |
| 음성 인식문 확인(보내기 · 고치기 · 취소) | 1 | 마이크로 말한 뒤 자동으로 열림 |
| 선택 문맥으로 요청("이것만 더 가볍게") | 0 | 부품을 고르면 칩이 생김 |
| 변경안 보기(요약) | 0 (생기면) | 바 위에 카드가 올라옴 |
| 변경안 여러 건 보기 | 1 | 요약 탭 |
| 미리보기(고스트 + 수치 변화) | 1 | 카드의 `미리보기` |
| 수락 | 1 | 카드의 `수락` |
| 부분 수락(명령별 선택) | 2 | `부분 수락` → 명령별 체크박스 → 적용 |
| 거절 | 1 | 카드의 `거절` |
| 수락한 변경 되돌리기 | 1 | 수락 직후 카드 줄의 `되돌리기`, 또는 `⋯` 메뉴(SC-01) |
| 명령 목록 보기 | 1 | 카드의 접힌 머리 "명령 7개" |
| 검증기 거부와 재시도 상태 | 0 (생기면) | 상태 한 줄과 카드의 접힌 머리 |
| 삭제류 명령 확인 | 1 | 확인 대화상자(삭제 대상 이름 포함) |
| 예산 안내와 한도 | 0 (한도 근처) / 1 | 상태 한 줄 "예산 n% 사용", 누르면 내역 |
| 에이전트 실행 취소(생각 중 취소) | 1 | 상태 한 줄의 `취소` |

## 4. 정직성 규칙

- **에이전트가 하는 것/하지 않는 것**(4.4절): 부품 추가·배치·결합, 파라미터·재질 변경, 제어 스케줄 초안, 탐색·판정 **실행 요청**은 한다. 판정 선언, 행성 상수·물성 DB 변경, 카탈로그에 없는 사양을 있는 것처럼 쓰기는 하지 않는다. 화면 문구는 "시뮬 결과: …", "롤아웃 수치만 인용"의 형태이고 "에이전트가 가능하다고 판정했습니다"류는 없다.
- 변경안 카드의 수치(질량, 무게중심, 부품 수)는 값 · 단위 · 배지. 엔진이 계산한 값은 `시뮬`, 에이전트가 어림한 값은 `추정`, 카탈로그 밖 값(예: 노즐당 추력 8 kN)은 `카탈로그 밖 · 사용자 선언`(`design-system.md` 10절). 새로 지어낸 수치는 `예시`.
- 카탈로그에 없는 부품 사양을 에이전트가 제안하면 카드에 "카탈로그 밖 · 사용자 선언" 배지가 붙고 수락할 때 사용자가 선언하는 값이 된다는 한 줄이 보인다 [제안].
- 음성은 인식문을 **확인한 뒤에만** 보낸다. 삭제류 명령은 별도 확인 단계(대상 이름 + `삭제` / `취소`)를 둔다. 한국어 인식 품질은 [확인 필요](계획 4.3절).
- 오류가 아닌 것: 검증기가 겹침·공중에 뜬 부품·무효 스냅·스키마 위반을 거부하는 것은 "시스템 오류"가 아니라 "재시도 중" 상태다(`status.danger`를 쓰지 않는다). 정해진 횟수를 다 써도 못 만들면 그때 오류 상태(실패)다 [제안].
- 예산 초과는 오류가 아니라 한도 도달이다(`status.warning`, 시스템 상태). "예산 초과로 요청을 거절했습니다" 문구와 남은 것(내역 보기, 한도 설명). 결과를 숨기거나 가짜 변경안으로 채우지 않는다.

## 5. 상태: 그려야 할 아트보드

기준: 폭 1200 px(셸 하단 영역) × 높이는 상태별(바 56 + 카드 영역 상한 306). 아트보드마다 위에 한 줄 이름과 상시 조작 요소 수. 어두운 테마 하나, 한국어 UI. 카드와 바는 디자인 시스템의 것을 그대로 쓴다.

### 5.1 S1 기본: 입력 대기(변경안 없음, 선택 없음)

상시 조작 요소 2개(이름 고정): ① 마이크 ② 입력창. 입력창 안에 안내 글자 "에이전트에게 요청하기"와 읽기 전용 힌트 "Enter 보내기". 상태 한 줄: "대기". 칩·보내기·카드 없음.

### 5.2 나머지 아트보드

| ID | 상태 | 보여줄 것 |
|---|---|---|
| S2 | 텍스트 입력 중 | 글자가 들어가 `보내기` 버튼이 나타남(조작 요소 3). 문맥 칩 "선택: 차체"가 있는 변형 한 줄 |
| S3 | 음성: 듣는 중 → 받아쓰는 중 → 인식문 확인 | 세 단계를 나란히. 인식문 확인은 `보내기` `고치기` `취소` 3개와 인식문 텍스트 입력. 권한 거부, 지원 안 됨 변형은 각각 한 줄(오류가 아니라 안내 문구 + 텍스트 입력으로 이어짐) |
| S4 | 에이전트 생각 중 | 상태 한 줄 "생각 중" + `취소`. 입력창은 읽기 전용이 아니라 다음 요청을 쓸 수 있다 [제안]. 변경안 없음 |
| S5 | 변경안 카드: 제안됨(1/4) | 요약 탭 4개(차체와 바퀴, 추력기 배치, 점프대 소품, 성공 조건), 첫 탭 펼침. 제목, 한 줄 설명, "명령 7개 ▸", 수치 변화 3행(질량 `1.3 t → …`는 `예시`, 무게중심, 부품 수 각각 이전 → 이후 · 단위 · 배지), 4행동. `primary` 없음 |
| S6 | 미리보기 중 | 카드 위쪽에 "미리보기 중 · 뷰포트에 고스트가 표시됩니다"(글만, 고스트는 그리지 않음). 4행동 중 `미리보기`는 `미리보기 끄기`로 바뀜. `Esc`로 끄기 |
| S7 | 부분 수락 | 명령 7개 목록이 열리고 명령마다 체크박스. 적용할 개수 요약("5개 적용"), `적용` `취소` |
| S8 | 수락됨 | 카드가 한 줄로 줄고 "수락됨 · 명령 7개 적용" + `되돌리기`. 거절됨과 되돌림(취소됨) 변형 한 줄씩 |
| S9 | 카탈로그 밖 값을 담은 카드 | 노즐당 추력 8 kN `카탈로그 밖 · 사용자 선언` 행과 안내 한 줄. 카탈로그 밖이라는 사실이 가려지지 않게 |
| S10 | 검증기 재시도와 실패 | (a) 재시도 중: 상태 "검증기 재시도 2/3", 거부 이유 한 줄(예: 겹친 부품), 카드 없음 (b) 정해진 횟수를 넘겨 실패: 오류 상태(`status.danger` 아이콘 + 문구 + 복사할 코드 + 다음 행동 `다시 요청`). 부품 수치는 예시 |
| S11 | 예산 | (a) 80% 사용 안내(`status.info`, 한 줄) (b) 예산 초과: `status.warning` 한 줄 + "예산 초과로 요청을 거절했습니다" + `내역 보기`. 예산 수치는 `예시`와 단위(원이 아니라 토큰 또는 호출 수 [확인 필요: G-01이 정함]) |
| S12 | 삭제 확인 | 삭제류 명령의 확인 대화상자: 삭제 대상 이름, `삭제`(`danger` 변형) / `취소`. 대화상자에는 `primary`가 없다 |
| S13 | 키보드 | S5 위에 탭 순서(입력창 → 마이크 → 칩 → 요약 탭 → 카드 행동 4개)와 포커스 링, `Esc`는 미리보기·팝오버를 닫음 주석 |

## 6. 규칙

- 한 번에 카드 1장. 4건이면 탭 4개(탭 목록, 화살표 키 이동)이고 접힌 탭은 제목만 보인다.
- 카드 안에 `primary` 없음. [수락]은 `secondary`. `danger`는 삭제 확인과 입력 검증 거부 같은 파괴적 동작에만.
- 모든 텍스트 대비 4.5:1, 비문자 3:1, 누르는 영역 24×24 px 이상, 포커스 링 2 px `color.focus.ring` + 2 px 간격. `prefers-reduced-motion`이면 카드 등장·접힘은 불투명도 전환만.
- 키보드로 모든 행동. `Esc`는 미리보기·팝오버·인식문 확인을 닫는다. 변경안 카드 네 행동은 모두 Tab으로 닿는다. 단축키는 툴팁에 적는다.
- 스크린리더: 변경안이 생기면 "변경안 4건"을 읽어 준다. 상태 바뀜(생각 중 → 변경안)도 읽는다.
- 색은 `tokens.json`에 있는 값만. 새 색 토큰 금지. 초록 성공·빨강 실패 금지.

## 7. 이 브리프가 정하지 않는 것

고스트·질량중심 오버레이(코드 프로토타입), 인스펙터(SC-02), 판정 카드(SC-04), LLM 예산의 단위와 한도(G-01), 도구 스키마(G-02), 검증기가 거부하는 규칙의 전체 목록(C-02c), 한국어 음성 인식 엔진(XR-04 등), XR 안의 변경안 카드(SC-11).
