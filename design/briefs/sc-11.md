## 0. 창업자 지시: 하드 제약 (모든 화면에 적용, 2026-11-10, #33 승인 코멘트)

> **기능은 빠짐없이, 화면은 단순하게.** 기본 화면에는 주 행동 하나와 필요한 정보만 보이고, 나머지 기능은 단계적으로 드러낸다(진행형 공개). 인지부하를 최소로 한다.

첫 조건(`docs/process/design-workflow.md`의 "브리프의 첫 조건" 그대로. 이 브리프와 `/design` 프롬프트의 첫 조건이다):

```text
첫 조건: 기능은 빠짐없이, 화면은 단순하게, 인지부하는 최소로.
- 이 화면이 맡은 기능은 하나도 빼지 않는다. 빼는 것은 "보이는 양"이지 기능이 아니다.
- 기본 화면에는 주 행동 하나와 지금 필요한 정보만 보인다.
- 나머지 기능은 단계적으로 드러낸다(진행형 공개). 숨은 기능마다 어디서 어떻게 여는지(단추, 접힘, 메뉴, 단축키)를 화면에 그리고 기능 목록과 화면 위치 대응표를 함께 낸다.
```

어긴 아트보드는 승인하지 않는다. 헤드셋 안은 타자가 안 되고 정밀 입력이 어렵다(4.3절). 그래서 데스크톱보다 **더 적게 보이고 더 크게 누른다**.

1. **기능을 빼서 단순하게 만들지 않는다.** 3절의 기능 전부가 최대 2단계 안에서 닿는다. XR이 못 하는 정밀 수치 편집은 기능을 지운 것이 아니라 "데스크톱에서 편집" 줄로 존재를 보인다.
2. **기본 화면(S1)의 상시 조작 요소는 8개 이하**이고 5.1절에 이름을 못 박았다. 세는 법은 SC-01 브리프 0절 2번과 같다(버튼, 입력, 선택 컨트롤, 접기·펼치기 머리, 누를 수 있는 배지가 각각 1. 분할 컨트롤은 하나, 목록은 하나. 읽기 전용 글자는 세지 않음).
3. **`primary` 버튼은 공간 전체에 하나다.** 손목 팔레트의 `실행하기`(SC-01과 같은 문구)이고 실행 보기에서는 같은 자리에서 `▶ 1회 실행`으로 바뀐다. 변경안 카드의 `수락`, 인식문의 `보내기`를 포함한 나머지는 `secondary`·`ghost`·`danger`다.
4. **동시에 열린 표면은 3개 이하 [제안].** ① 손목 팔레트 ② 정보 패널(증거 띠 + 인스펙터 요약) ③ 에이전트 패널(인식문 확인과 변경안 카드가 한 자리를 번갈아 쓰며 카드는 한 장).
5. **한 번에 한 수준만 연다.** 명령 목록, 가정표, "이 모델이 보지 않는 것", 더보기는 접힌 머리 뒤에 있고 머리의 이름과 개수("명령 7개", "가정 4개")로 존재가 보인다.
6. **정직성 표시는 줄이지 않는다.** 증거 띠, L1 고정 문구, L3 "실물 검증 없음", 수치의 단위와 배지는 XR의 모든 상태에 남는다(V1).
7. **헤드셋에 맞춘 단순함 [제안]:** 글자와 눌림 영역을 키우고(2.1절), 되돌릴 수 없는 동작(삭제)에는 확인을, 수락에는 `되돌리기`를 붙인다.

## 1. 대목표와 핵심 가치

대목표 G0: 모든 작업이 대목표·핵심 가치·계획에 묶여 한 번에 100% 끝나는 루프를 만든다. XR 패널은 G1에서 헤드셋 안에서도 "생각 → 상상 → 손으로 조립 → 정직한 판정"이 끊기지 않게 하는 자리다. 이 화면이 없으면 XR-03 구현이 참조할 승인된 디자인이 없다.

> **V1 정직한 판정** — 판정은 시뮬과 몬테카를로만 한다. 확률, 가정, 한계를 숨기지 않는다. 1회 미리보기 실행을 판정이라 부르지 않는다.

> **V2 상상에서 현실까지** — 모든 기능은 생각 → 상상 → 실제 물리 세계의 거리를 줄여야 한다.

V1은 공간에서도 접히지 않는 증거 띠와 "1회 실행. 판정이 아닙니다"로, V2는 손목에서 부품을 꺼내고 말 한마디가 변경안 카드가 되는 흐름으로 나타난다. (V5의 값 배지 규칙도 따른다: `design-system.md` 4절.)

## 2. 구조

세 표면이다. 아래 그림은 **구성**이고 놓이는 위치가 아니다.

```
┌ 손목 팔레트 ──────────────┐  ┌ 정보 패널 ───────────────┐  ┌ 에이전트 패널(있을 때만) ┐
│ [기본 부품 | 내 것]  접기 │  │ ▮▯▯▯ L0 조립 (증거 띠)    │  │ 음성: 인식문 확인         │
│ 부품 목록 (집어 꺼내기)   │  │ L3 실물 검증 없음         │  │ 변경안: 카드 1장 + 탭     │
│ [되돌리기] [⋯] [마이크]   │  │ ── 선택이 있을 때만 ──    │  │ [미리보기] [수락]         │
│ [실행하기] ← primary 하나 │  │ 인스펙터 요약 · 판정 줄   │  │ [부분 수락] [거절]        │
└──────────────────────────┘  └──────────────────────────┘  └─────────────────────────┘
```

- **손목 팔레트:** 펼침(기본)과 접힘(손목 띠: `펼치기` `마이크` `실행하기` 3개). 목록, `되돌리기`, `⋯`(다시 실행 · 복제 · 삭제 · 작업대 크기 · 손 바꾸기), 마이크, `실행하기`를 갖는다. 어디까지 손목에 붙고 어디부터 공간에 떠 있는지는 코드 프로토타입이 정한다.
- **정보 패널:** 증거 띠가 **항상** 있다(XR의 증거 배지, 이 패널에 하나뿐). 부품을 잡거나 가리켜 선택하면 그 아래에 인스펙터 요약이 펼쳐진다.
- **에이전트 패널:** 음성 인식문 확인과 변경안 카드가 번갈아 쓴다. 인식문과 카드가 동시에 뜨지 않는다.
- **입력 [제안]:** 손 추적은 핀치, 컨트롤러는 트리거로 "누르기"를 하고 결과는 같다. 눌림은 **뗄 때** 확정하고(누르는 중 포인터가 벗어나면 취소) 호버만으로 실행되는 동작은 없다. 목업은 "누르기"로만 쓴다.
- 모든 동작은 데스크톱과 같은 편집 명령(Command)이 된다(4.3절).

### 2.1 XR 크기 스케일 [제안]

토큰 **이름과 색은 그대로**이고 크기만 키운다. px는 목업 기준이고 실제 공간 크기(mm, 각도)와 읽는 거리는 코드 프로토타입과 실기 시험(XR-07)이 정한다 [확인 필요]. 새 크기 값은 쓴 만큼 목록으로 보고한다(새 **색** 토큰은 0).

| 항목 | 데스크톱 | XR 목업 |
|---|---|---|
| 눌림 영역 최소 | 24 × 24 | **48 × 48** (권장 56), 사이 간격 8 이상 |
| 글자 | 본문 13, caption 11 | 본문·라벨 18, caption 16, 수치(mono) 20, 제목 24, `p_success` 40 |
| 값 배지 | 높이 20 | 높이 32, 누르는 영역 48 |
| 패널 폭 | 320 | 손목 팔레트 360, 정보 패널 480, 에이전트 패널 560 |

- 면은 불투명한 `color.bg.panel`이다(3D 장면이 비치지 않게, `design-system.md` 3.6절). 포커스와 포인터 호버는 2 px `color.focus.ring` + 2 px 간격의 링으로 같이 그린다 [제안].

| 판정 실행, 가정 편집 | — | XR 범위 밖(데스크톱 SC-04). 있는 판정을 보여 주기만 한다 [제안] |

## 4. 정직성 규칙

- **증거 띠는 모든 상태에서 보인다**(강도 막대 4칸 + 코드 + 이름, `design-system.md` 5.1절). L1이면 "1회 실행. 판정이 아닙니다"가 띠 안에 있고 좁으면 `1회 실행 · 판정 아님`으로 줄이되 없애지 않는다. L3 "실물 검증 없음"(0건)은 `color.evidence.none`으로 항상 있다. 판정이 없으면 "판정 없음"이고 가짜 확률은 없다.
- **판정은 데스크톱과 같은 문구와 구성이다**(XR-03b). 확률·민감도 자리는 `design-system.md` 5.1절 표 그대로: `FEASIBLE_FOUND`만 `p_success` + 95% CI + 표본 수와 민감도 1위, 나머지 셋은 `확률 미산출 · 이유` / `민감도 미산출 · 이유` + 판정별 내용(어긴 필요조건과 여유 / 쓴 탐색 예산 + "약한 증거" / 모델이 다루지 않는 현상). **가정표와 "이 모델이 보지 않는 것"과 L3는 네 판정 모두에 붙는다.** XR 요약이라도 이름과 개수가 보이는 접힌 머리로 둔다. 이를 뺀 축약형은 없다(`design-system.md` 6절).
- 가정이 바뀐 판정은 **무효**다(`color.evidence.none` + "무효: 다시 판정해야 합니다", 이전 확률을 큰 글자로 남기지 않음). 진행 중은 "진행 중 · 아직 판정이 아닙니다". 증거 색은 증거의 강도라서 확률이 달라도 같은 L2는 같은 색이고 초록 성공·빨강 실패·신호등·히트맵은 없다.
- 모든 수치는 값 · 단위 · 값 배지다. 예시는 `design-system.md` 10절의 값만 쓴다: 차체 질량 1.3 t `사용자 선언`, 냉가스 추력기 최대 추력 8.9 N `인용`, 노즐당 추력 8 kN `카탈로그 밖 · 사용자 선언`, `p_success` 15.2% [12.3, 18.6] n = 500 `시뮬`(민감도 시연 0.8% [0.3, 2.0] n = 500). 그 밖의 수치와 재질·출처 이름은 `예시` 꼬리표를 붙이고("재질 프리셋 A(예시)") 실제 물성처럼 보이는 값을 지어내지 않는다.
- 변경안의 수치(질량, 무게중심, 부품 수)에도 배지가 붙는다(`시뮬`, `추정`, 카탈로그 밖은 `카탈로그 밖 · 사용자 선언`). 에이전트는 판정을 선언하지 않는다("시뮬 결과: …"만).
- **음성은 인식문을 확인한 뒤에만 전송한다.** 삭제류 명령은 별도 확인(대상 이름 + `삭제`/`취소`)을 둔다. 마이크를 누르는 동안만 듣고 놓으면 즉시 멈추며 "듣는 중" 표시가 보인다. 상시 청취는 없다. 한국어 인식 품질은 [확인 필요](계획 4.3절).
- 검증기 거부(겹침, 공중에 뜬 부품, 무효 스냅)는 오류가 아니라 "재시도 중"이다. 횟수를 다 쓴 실패와 시스템 오류만 `status.danger`, 예산 한도 도달은 `status.warning`이다.
- 엔진 오프라인: 증거 띠에 "엔진 연결 끊김" 칩(`status.warning`) + `다시 연결`, `실행하기` 비활성 + 이유, `시뮬` 값과 판정에 "오래됨 · 마지막 계산 시각 [예시]". 가짜 결과로 채우지 않는다(`design-system.md` 7절).
- 파단 임계 같은 단순화 모델 값은 XR 요약에 없다(데스크톱 인스펙터).
- 금지 문구: `design-system.md` 9절 전체. 헤드셋이라고 "실감", "실제처럼", "현실과 동일"을 쓰지 않는다.

## 5. 상태: 그려야 할 아트보드

기준: `color.bg.app` 위에 평면 패널을 나란히 둔 1920 × 1080 px 판(패널은 2.1절 크기). 아트보드 위쪽에 이름과 상시 조작 요소 수, 왼쪽 아래에 "공간 배치는 코드 프로토타입으로 검증" 한 줄. 어두운 테마 하나, 한국어 UI. 새 컴포넌트를 만들지 않고 한 아트보드에 표면 3개까지만 둔다.

손목 팔레트 펼침 + 정보 패널(증거 띠 L0 조립). 상시 조작 요소 8개(이름 고정):

| 1 | 팔레트 접기 | 손목 팔레트 |

## 6. 규칙

- 대비 글자 4.5:1, 비문자 3:1(WCAG 2.2 AA를 목업에 적용. XR의 기준은 [확인 필요]). 눌림 영역 48 × 48 px 이상. `prefers-reduced-motion`이면 불투명도 전환만. 판정 결과는 어떤 코드든 같은 전환이다.
- 패널을 시선에 고정(head-locked)하지 않는다 [제안: 불편감 방지, 실기 확인 필요]. 패널이 선택한 부품이나 손을 가리는지는 코드 프로토타입이 검증한다.
- 손 추적만으로 모든 행동에 닿고, 핀치가 어려우면 컨트롤러가 같은 일을 한다 [제안]. 음성이 안 되면 데스크톱(SC-03)으로 이어진다는 안내가 있다.
- 색은 `tokens.json`에 있는 값만. 새 색 토큰 금지. `status.danger`는 시스템 오류, 삭제 확인, 입력 검증 거부에만.

## 7. 이 브리프가 정하지 않는 것

패널의 공간 위치·거리·각도·실제 크기와 읽기 편한 거리, 손 추적·컨트롤러 입력 처리, 고스트와 스냅 피드백(XR-02c), 손목을 돌려 팔레트를 여는 감지, 공간 UI 라이브러리 선택(XR-03a가 출처·라이선스를 기록), 실기 가독성(XR-07), 데스크톱 인스펙터 전체(SC-02), 판정 카드와 가정 편집(SC-04), 가져오기와 검색(SC-05), 실행 HUD와 타임라인(SC-06), 상시 청취와 대화형 음성(범위 밖), 한국어 음성 인식 엔진(I-01), LLM 예산의 단위(G-01).
