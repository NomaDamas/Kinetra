> 이슈 #39 [D0-03d]. 근거는 `docs/plan/studio-plan.md` 4.5절(물리 판정 표시), 4.6절(실패 리포트), 12절의 J-04(a 판정 카드 · b 가정표 편집 · c 민감도 표시 · d 실패 리포트 ↔ 타임라인 · e 소요 시간 예산)이다. 토큰과 공통 컴포넌트(판정 카드)는 승인된 `design/exports/design-system/`(v0)을, 셸 안의 자리(오른쪽 패널 320 px, 판정 모드 진입 시 자동으로 열림, SC-01 S5의 판정 요약)는 승인된 `design/exports/sc-01/`을 그대로 쓴다. 이 브리프는 그 요약이 열어 주는 **전체 판정 카드와 그 안의 가정표·민감도**를 정한다.
>
> 표기: **[제안]** 이 브리프가 새로 내는 기준이다. **[확인 필요]** 채택 전에 확인할 사실이다. 값 배지 5종과 이름, 증거 4단계와 고정 문구, 판정 4종의 문구와 구성, 5.2절 규칙(증거 색은 증거의 강도), 금지 문구는 `design-system.md` 4·5·9절 그대로이고 여기서 바꾸지 않는다(계획이 직접 정한 요구다).
>

## 0. 창업자 지시: 하드 제약 (모든 화면에 적용, 2026-11-10, #33 승인 코멘트)

> **기능은 빠짐없이, 화면은 단순하게.** 기본 화면에는 주 행동 하나와 필요한 정보만 보이고, 나머지 기능은 단계적으로 드러낸다(진행형 공개). 인지부하를 최소로 한다.

어긴 아트보드는 승인하지 않는다.

1. **기능을 빼서 단순하게 만들지 않는다.** 판정 카드에 있어야 하는 모든 것(가정표, 민감도, 이 모델이 보지 않는 것, L3 "실물 검증 없음", 시드)이 최대 2단계 안에서 닿는다. **정직성 요소는 단순함을 이유로 줄이지 않는다**(V1, `design-system.md` 9절: 가정표·"이 모델이 보지 않는 것"을 뺀 판정, CI 없는 확률은 금지). 이 두 가지가 충돌해 보이면 요약은 접어도 **존재는 항상 보이게** 하고(접힌 머리의 이름과 개수), 확률과 95% CI, 판정 코드, 증거 배지는 접지 않는다.
2. **기본 화면(S1: `FEASIBLE_FOUND` 판정 카드)의 상시 조작 요소는 8개 이하**이고 5.1절에 이름을 못 박았다. 세는 법(SC-01 브리프 0절 2번과 같다): 버튼, 입력, 선택 컨트롤, 접기·펼치기 머리, 누를 수 있는 값 배지가 각각 1. 읽기 전용 글자, 단위, 구분선, 신뢰구간 막대는 세지 않는다. 카드 바깥(상단바 등)은 세지 않는다.
3. **판정 카드 안에 `primary` 버튼은 없다.** 판정 모드의 `primary`는 상단바의 `판정 실행` 하나뿐이다. 카드 안의 행동(가정 편집, 재판정 요청)은 `secondary`나 `ghost`다.
4. **한 번에 한 수준만 연다.** 기본은 판정 코드와 한 줄, `p_success` + 95% CI + 표본 수, 민감도 1위 한 줄까지다. 가정표 전체, "이 모델이 보지 않는 것" 목록, 시드는 접힌 머리 뒤에 있고 한 번에 하나만 열린다(아코디언) [제안].
5. **같은 정보를 두 곳에 반복하지 않는다.** 한 카드에 제목 하나, 확률은 한 번만 큰 글자로.
6. **증거 색은 증거의 강도다(5.2절).** 확률 구간에 따라 카드 색이 바뀌지 않는다. 초록 성공·빨강 실패, 신호등, 히트맵이 없다.

## 1. 대목표와 핵심 가치

대목표 G0: 모든 작업이 대목표·핵심 가치·계획에 묶여 한 번에 100% 끝나는 루프를 만든다. 판정 카드는 G1에서 "상상한 물건이 이 모델에서 되는가"에 정직하게 답하는 자리다. 이 화면이 없으면 J-04 판정 UI가 참조할 승인된 디자인이 없다.

> **V1 정직한 판정** — 판정은 시뮬과 몬테카를로만 한다. 확률, 가정, 한계를 숨기지 않는다. 1회 미리보기 실행을 판정이라 부르지 않는다.

> **V2 상상에서 현실까지** — 모든 기능은 생각 → 상상 → 실제 물리 세계의 거리를 줄여야 한다.

V1은 판정 카드의 구성(가정표, 민감도, 보지 않는 것, "실물 검증 없음")과 "확률 미산출 · 이유"로, V2는 가정 하나를 고치면 판정이 어떻게 달라지는지 보고 다시 판정하는 흐름으로 나타난다. (V5의 값 배지 규칙도 따른다: `design-system.md` 4절.)

```
│ [▮▮▮▯ L2 판정]  FEASIBLE_FOUND                      │
│ 이 모델에서는 성공 사례를 찾았습니다.               │
│ p_success                                          │

│ ▕▁▁▁▁███▁▁▁▁▁▏ 0–25%                               │  신뢰구간 막대(색은 L2 보라 하나)
│ 민감도 1위: 노즐별 추력 잡음 ▸                      │  ← 판정을 뒤집는 가정 1위(누르면 순위)
├────────────────────────────────────────────────────┤
│ ▸ 가정표 · 가정 4개                                │  접힌 머리들(아코디언, 하나만 열림)
│ ▸ 이 모델이 보지 않는 것 · 4개                     │
│ ▸ 실행 정보 · 시드 · 소요 시간                     │
│ L3 실물 검증 없음 (실측 0건)                       │  읽기 전용, 항상 보임
└────────────────────────────────────────────────────┘
```

- 판정 카드는 SC-01의 오른쪽 패널(320 px) 안에서 스크롤된다. 상단의 코드·확률·CI는 스크롤해도 고정된다 [제안].
- 판정 4종과 확률·민감도 자리는 `design-system.md` 5.1절 표 그대로다. `INFEASIBLE_NECESSARY_CONDITION`, `NOT_FOUND_IN_BUDGET`, 모델 밖은 확률 자리와 민감도 자리에 `확률 미산출 · 이유`, `민감도 미산출 · 이유`를 쓰고, 대신 어긴 필요조건과 여유 / 쓴 탐색 예산과 "약한 증거" / 모델이 다루지 않는 현상을 보인다. 빈칸, `0%`, `–`로 두지 않는다.
- 값 배지: `p_success`와 CI와 표본 수는 `시뮬`. 가정표의 값은 각자의 출처 배지(`인용`, `기본값`, `사용자 선언`, `추정`, 카탈로그 밖은 `카탈로그 밖 · 사용자 선언`).

## 3. 기능 목록: 어디서 닿는가 (0 = 기본 화면에 보임, 1 = 한 번, 2 = 두 번)

| 기능 | 단계 | 닿는 방법 |
|---|---|---|
| 증거 단계, 판정 코드와 한 줄 | 0 | 카드 상단(접지 않음) |
| `p_success` + 95% CI + 표본 수 + 신뢰구간 막대 | 0 | 카드 상단(`FEASIBLE_FOUND`) |
| 민감도 1위 한 줄 | 0 | 카드 상단(`FEASIBLE_FOUND`) |
| 민감도 순위 전체 | 1 | `민감도 1위` 줄을 누르면 순위 목록(가정, 확률 변화) |
| 가정표(값, 분포, 출처, 신뢰도) 보기 | 1 | `가정표` 머리 |
| 가정 값 편집 | 2 | 가정표 행의 값 칸 → 고치면 판정이 `무효`가 되고 `다시 판정` 안내 |
| 가정 분포 편집(고정값 ↔ 분포) | 2 | 가정표 행의 분포 선택 |
| "이 모델이 보지 않는 것"(CFD, 연소, FEM, 열) | 1 | 머리 |
| L3 "실물 검증 없음" | 0 | 카드 하단(접지 않음) |
| 시드, 표본 수, 소요 시간 | 1 | `실행 정보` 머리 |
| 다시 판정 | 1 | 카드의 `다시 판정`(무효일 때 등). 모드의 `primary`는 상단바 `판정 실행` |
| 판정 진행 중(표본 n / N, 경과 시간, 취소) | 0 (진행 중) | 카드 자리에 진행 표시 |
| 소요 시간 예산 설정 | 2 | `실행 정보` 머리 → 예산 선택(예: 빠르게 / 보통 / 넉넉히 [제안]) |
| 실패 리포트 ↔ 타임라인 연결 | 1 | 실패 표식(타임라인)을 누르면 리포트 카드가 열리고, 리포트의 시점을 누르면 타임라인 표식으로 이동 |
| 판정 무효 표시와 이유 | 0 | 카드 상단 띠 |
| 오류(엔진 응답 없음 등) | 0 (생기면) | 카드 자리에 오류 상태 |

## 4. 정직성 규칙

- **확률·95% CI와 민감도는 계산한 판정(`FEASIBLE_FOUND`)에서만, 그때는 반드시 보인다.** 나머지 세 판정은 "미산출 · 이유"를 쓴다. 이유 문구 예(`design-system.md` 5.1절): "필요조건에서 막혀 몬테카를로를 돌리지 않았습니다", "예산 안에서 성공 사례를 찾지 못했습니다", "이 모델이 다루지 않는 현상입니다".
- **가정표와 "이 모델이 보지 않는 것"과 L3 "실물 검증 없음"은 네 판정 모두에 붙는다.** 접힌 머리로 있어도 이름과 개수가 보인다. 이를 뺀 축약형은 만들지 않는다(`design-system.md` 6절).
- 민감도: "판정을 뒤집는 가정 1위"는 **계산한 민감도**에서 나온 것만 쓴다. 시연의 두 확률(15.2% [12.3, 18.6] n = 500 노즐당 8 kN 추력 잡음 없음 / 0.8% [0.3, 2.0] n = 500 노즐별 추력 잡음 ±10%)은 `design-system.md` 10절의 값이다. 시연에서는 "가정 하나(노즐별 추력 잡음)가 성공 확률을 크게 바꿉니다"처럼 **보인 것만** 말하고, 판정 코드가 바뀌지 않는 한 "판정을 뒤집는다"고 쓰지 않는다(D0-02c 리뷰 지적). 두 확률은 같은 L2 색이다.
- `NOT_FOUND_IN_BUDGET`과 모델 밖을 "불가능"으로 쓰지 않는다. "예산 안에서 찾지 못했습니다(약한 증거)", "모델 밖: 판정할 수 없습니다". `INFEASIBLE_NECESSARY_CONDITION`은 "이 모델에서는 필요조건을 만족하지 못합니다"이며 "현실에서 불가능"이라 쓰지 않는다.
- 판정은 시뮬과 몬테카를로만 한다. 에이전트가 판정을 선언하는 문구는 없다. 실패 설명(G-05)은 롤아웃 수치만 인용한다.
- 가정 값을 고치면 이전 판정은 **무효**가 된다: `color.evidence.none` + "무효: 다시 판정해야 합니다". 현재 판정처럼 보이면 안 된다. 이전 확률을 큰 글자로 남기지 않는다.
- 진행 중에는 확률을 판정 모양으로 보여 주지 않는다: "진행 중 · 아직 판정이 아닙니다"(`design-system.md` 7절).
- 파단은 "단순화 모델" 라벨(4.6절). 실패 리포트의 원인은 증거 단계 색 + 모양(▲, ✕) + 문구이고 빨강이 아니다.
- 예시 수치는 `design-system.md` 10절의 값뿐이다. 나머지는 `예시` 꼬리표.

| S5 | `NOT_FOUND_IN_BUDGET`(약한 증거) | 약한 증거 변형(바탕을 비우고 점선 테두리 + "약한 증거"). 쓴 탐색 예산(살펴본 후보 200 / 200 개 `시뮬` `예시`). "예산 안에서 찾지 못했습니다(약한 증거)". 불가능이라 쓰지 않는다 |
| S6 | 모델 밖 | `color.evidence.none`. "모델 밖: 판정할 수 없습니다", 모델이 다루지 않는 현상 한 줄(예: 기·빔 같은 비물리 현상은 `예시`) |
| S7 | 진행 중 | 진행 막대 + `n / N 표본` + 경과 시간 + `취소`. "진행 중 · 아직 판정이 아닙니다". 확률 자리 없음 |
| S8 | 무효 | 가정을 고쳤거나 행성을 바꿔 무효: 상단 띠 "무효: 다시 판정해야 합니다", `color.evidence.none`, 이전 값을 큰 글자로 남기지 않음(작은 글씨 "이전 판정 · 무효"). `다시 판정` |
| S9 | 오류와 엔진 오프라인 | (a) 오류: 판정을 계산하지 못했습니다 · 이유 · 복사할 코드 · `다시 시도` (`status.danger` 아이콘) · "설계와 가정은 그대로입니다. 판정은 없습니다" (b) 엔진 오프라인: 마지막 판정에 "오래됨 · 마지막 계산 시각 [시각]" |
| S10 | 가정 편집 | 가정표 행의 편집 상태 한 장: 편집 중 → 바뀜(이전 → 새 값, 배지 `사용자 선언`) → 카드가 무효로 바뀌는 순서 세 줄. 검증 거부(`status.danger` 테두리 + 이유) |
| S11 | 실행 정보와 소요 시간 예산 | `실행 정보` 머리 펼침: 시드, 표본 수, 소요 시간, 예산 선택(빠르게 / 보통 / 넉넉히 [제안]). 예산이 작으면 `NOT_FOUND_IN_BUDGET`이 나올 수 있다는 한 줄 |
| S12 | 실패 리포트 ↔ 타임라인 | 실패 리포트 카드: 원인(전복, 슬립, 토크 부족, 추진제 고갈, 파단 중 하나, `예시`), 타임라인 시점, 임계 대비 여유(단위 · 배지). 파단이면 "단순화 모델". 위쪽에 SC-01의 타임라인 줄 일부와 ▲/✕ 표식과의 연결 주석. 빨강 없음 |
| S13 | 키보드 | S1 위에 탭 순서 번호(접기 → 증거 배지 → 배지 → 민감도 → 머리 3개 → 다시 판정), 포커스 링, 화살표 키로 머리 사이 이동 주석 |

## 6. 규칙

- 증거 단계 색은 5.2절 그대로다. 같은 L2면 `p_success`가 0.8%든 15.2%든 같은 색. 판정 4종의 구분은 코드, 문구, 모양으로.
- 모든 텍스트 대비 4.5:1, 비문자 3:1, 누르는 영역 24×24 px 이상, 포커스 링 2 px `color.focus.ring` + 2 px 간격. `prefers-reduced-motion`이면 카드 등장·접힘은 불투명도 전환만. 판정 결과는 어떤 코드든 같은 전환(축하·흔들림·번쩍임 없음, `design-system.md` 3.7절).
- 키보드로 모든 행동. 머리는 Enter/Space. `Esc`는 팝오버·편집을 닫는다. 증거 단계가 바뀌면 스크린리더에 문구를 읽어 준다.
- 색은 `tokens.json`에 있는 값만. 새 색 토큰 금지.
- 금지 문구: `design-system.md` 9절 전체. 특히 "현실과 동일", "검증됨", "보장", 1회 실행을 판정이라 부르기, 에이전트가 판정을 선언하는 문구, 확률을 성공/실패로 부르기.

## 7. 이 브리프가 정하지 않는 것

몬테카를로·탐색의 계산과 표본 수·예산의 실제 값(J-01), 민감도 계산법(J-03), 성공 조건 편집기(J-02b), 3D 안의 실패 표식(코드 프로토타입), 실행 HUD와 타임라인 전체(SC-06), 3행성 비교(SC-07), Halo 자막(SC-08), 가정표 값의 실제 출처 목록(B-06b 등).
