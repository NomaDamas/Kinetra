## 0. 창업자 지시: 하드 제약 (모든 화면에 적용, 2026-11-10, #33 승인 코멘트)

```text
첫 조건: 기능은 빠짐없이, 화면은 단순하게, 인지부하는 최소로.
- 이 화면이 맡은 기능은 하나도 빼지 않는다. 빼는 것은 "보이는 양"이지 기능이 아니다.
- 기본 화면에는 주 행동 하나와 지금 필요한 정보만 보인다.
- 나머지 기능은 단계적으로 드러낸다(진행형 공개). 숨은 기능마다 어디서 어떻게 여는지(단추, 접힘, 메뉴, 단축키)를 화면에 그리고 기능 목록과 화면 위치 대응표를 함께 낸다.
```

어긴 아트보드는 승인하지 않는다. 위 세 줄을 아래 하드 제약으로 푼다.

1. **기능을 빼서 단순하게 만들지 않는다.** 3절 기능 목록 전부가 최대 2단계(클릭이나 키 입력 2번) 안에서 닿는다. 기능이 없어 보이게 하는 것은 실패다.
2. **기본 화면(S1: 최근 프로젝트가 있는 상태)의 상시 조작 요소는 7개이고 5.1절에 이름을 못 박았다. 어떤 상태에서도 10개 이하다.** 세는 법(SC-01 브리프 0절 2번과 같다): 버튼, 입력, 선택 컨트롤, 접기·펼치기 머리, 누를 수 있는 배지가 각각 1이고 **목록은 하나**다. 목록 행 안의 `⋯`은 그 목록에 속한다. 읽기 전용 글자, 구분선, 안내문은 세지 않는다. 모달 시트가 열려 있으면 시트 안의 요소만 세고 뒤의 화면은 비활성이다.
3. **`primary` 버튼은 한 화면에 하나이고 이 화면의 `primary`는 늘 `새 프로젝트`다.** 최근 프로젝트가 있든 없든, 시작 프로젝트가 있든 같다. 시트가 열리면 `primary`는 시트의 `만들기` 하나로 옮겨 가고 뒤 화면의 `새 프로젝트`는 비활성이다(둘이 동시에 활성이면 안 된다). 목록 행, 시작 프로젝트 카드, `프로젝트 열기`는 `secondary`나 `ghost`다.
4. **한 번에 한 가지만 묻는다.** 시작 화면에서 고르는 것은 "새로 만들 것인가, 이어서 열 것인가" 하나다. 새로 만들 때만 이름과 행성을 묻고, 둘 다 기본값이 있어 Enter 한 번으로 끝난다.
5. **같은 정보를 두 곳에 반복하지 않는다.** 한 열에 제목 하나, 시작 프로젝트의 설명은 카드 한 줄이고 "무엇이 들어 있나"는 접힌 머리 뒤에 있다.
6. **정직성 표시는 단순함을 이유로 줄이지 않는다.** 화면 아래의 L3 "실물 검증 없음" 줄은 모든 상태에서 보인다. 수치에는 단위와 값 배지가 붙고, 이 화면에 확률은 나오지 않는다(4절).
7. **빈 화면에 가짜 예시 수치와 일러스트를 넣지 않는다**(`design-system.md` 7절). 아트보드에 보이는 프로젝트 이름과 시각은 `예시` 데이터이고 화면 옆 주석에 `예시`라고 적는다.

### 자기 점검 (Claude Design이 끝에 표로 보고)

| 점검 | 기준 |
|---|---|

| `primary` 버튼 수 | 모든 아트보드에서 정확히 1. 오프라인에서는 비활성이지만 1개 남는다. 시트가 열리면 `만들기`가 그 1개 |

| 금지 | 새 색 토큰 0. 초록 성공·빨강 실패·신호등·히트맵 0. 행성별 색 0(글자 라벨로 구분). 금지 문구 0건(`design-system.md` 9절) |

## 1. 대목표와 핵심 가치

대목표 G1: 창업자가 세 행성 어디서든 상상한 물건을 만들어 정직한 판정이 붙은 Halo로 내보낸다. 시작 화면은 그 모든 작업의 입구다("빈 프로젝트에서 시작해 코드를 건드리지 않고 Halo 한 편을 끝까지 만든다": 9절 "완성"의 정의, 첫 실행까지 걸린 시간: V-03). 이 화면이 없으면 시작 프로젝트(L-03)와 프로젝트 열기(C-03)를 보여 줄 승인된 디자인이 없다.

> **V3 한 번에 100%** — 작은 단위를 증거와 함께 완전히 끝낸다. 부분 완성은 미완성이다.

> **V1 정직한 판정** — 판정은 시뮬과 몬테카를로만 한다. 확률, 가정, 한계를 숨기지 않는다. 1회 미리보기 실행을 판정이라 부르지 않는다.

V3은 첫 행동 하나(`새 프로젝트`)가 어디서든 같다는 것, 시작 프로젝트 3개가 모두 세 행성에서 열린다는 것으로, V1은 시작 프로젝트가 "판정 없음"으로 열린다는 것, 목록 행의 증거 칩이 **저장 시점의** 단계라는 것, L3 줄이 늘 보인다는 것으로 나타난다. (V5 값 배지 규칙은 `design-system.md` 4절 그대로다.)

## 2. 구조

기준 화면 1440×900 [제안]. 어두운 테마 하나, 한국어 UI. 이 화면은 Studio 셸이 아니다. 3패널도 뷰포트도 없고, 가운데 정렬된 두 열이다.

```
┌ 상단줄 48px ──────────────────────────────────────────────────────────────┐
│ Kinetra Studio                              [엔진 연결 끊김 · 다시 연결]* │  *오프라인일 때만
├───────────────────────────────────────────────────────────────────────────┤
│        ┌ 새로 시작 (520) ─────────┐   ┌ 최근 프로젝트 (552) ───────────┐ │
│        │ [ 새 프로젝트 ] ←primary │   │ 최근 프로젝트    [프로젝트 열기] │ │
│        │ 빈 작업대, 지구 평지에서 │   │ ┌─────────────────────────────┐ │
│        │ 시작합니다. 행성은 만들  │   │ │ 로켓 자동차 점프    지구  ⋯ │ │
│        │ 때 고릅니다.             │   │ │ L2 · FEASIBLE_FOUND · 2일 전│ │
│        │ ─ 시작 프로젝트 ──────── │   │ ├─────────────────────────────┤ │
│        │ ┌ 4륜차 ───────────────┐ │   │ │ 로버 경사 시험      화성  ⋯ │ │
│        │ ┌ 로켓 자동차 ─────────┐ │   │ │ 판정 없음 · 정의 없음 · 2개 │ │
│        │ ┌ 로버 ────────────────┐ │   │ ├─────────────────────────────┤ │
│        │ ▸ 시작 프로젝트에 든 것·3│   │ │ …                           │ │
│        └──────────────────────────┘   │ └─────────────────────────────┘ │
│                                        │ 파일을 끌어 놓아도 열립니다     │ │
│                                        └──────────────────────────────────┘ │
├───────────────────────────────────────────────────────────────────────────┤
│ L3 실물 검증 없음 (실측 0건)                                  (읽기 전용) │
└───────────────────────────────────────────────────────────────────────────┘
```

- 열 폭 520 / 552, 사이 간격 48, 바깥 가운데 정렬 [제안]. 왼쪽이 "새로 시작", 오른쪽이 "최근 프로젝트"다. 시선은 왼쪽 `primary`에서 시작한다.
- `새 프로젝트`는 `primary`이고 열 폭을 채운다. 아래 한 줄: "빈 작업대, 지구 평지에서 시작합니다. 행성은 만들 때 고릅니다." 이 한 줄이 "새로 만들기" 기능의 설명이다.
- **시작 프로젝트 3개**(L-03: 4륜차, 로켓 자동차, 로버)는 카드 세 장이다. 카드 한 장 = 이름 + 한 줄 설명 + "판정 없음 · L0 조립에서 열림". 설명 문구 예 [제안]: 4륜차 "바퀴 네 개로 굴러가는 가장 단순한 차", 로켓 자동차 "추력기를 단 차. 점프대 장면용", 로버 "경사로를 오르는 탐사차". 카드는 `secondary`이고 숫자를 넣지 않는다.
- 카드를 누르면 **새로 만들기 시트**(5.2절)가 그 시작 프로젝트로 열린다. 시작 프로젝트는 **복사본으로 열리고 원본은 바뀌지 않는다**(카드 아래 한 줄 안내) [제안].
- `▸ 시작 프로젝트에 든 것 · 3개` 접힌 머리(S4)는 카드에 안 보이는 내용(부품 종류, 출처 배지, 열었을 때의 증거 단계)을 펼친다. 머리에 이름과 개수가 항상 보인다.
- 오른쪽 목록은 **최근에 연 순서**로 고정이다 [제안]. 정렬·필터·검색 컨트롤은 두지 않는다(프로젝트 수가 적은 S1 단계 가정 [제안], 7절). 목록은 자체 스크롤이다.
- 목록 행 한 줄에는 (1) 이름 (2) 행성 글자 라벨 (3) 마지막 수정 시각 (4) 저장 시점의 증거 칩 (5) 문제 칩(있을 때만) (6) `⋯`가 있다. 이 여섯 개를 넘기지 않는다.
- 화면 맨 아래 읽기 전용 줄: `L3 실물 검증 없음 (실측 0건)`. 접거나 숨길 수 없다. 이 화면에는 상단바의 증거 배지가 없다(프로젝트를 열기 전이라 현재 증거 단계가 없다).
- 로고, 일러스트, 마케팅 문구, 환영 영상, 튜토리얼 안내, 계정·로그인, 클라우드 동기화 문구를 그리지 않는다.

## 4. 정직성 규칙

- **시작 프로젝트는 판정 없이 열린다.** 카드와 시트에 "판정 없음 · L0 조립에서 열립니다". 미리 계산된 판정이 든 것처럼 쓰지 않고, 로켓 자동차 카드에 15.2% 같은 확률을 넣지 않는다.
- **목록 행의 증거 칩은 "저장 시점의" 단계다.** 증거 배지의 축소형(단계 코드 + 이름)이고 현재 판정이 아니라 마지막 저장 상태를 말한다 [제안]: `L1 · 1회 실행 · 판정 아님`, `L2 · FEASIBLE_FOUND`, `L2 · INFEASIBLE_NECESSARY_CONDITION`, `L2 · NOT_FOUND_IN_BUDGET(약한 증거)`, `L2 · 모델 밖`, `무효`, 판정이 없으면 `판정 없음`. 코드 글자만 쓰고 **확률·CI·표본 수는 이 화면에 쓰지 않는다**(가정표와 "이 모델이 보지 않는 것" 없이 확률만 보이지 않게 한다. `design-system.md` 9절). 칩을 누르면 팝오버: "저장된 판정입니다. 열어서 가정표와 함께 확인하세요. 가정이나 행성을 바꾸면 무효가 됩니다."
- 칩의 색은 증거의 강도다(`design-system.md` 5.2절). `FEASIBLE_FOUND`든 `INFEASIBLE_NECESSARY_CONDITION`이든 같은 L2 색이다. `NOT_FOUND_IN_BUDGET`은 약한 증거 변형(바탕 없음 + 점선), 모델 밖과 `무효`는 `color.evidence.none`. "불가능", "성공", "실패" 문구와 결과의 좋고 나쁨을 암시하는 아이콘은 없다.
- 프로젝트 파일이 마지막 판정을 담는지는 [확인 필요](C-01, C-03). 담지 않으면 칩 자체를 그리지 않는다(`–`나 빈칸 칩 금지). 위 칩 목록은 담는 경우의 디자인이다.
- **정의 없음(C-06):** 열기는 성공한다. 행에 `정의 없음 · N개` 문제 칩, 팝오버 "열 수 있습니다. 실행·판정·Halo 내보내기는 열린 뒤 막힙니다. 빠진 정의는 열린 뒤 다시 연결하거나 지울 수 있습니다." 숨기거나 조용히 빼지 않고, 질량·형상 숫자는 쓰지 않는다. **카탈로그와 다름:** 팝오버 "프로젝트에 담긴 정의를 씁니다. 카탈로그의 같은 ID와 해시가 다릅니다."
- 행성은 글자 라벨(`지구`/`화성`/`달`)이고 색으로 구분하지 않는다. 행성 상수는 이 화면에 숫자로 쓰지 않는다. 시트 안내: "나중에 상단바에서 바꿀 수 있습니다. 바꾸면 이미 낸 판정은 무효가 됩니다"(4.6절). 새 프로젝트에는 판정이 없으므로 무효 표시는 없다.
- 로켓 자동차의 카탈로그 밖 값은 배지를 지킨다: 노즐당 추력 8 kN `카탈로그 밖 · 사용자 선언`, 차체 1.3 t `사용자 선언`(`design-system.md` 10절). 시작 프로젝트에 실제로 든 값인지는 [확인 필요](J-05, L-03)이고, 이 화면에서는 S4 안에서만 `예시`와 함께 보인다. 다른 두 시작 프로젝트의 수치는 쓰지 않는다.
- 에이전트가 판정을 선언하는 문구, "현실과 동일", "검증됨", "보장"은 없다. "된다", "바로 완성됩니다" 같은 약속도 쓰지 않는다.
- **판정 4종 카드는 이 화면에 없다.** 판정 코드는 행의 증거 칩 글자로만 나오고 카드 구성(확률 자리, 가정표)은 SC-04가 정한다. 칩의 문구가 `design-system.md` 5.1절 판정 4종과 어긋나지 않는지만 자기 점검에서 본다.
- 예시 수치는 `design-system.md` 10절의 값뿐이다. 나머지(이름, 시각, 개수)는 `예시`.

## 6. 규칙

- 증거 칩 색은 `design-system.md` 5.2절 그대로다. `color.status.*`는 시스템 상태(오류, 엔진 연결 끊김, 파일 없음, 파괴적 동작 확인, 입력 거부)에만 쓴다. `정의 없음`·`카탈로그와 다름` 문제 칩은 오류가 아니라 정보이므로 글자 + 아이콘 + 무채색 테두리다 [제안].
- 대비 4.5:1(글자)·3:1(비문자), 누르는 영역 24×24 px 이상, 포커스 링 2 px `color.focus.ring` + 2 px 간격. `prefers-reduced-motion`이면 시트 등장·목록 갱신은 불투명도 전환만, 뼈대 반짝임은 멈춘다.
- 키보드로 모든 행동. 시트는 모달(포커스를 가두고 `Esc`로 닫음). 목록은 화살표로 이동(roving tabindex), `⋯` 메뉴는 Enter·Space로 열고 `Esc`로 닫는다. 증거 칩은 근거 팝오버를 여는 버튼이다. 오류·로딩은 포커스를 빼앗지 않고 스크린리더에 읽어 준다.
- 색은 `tokens.json`에 있는 값만. 새 색 토큰, 행성별 색, 로고, 일러스트 없음. 클라우드·계정·공유를 암시하지 않고 로컬임을 말한다("이 컴퓨터에 저장된 프로젝트") [제안; 저장 방식 확인 필요].
- 금지 문구: `design-system.md` 9절 전체(특히 "현실과 동일", "검증됨", "보장", 판정처럼 보이는 문구, 에이전트의 판정 선언, `NOT_FOUND_IN_BUDGET`·모델 밖을 "불가능"이라 쓰기).

## 7. 이 브리프가 정하지 않는 것

- 프로젝트 저장 위치·형식·확장자, 최근 목록의 저장 방식(C-03), 프로젝트 파일이 마지막 판정을 담는지(C-01, C-03).
- 엔진이 끊긴 동안 만들기·열기가 되는지(A0-04). 이 브리프는 안전한 쪽(비활성 + 이유)으로 그렸다.
- Studio 셸(SC-01), 판정 카드(SC-04), 열린 뒤의 "정의 없음" 표시·재연결(SC-15, C-07), 공유 링크로 열기(SC-09), 시작 프로젝트의 부품 구성과 수치(L-03, J-05), 행성 데이터 값(W-01), 튜토리얼과 빠진 최소 구성 안내(G-09), 목록의 검색·정렬·태그, 계정과 클라우드 저장(9절), 3D 뷰포트 안.
- 프로젝트 이름의 허용 문자와 길이, 복사본 이름 규칙.
- 행성 선택을 새로 만들기 시트에 두는 것: 계획은 "새 프로젝트 → 지구 평지"(4.2절)와 "시작 프로젝트가 세 행성에서 열린다"(L-03)만 말한다. 시트의 행성 선택(기본 지구)은 [제안]이다 [확인 필요].
