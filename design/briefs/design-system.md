# 디자인 시스템 브리프 (DS)

> 이슈 #31 [D0-02a]. 근거는 `docs/plan/studio-plan.md` 4절(4.1~4.7)과 7절이다. 창업자가 이 파일을 Claude Design(`/design`)에 붙여 넣어 디자인 시스템을 만든다(D0-02b).
>
> 표기: **[제안]** 이 브리프가 새로 내는 기준이다. 3절의 수치와 6~7절의 세부 상태 목록도 여기에 든다. 창업자와 Claude Design이 고칠 수 있다. **[확인 필요]** 채택 전에 확인할 사실이다. 값 배지 5종의 이름, 증거 4단계와 화면 문구, 5.2절 규칙 1, 9절에서 계획이 직접 금지한 문구는 계획 문서(4.4~4.6)의 요구라서 바꾸려면 `type:plan-change` 이슈가 필요하다.
>
> 범위: 토큰과 공통 컴포넌트까지다. 화면 배치(SC-01~SC-11)는 D0-03, D1의 브리프가 맡는다. 기즈모·고스트 같은 3D 상호작용은 Claude Design이 아니라 코드 프로토타입으로 검증한다(4.7).

## 0. 쓰는 법

1. 11절의 프롬프트 블록을 `/design`에 붙여 넣는다. 저장소를 읽지 못하는 경로(claude.ai Artifacts의 Design)라면 블록 아래에 이 파일 전체를 이어 붙인다.
2. 결과가 11절의 자기 점검을 통과하면 승인하고 `design/exports/design-system/`에 내보낸다(D0-02c). 실행·내보내기 절차는 D0-01a 절차서가 정한다(이 브리프를 쓰는 시점에는 아직 없다).

## 1. 대목표와 핵심 가치

대목표 G0: 모든 작업이 대목표·핵심 가치·계획에 묶여 한 번에 100% 끝나는 루프를 만든다. 이 디자인 시스템은 G1(창업자가 세 행성 어디서든 상상한 물건을 만들어 정직한 판정이 붙은 Halo로 내보낸다)의 모든 화면이 쓰는 공통 부품이다.

> **V1 정직한 판정** — 판정은 시뮬과 몬테카를로만 한다. 확률, 가정, 한계를 숨기지 않는다. 1회 미리보기 실행을 판정이라 부르지 않는다.

> **V5 깨끗한 출처** — 수치, 부품, 에셋은 출처와 라이선스가 기록된 것만 쓴다. 사용자가 선언한 값과 가져온 에셋은 배지로 구분한다.

V1은 증거 4단계(5절)로, V5는 값 배지 5종(4절)으로 화면에 나타난다. 두 표현이 디자인 시스템에 한 벌로 있어야 화면마다 정직성 표시가 달라지지 않는다.

## 2. 방향

- **뷰포트가 주인공인 어두운 작업 도구.** 3D 뷰포트가 화면의 중심이고 가장 넓다. 패널(왼쪽 라이브러리, 오른쪽 인스펙터, 아래 에이전트 바·타임라인)은 접을 수 있고 뷰포트보다 눈에 띄지 않는다. 장식, 그라디언트, 마케팅 느낌의 히어로 영역은 없다.
- **한 모드에 주 행동 하나.** 모드는 조립(물리 꺼짐), 실행(미리보기 1회), 판정(탐색 + 몬테카를로), Halo(카메라·자막·내보내기) 네 개다. 강조색으로 채운 `primary` 버튼은 화면에 한 개만 보인다. 변경안 카드의 [수락]을 포함한 나머지 버튼은 `secondary`, `ghost`, `danger`다 [제안].
- **숫자에는 항상 단위와 배지.** 수치는 `값 · 단위 · 값 배지`를 한 묶음으로 그린다. 단위나 배지가 빠진 수치는 그리지 않는다. 무차원 값도 단위 자리에 `–`를 둔다 [제안].
- **색은 뜻이 하나다.** 증거 색은 증거의 강도만, 상태 색은 시스템 상태만 뜻한다(5.2절). 초록 성공색 토큰은 두지 않는다 [제안].
- **언어.** UI는 한국어다. 판정 코드(`FEASIBLE_FOUND` 등), `p_success`, `CI`, `Halo`는 원문 그대로 쓴다.

모드별 주 행동의 예 [제안](최종 문구는 SC-01에서 정한다): 조립 → `실행하기`, 실행 → `▶ 1회 실행`, 판정 → `판정 실행`, Halo → `내보내기`.

## 4. 값 배지 5종

수치의 **출처 종류**를 말하는 작은 알약 모양 표지다. 모든 수치 옆에 붙는다(4.4). 색만으로 구분하지 않도록 글자 라벨, 글리프, 테두리 모양을 함께 쓴다. 이름 다섯 개는 계획의 요구다. "뜻"은 계획 4.2, 4.4, 13절 위험 5에 나온 쓰임을 정리한 것이다 [제안].

| 배지 | 뜻 | 예 | 글리프 | 시각 처리 [제안] |
|---|---|---|---|---|
| `시뮬` | 엔진이 계산하거나 시뮬해서 나온 값 | 조립체 질량 합, 무게중심, `p_success` | 파형 | 글자 `#E8EDF2`, 채움 `#303B49`(대비 9.65), 테두리 없음 |
| `인용` | 출처가 기록된 값 | 카탈로그 부품 사양, 재료 물성, 행성 상수 | 따옴표 | 글자 `#C5D0DC`(최저 대비 8.27), 채움 없음, 실선 테두리 `color.border.strong` |
| `기본값` | 사용자가 정하지 않아 시스템이 넣은 값. 이 설계에 맞는지 확인된 적이 없다 | 새 관절의 한계, 새 재질의 마찰 | 빈 원 | 글자 `color.text.secondary`(최저 대비 6.15), 채움 없음, 테두리 `color.border.default` |
| `사용자 선언` | 사용자가 직접 넣거나 선언한 값. 판정은 선언만큼만 맞다 | 가져온 glb의 질량, 카탈로그 밖 추력 | 연필 | 글자 `#F2A8D0`, 채움 `#3A1D2E`(대비 8.09) |
| `추정` | 에이전트나 규칙이 어림한 값 | 가져온 에셋의 프록시·질량 제안 | ≈ | 글자 `#D2C6A0`, 채움 `#2C2819`(대비 8.65), 점선 테두리 |

- 판정을 흔들 수 있는 `사용자 선언`과 `추정`만 색을 띠고 나머지 셋은 무채색이다. 증거 색(보라)과 상태 색(빨강·주황)은 배지에 쓰지 않는다.
- 수식어를 앞에 붙일 수 있다: `카탈로그 밖 · 사용자 선언`.
- 배지는 포커스를 받는 버튼이다. 누르면 근거 팝오버가 열린다: `인용`은 출처와 라이선스, `시뮬`은 어떤 계산·실행에서 나왔는지, `사용자 선언`은 선언한 사람과 시각, `추정`은 추정 방법, `기본값`은 기본값의 출처.
- 사용자가 값을 덮어쓰면 배지가 `사용자 선언`으로 바뀌는 모습을 그린다 [제안].
- 상태: 기본, hover, 포커스, 팝오버 열림, 읽기 전용(공유 플레이 페이지 등 값을 편집할 수 없는 화면: 값 편집만 막고 배지의 포커스와 근거 팝오버 조회는 그대로 된다), 오래됨(엔진 연결이 끊겨 `시뮬` 값을 다시 계산하지 못한 상태. 7절). 배지 자체를 비활성으로 만드는 상태는 두지 않는다. 근거 조회는 어느 화면에서도 막지 않는다(V1).

## 5. 증거 4단계

### 5.1 단계와 문구

상단바의 증거 배지가 현재 단계를 보여 준다(4.5). 구성은 강도 막대 4칸 + 단계 코드 + 이름 + 고정 문구다.

| 단계 | 화면 문구 | 근거 | 색 토큰 |
|---|---|---|---|
| L0 조립 | 질량, 무게중심, 정역학 경고 | 해석 계산 | `color.evidence.l0` |
| L1 미리보기 | "1회 실행. 판정이 아닙니다" (좁은 곳: `1회 실행 · 판정 아님`) | 명목 모델 1회 | `color.evidence.l1` |
| L2 판정 | `FEASIBLE_FOUND` + `p_success`·95% CI / `INFEASIBLE_NECESSARY_CONDITION` / `NOT_FOUND_IN_BUDGET`(약함) / 모델 밖 | 탐색 + 몬테카를로 | `color.evidence.l2` |
| L3 실측 | "실물 검증 없음" | 현재 0건이다. 숨기지 않는다 | 0건인 동안 `color.evidence.none` |

- **확률·95% CI와 민감도는 계산한 판정에서만, 그때는 반드시 보인다.** 몬테카를로를 돌린 `FEASIBLE_FOUND`가 그 경우다. 나머지 세 판정은 그 자리에 `확률 미산출 · 이유`, `민감도 미산출 · 이유`를 쓰고 아래 표의 판정별 내용을 보인다. 이유의 예 [제안]: "필요조건에서 막혀 몬테카를로를 돌리지 않았습니다", "예산 안에서 성공 사례를 찾지 못했습니다", "이 모델이 다루지 않는 현상입니다". 빈칸, `0%`, `–`로 두지 않는다.
- L1의 문구는 접거나 숨길 수 없다. 실행 화면, 타임라인, 내보낸 영상("판정 없음: 1회 실행")에 모두 남는다.
- L3 칸은 실측이 0건이어도 항상 보인다. 빈 막대와 "실물 검증 없음"으로 그린다.
- 행성을 바꾸거나 설계를 고치면 이전 판정은 **무효**가 된다. `color.evidence.none`으로 내리고 "무효: 다시 판정해야 합니다"를 붙인다. 현재 판정처럼 보이면 안 된다.

| 판정 | 확률 자리 | 민감도 자리 | 대신 반드시 보이는 것 |
|---|---|---|---|
| `FEASIBLE_FOUND` | `p_success` + 95% CI + 표본 수 | 판정을 뒤집는 가정 1위와 순위 | — |
| `INFEASIBLE_NECESSARY_CONDITION` | 확률 미산출 · 이유 | 민감도 미산출 · 이유 | 어긴 필요조건과 그 여유(필요한 값 대 쓸 수 있는 값) |
| `NOT_FOUND_IN_BUDGET` | 확률 미산출 · 이유 | 민감도 미산출 · 이유 | 쓴 탐색 예산, "약한 증거" |
| 모델 밖 | 확률 미산출 · 이유 | 민감도 미산출 · 이유 | 모델이 다루지 않는 현상이 무엇인지 |

가정표, "이 모델이 보지 않는 것", L3 "실물 검증 없음"은 네 판정 모두에 붙는다.

### 5.2 규칙: 증거 색은 증거의 강도다. 성공·실패가 아니다

1. **증거 색(`color.evidence.*`)과 채움은 증거가 얼마나 강한지만 나타낸다.** 같은 단계라면 성공 확률이 높든 낮든, 가능이든 불가능이든 색이 같다. `p_success`가 0.8%인 카드와 15.2%인 카드는 같은 L2 색이고, 차이는 숫자와 신뢰구간 막대가 말한다. 이 원칙은 과거 판정이 가정에 따라 13%↔77%로 흔들린 데서 나왔다(4.5).
2. **결과의 종류는 판정 코드, 한국어 한 줄, 아이콘 모양으로 전한다.** 초록 = 성공, 빨강 = 실패 배색은 판정·실행 결과 어디에도 쓰지 않는다. 확률 구간에 따라 색이 바뀌는 표현(신호등, 히트맵)도 쓰지 않는다.
3. **물리적 실패는 시스템 오류가 아니다** [제안]. 전복, 슬립, 토크 부족, 추진제 고갈, 파단, 정역학 경고는 `color.status.*`를 쓰지 않는다. 그 결과가 나온 실행의 증거 단계 색 + 모양(▲, ✕, △) + 문구로 그린다. `color.status.*`는 시스템 상태(오류, 연결 끊김, 파괴적 동작 확인, 입력 검증 거부)에만 쓴다.
4. **약한 증거를 강하게 그리지 않는다.** `NOT_FOUND_IN_BUDGET`은 약한 증거 변형(3.3)으로, 모델 밖은 `color.evidence.none`으로 그린다. 둘 다 "불가능"으로 읽히는 문구나 모양을 쓰지 않는다.

## 6. 컴포넌트

배치가 아니라 부품의 구성·변형·상태를 정한다. 모든 부품은 기본, hover, 포커스, 비활성 상태를 갖는다(예외: 값 배지는 비활성 상태가 없다. 4절). 아래 "상태"는 그 밖에 더 그릴 것이다.

| 컴포넌트 | 구성 | 변형·상태 | 규칙 |
|---|---|---|---|
| 버튼 | 라벨, 선택적 아이콘·단축키 | `primary` / `secondary` / `ghost` / `danger`; 누름, 진행 중, 비활성(이유 툴팁) | `primary`는 모드의 주 행동 하나뿐이다 |
| 패널 | 머리(제목, 접기), 섹션, 스크롤 본문 | 펼침, 접힘(아이콘 레일), 너비 조절 중, 빈 화면, 로딩, 오류 | 접어도 뷰포트를 가리지 않는다. `elevation.1` |
| 카드 | 제목, 본문, 행동 줄 | 기본, 선택 가능, 증거 띠(왼쪽 3 px 증거 색), 제안 중(점선 테두리) | `elevation.2`. 카드 안에 `primary` 버튼을 두지 않는다 |
| 인스펙터 필드 행 | 라벨 · 값(`type.mono`) · 단위 · 값 배지 | 편집 중, 바뀜(이전 → 새 값), 계산값(읽기 전용), 여러 개 선택(값 `—`), 에이전트 제안 값, 검증 거부(`color.status.danger` 테두리 + 이유), 오래됨 | 단위와 배지가 없는 행은 없다. 높이 `size.control.md` |
| 변경안 카드 | 제목, 요약, 수치 변화 행(질량·무게중심·부품 수: 이전 → 이후 · 단위 · 배지), 명령 수, [미리보기] [수락] [부분 수락] [거절] | 제안됨, 미리보기 중, 부분 선택(명령별 체크박스), 수락됨([되돌리기]), 거절됨, 되돌림, 검증기 거부·재시도 중(n/N), 삭제 확인 필요 | 에이전트가 낸 수치에도 배지가 붙는다(`추정` 등). [수락]은 `secondary`다 |
| 판정 카드 | 증거 배지, 판정 코드 + 한국어 한 줄, 확률 자리(`type.display`): `p_success` + 95% CI + 신뢰구간 막대 + 표본 수 또는 `확률 미산출 · 이유`. 가정표(값, 분포, 출처, 신뢰도), 민감도 자리: 판정을 뒤집는 가정 1위 또는 `민감도 미산출 · 이유`. 판정별 내용(5.1절 표), "이 모델이 보지 않는 것"(CFD, 연소, FEM, 열), L3 "실물 검증 없음" | 판정 4종: `FEASIBLE_FOUND`(확률 + CI + 민감도 필수), `INFEASIBLE_NECESSARY_CONDITION`(어긴 필요조건과 여유), `NOT_FOUND_IN_BUDGET`(약한 증거 변형, 탐색 예산), 모델 밖(`color.evidence.none`, 모델 밖인 현상); 계산 중, 무효, 오류 | 5.1절, 5.2절 그대로. 가정표와 "보지 않는 것"을 뺀 축약형은 만들지 않는다. 시드를 보인다 [제안] |
| 타임라인 표식 | 모양 + 시점 + 원인 라벨 | 실패 ▲(전복, 슬립, 토크 부족, 추진제 고갈), 파단 ✕("단순화 모델" 표시); hover·포커스 시 원인, 시점, 임계 대비 여유 팝오버; 선택됨(실패 리포트와 연결) | 색은 그 실행의 증거 단계 색이다. 빨강을 쓰지 않는다 |
| 행성 전환기 | `지구 / 화성 / 달` 분할 컨트롤 | 선택됨, 전환 중(다시 컴파일), 실행 중 비활성, 전환 뒤 안내("이전 판정은 무효입니다") | 글자 라벨로 구분한다. 행성별 색으로 구분하지 않는다 [제안] |
| 모드 전환기 | `조립 / 실행 / 판정 / Halo` 탭 | 선택됨, 비활성(이유 표시) | 모드가 바뀌면 `primary` 버튼이 그 모드의 주 행동으로 바뀐다 |
| 에이전트 바 | 마이크 버튼, 입력창, 문맥 칩("선택: …"), 보내기, 에이전트 상태 | 마이크: 대기, 듣는 중, 받아쓰는 중, 인식문 확인([보내기] [고치기] [취소]), 권한 거부, 지원 안 됨 · 에이전트: 생각 중, 검증기 재시도 n/N, 변경안 n건, 실패 | 음성은 인식문을 확인한 뒤에만 보낸다. 삭제류 명령은 확인 단계를 둔다(4.3) |
| 토스트 | 아이콘, 한 줄 문구, 선택적 행동(되돌리기, 열기) | 알림(`status.info`), 경고(`status.warning`), 오류(`status.danger`) | 판정 결과(코드·확률)를 토스트만으로 전하지 않는다 [제안]. 오류는 닫을 때까지 남는다 |

## 7. 상태

모든 패널과 카드는 아래 네 상태를 갖는다. 화면별 문구는 화면 브리프가 정한다.

| 상태 | 표현 | 규칙 |
|---|---|---|
| 빈 화면 | `type.heading` 한 줄 + 설명 한 줄 + 다음 행동 하나 | 일러스트와 가짜 예시 수치를 넣지 않는다. 판정이 없으면 "판정 없음"이라고 쓴다 |
| 로딩 | 패널은 뼈대(skeleton). 실행·탐색·판정은 진행 막대 + `n / N 표본` + 경과 시간 + [취소] | 진행 중에는 확률을 판정 모양으로 보여 주지 않는다. "진행 중 · 아직 판정이 아닙니다" [제안] |
| 오류 | 무엇이 안 됐는지, 왜, 다음 행동. 복사할 수 있는 오류 코드. `color.status.danger` 아이콘 + 문구 | 시스템 오류에만 쓴다. 물리적 실패(전복, 파단)는 오류가 아니다(5.2) |
| 엔진 오프라인 | 상단바에 "엔진 연결 끊김" 칩(`color.status.warning`) + [다시 연결]. 주 행동 버튼은 비활성 + 이유 | 마지막 `시뮬` 값과 판정에는 "오래됨 · 마지막 계산 시각"을 붙인다. 지금 계산한 값처럼 보이게 하지 않는다. 가짜 결과로 채우지 않는다 |

엔진이 끊긴 동안 어떤 편집이 되는지는 어댑터 경계 결정(A0-04)의 몫이라 여기서 정하지 않는다 [확인 필요].

## 8. 접근성

기준은 WCAG 2.2 AA다(https://www.w3.org/TR/WCAG22/). 아래 수치는 그 문서에서 인용했다.

- **대비:** 글자 4.5:1 이상, 큰 글자 3:1 이상(1.4.3). 입력 테두리·아이콘·포커스 링 같은 비문자 요소 3:1 이상(1.4.11). 3절의 제안값은 이 하한을 넘는다. 토큰을 조정해도 하한은 지킨다.
- **색만으로 전하지 않는다(1.4.1):** 값 배지는 라벨 + 글리프 + 테두리 모양, 증거 단계는 코드(L0~L3) + 막대 칸 수 + 문구, 타임라인 표식은 모양으로도 구분된다.
- **키보드(2.1.1, 2.1.2):** 모든 기능을 키보드로 쓸 수 있고 포커스가 갇히지 않는다. 탭 순서는 상단바 → 라이브러리 → 뷰포트 → 인스펙터 → 에이전트 바 → 타임라인이다 [제안]. 모드 전환기는 탭 목록, 행성 전환기는 라디오 그룹으로 화살표 키로 옮긴다. `Esc`는 팝오버·모달·미리보기를 닫는다. 변경안 카드의 네 행동은 모두 키보드로 닿는다. 단축키는 툴팁에 적는다.
- **포커스(2.4.7, 2.4.11):** 2 px `color.focus.ring` + 2 px 간격의 링을 모든 조작 요소에 둔다 [제안]. 패널이나 토스트가 포커스된 요소를 가리지 않는다.
- **크기(2.5.8):** 누르는 영역은 24 × 24 px 이상이다.
- **알림:** 토스트는 포커스를 빼앗지 않는다. 증거 단계가 바뀌면 스크린리더에 문구를 읽어 준다("L1 미리보기. 1회 실행. 판정이 아닙니다").
- **모션:** 3.7절의 `prefers-reduced-motion` 규칙을 따른다.

## 9. 금지 문구와 표현

| 금지 | 이유 | 대신 |
|---|---|---|
| "현실과 동일", "실제와 똑같이". 실물 검증 없는 결과에 "검증됨", "보장" | 실물 검증은 0건이다 | "이 모델에서는", L3 "실물 검증 없음" |
| 1회 실행을 판정이라 부르기: L1 결과를 "판정", "성공 확인", "통과", "된다/안 된다"로 쓰기 | V1 | "1회 실행. 판정이 아닙니다", "이번 실행에서는 …" |
| 가정 숨기기: 가정표·"이 모델이 보지 않는 것"을 뺀 판정, CI 없는 확률, 계산한 민감도를 뺀 판정, 산출하지 않은 확률·민감도를 숫자나 빈칸으로 두기, 배지나 단위 없는 수치 | V1, V5 | 판정 카드 전체 구성, `15.2% [12.3, 18.6]`, `확률 미산출 · 이유`, `민감도 미산출 · 이유` |
| 에이전트가 판정을 선언하는 문구("에이전트가 가능하다고 판정했습니다") | AI는 판정하지 않는다 | "시뮬 결과: …", 롤아웃 수치만 인용 |
| `NOT_FOUND_IN_BUDGET`이나 모델 밖을 "불가능"이라 쓰기 | 약한 증거다 | "예산 안에서 찾지 못했습니다(약한 증거)", "모델 밖: 판정할 수 없습니다" |
| 판정 없는 영상·화면에 판정처럼 보이는 문구, 표본 하나를 대표 결과처럼 보이기 | 4.6 | "판정 없음: 1회 실행", "표본 중 하나" |
| 파단을 정밀 해석처럼 말하기 | 결합부 임계값 모델이다 | "단순화 모델" 표시 |

계획이 직접 금지한 것은 "현실과 동일", 1회 실행을 판정이라 부르기, 가정 숨기기, 에이전트의 판정 선언, 판정 없는 영상의 판정처럼 보이는 문구다(계획 2절, 4.4~4.6, `docs/process/review-rubric.md` 1번). 같은 줄의 나머지 표현은 같은 뜻의 변형을 막으려는 [제안]이다.

## 11. `/design`에 붙여 넣을 프롬프트

```text
Kinetra Studio의 디자인 시스템(DS)을 만들어 줘. 화면이 아니라 토큰과 공통 컴포넌트 갤러리다.

규격은 저장소의 design/briefs/design-system.md 전문이다. 저장소를 읽을 수 없으면 이 프롬프트 아래에 붙여 넣은 전문을 따른다. 규격과 아래 요약이 다르면 규격이 이긴다.

제품: 빈 행성 평지(지구·화성·달)의 작업대에서 에이전트와 함께 물건을 조립하고, 그 행성의 물리로 돌려 보고, 가정과 확률이 붙은 Halo(영상 + 플레이 링크)로 내보내는 웹 스튜디오. 데스크톱 웹, 한국어 UI.

깨면 안 되는 규칙
1. 뷰포트가 주인공인 어두운 작업 도구다. 패널은 접을 수 있고 뷰포트보다 조용하다. 장식·그라디언트·히어로 영역 없음.
2. 한 모드(조립 | 실행 | 판정 | Halo)에 주 행동 하나. 강조색 primary 버튼은 화면에 하나만.
3. 모든 수치는 "값 · 단위 · 값 배지" 한 묶음이다. 값 배지는 5종: 시뮬, 인용, 기본값, 사용자 선언, 추정. 라벨 + 글리프 + 테두리 모양으로 구분하고 색만으로 구분하지 않는다.
4. 증거는 4단계다. L0 조립(해석 계산) / L1 미리보기 "1회 실행. 판정이 아닙니다" / L2 판정(FEASIBLE_FOUND + p_success·95% CI, INFEASIBLE_NECESSARY_CONDITION, NOT_FOUND_IN_BUDGET(약함), 모델 밖) / L3 실측 "실물 검증 없음"(0건이어도 항상 보인다). 확률·95% CI와 민감도는 몬테카를로를 돌린 FEASIBLE_FOUND에서 필수다. 나머지 세 판정은 그 자리에 "확률 미산출 · 이유", "민감도 미산출 · 이유"를 쓰고 대신 이것을 보인다: INFEASIBLE_NECESSARY_CONDITION은 어긴 필요조건과 여유, NOT_FOUND_IN_BUDGET은 쓴 탐색 예산, 모델 밖은 모델이 다루지 않는 현상. 빈칸이나 0%로 두지 않는다.
5. 증거 색은 성공·실패가 아니라 증거의 강도를 뜻한다. 같은 단계면 확률이 높든 낮든 색이 같다. 초록=성공, 빨강=실패, 신호등, 확률 히트맵 금지. 초록 성공색 토큰을 만들지 않는다. 결과 종류는 코드·문구·아이콘 모양으로 전한다.
6. 상태 색(danger, warning, info)은 시스템 상태에만 쓴다. 전복·파단 같은 물리적 실패에는 쓰지 않는다.
7. 금지 문구: "현실과 동일", "검증됨", "보장". L1을 "판정", "성공 확인"이라 부르지 않는다. 가정표·"이 모델이 보지 않는 것"을 뺀 판정, CI 없는 확률, 계산한 민감도를 뺀 판정을 그리지 않는다. 에이전트가 판정을 선언하는 문구를 쓰지 않는다.
8. WCAG 2.2 AA: 글자 대비 4.5:1, 비문자 3:1, 보이는 포커스 링, 키보드로 모든 조작, 누르는 영역 24×24 px 이상, prefers-reduced-motion 대응.
9. 예시 수치는 규격 10절의 값만 쓴다. 다른 수치에는 "예시" 꼬리표를 붙인다.

만들 것(한 프로젝트 안의 갤러리 페이지)
A. 토큰: 색 역할(면, 글자, 강조, 상태, 증거 강도 스케일 none·L0~L3, 값 배지), 타이포 스케일, 간격·크기, 모서리, 높이, 모션. 색마다 이름, hex, 대비 수치를 적는다.
B. 값 배지 5종: 상태(기본, hover, 포커스, 팝오버 열림, 읽기 전용, 오래됨. 비활성 상태는 없고 근거 팝오버는 어느 화면에서도 열린다)와 수식어 예("카탈로그 밖 · 사용자 선언").
C. 증거 배지 4단계 + 약한 증거 변형 + 무효 상태. "p_success 0.8% [0.3, 2.0] 카드와 15.2% [12.3, 18.6] 카드의 색이 같다"를 나란히 보여 주는 시연 한 칸.
D. 컴포넌트: 버튼, 패널, 카드, 인스펙터 필드 행(배지 포함), 변경안 카드(미리보기·수락·부분 수락·거절·되돌리기), 판정 카드(판정 4종), 타임라인 표식(실패 ▲, 파단 ✕), 행성 전환기, 모드 전환기, 에이전트 바(마이크 상태 포함), 토스트. 규격 6절의 변형·상태를 전부 그린다.
E. 상태: 빈 화면, 로딩, 오류, 엔진 오프라인을 패널과 카드에 각각.
F. 접근성: 포커스 링과 키보드 순서 예시.

만들지 않을 것: Studio 셸·인스펙터·판정 화면 같은 화면 배치(SC-01~SC-11), 3D 기즈모·고스트, 로고·일러스트·마케팅 페이지, 밝은 테마.

내보내기: 독립 실행 HTML 갤러리와 토큰 파일(CSS 변수 --kin-*, 같은 키의 JSON). 토큰 이름은 규격 3절 그대로. 값을 조정했다면 바꾼 토큰과 이유, 새 대비 수치를 목록으로 알려 줘.

끝나면 자기 점검을 표로 보고해 줘(항목 / 통과 여부 / 갤러리 위치)
- 값 배지 5종이 모두 있고 색 없이도 구분된다
- 증거 4단계가 모두 있고 L1·L3 고정 문구가 글자 그대로 있다
- 성공·실패를 색으로 나타낸 곳이 없다(초록·빨강 판정, 신호등 없음)
- 단위나 배지가 빠진 수치가 없다
- primary 버튼이 한 화면에 둘 이상인 예시가 없다
- 확률이 있는 판정 카드에는 95% CI와 민감도가 있고, 산출하지 않은 판정 카드에는 "확률 미산출 · 이유"와 "민감도 미산출 · 이유", 판정별 내용(어긴 필요조건과 여유 / 탐색 예산 / 모델 밖인 현상)이 있다
- 6절의 컴포넌트 11종과 7절의 상태 4종이 모두 있다
- 금지 문구가 어디에도 없다
- 글자 대비 4.5:1, 비문자 3:1 미만인 조합이 없다
```
