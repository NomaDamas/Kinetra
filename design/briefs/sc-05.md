## 0. 창업자 지시: 하드 제약 (모든 화면에 적용, 2026-11-10, #33 승인 코멘트)

아래 블록은 `docs/process/design-workflow.md` "브리프의 첫 조건"과 같다. 어긴 아트보드는 승인하지 않는다.

```text
첫 조건: 기능은 빠짐없이, 화면은 단순하게, 인지부하는 최소로.
- 이 화면이 맡은 기능은 하나도 빼지 않는다. 빼는 것은 "보이는 양"이지 기능이 아니다.
- 기본 화면에는 주 행동 하나와 지금 필요한 정보만 보인다.
- 나머지 기능은 단계적으로 드러낸다(진행형 공개). 숨은 기능마다 어디서 어떻게 여는지(단추, 접힘, 메뉴, 단축키)를 화면에 그리고 기능 목록과 화면 위치 대응표를 함께 낸다.
```

이 화면에 적용하면 다음이다.

1. **기능을 빼서 단순하게 만들지 않는다.** 3절 표의 모든 기능이 최대 2단계 안에서 닿는다. 정직성 요소(값 배지, 출처·라이선스, `사용자 선언`/`추정` 구분)는 단순함을 이유로 줄이지 않는다(V5, V1).
2. **기본 화면(S1: 기본 부품 탭)의 상시 조작 요소는 8개 이하**이고 4.1절에 이름을 못 박았다. 세는 법은 SC-01·SC-04 브리프와 같다: 버튼, 입력, 선택 컨트롤, 접기·펼치기 머리, 누를 수 있는 값 배지가 각각 1(목록과 탭 묶음은 각 1, SC-01 #9·#10과 같다). 읽기 전용 글자, 단위, 구분선, 2D 썸네일은 세지 않는다.
3. **주 행동은 화면마다 하나다.** 라이브러리 패널에는 `primary`가 없다(모드의 `primary`는 SC-01 상단바의 것이다). 가져오기 마법사의 `다음`(마지막 단계는 `가져오기 완료`)이 마법사의 유일한 `primary`다. 패널 안 `가져오기`, `선택한 조립체 저장`은 `secondary`다.
4. **한 번에 한 수준만 연다.** 부품 줄의 상세(미리보기·사양·출처)는 한 번에 한 줄만 펼쳐진다(아코디언) [제안]. 마법사는 한 단계에 한 가지 질문만 한다.
5. **같은 정보를 두 곳에 반복하지 않는다.** 줄마다 값 하나에 배지 하나.
6. **색은 뜻이 하나다.** 값 배지 색은 출처 종류이고, 증거 색(보라)을 배지·줄·마법사에 쓰지 않는다(이 화면은 판정을 그리지 않는다). 초록 성공·빨강 실패, 신호등이 없다. `color.status.danger`는 시스템 오류, 입력 검증 거부, 파괴적 동작 확인에만 쓴다.

## 1. 대목표와 핵심 가치

대목표 G1: 창업자가 세 행성 어디서든 상상한 물건을 만들어 정직한 판정이 붙은 Halo로 내보낸다. 라이브러리는 "내 것 또는 기존 에셋으로 무엇이든"이 성립하게 하는 입구다. 이 화면이 없으면 L-01, L-02 구현 이슈가 참조할 승인본이 없다.

> **V3 한 번에 100%** — 작은 단위를 증거와 함께 완전히 끝낸다. 부분 완성은 미완성이다.

> **V5 깨끗한 출처** — 수치, 부품, 에셋은 출처와 라이선스가 기록된 것만 쓴다. 사용자가 선언한 값과 가져온 에셋은 배지로 구분한다.

> **V1 정직한 판정** — 판정은 시뮬과 몬테카를로만 한다. 확률, 가정, 한계를 숨기지 않는다. 1회 미리보기 실행을 판정이라 부르지 않는다.

V5는 값 배지 열과 마법사의 출처·라이선스 단계로, V1은 "가져온 물체의 질량은 선언한 만큼만 맞다"는 문구로 나타난다(13절 위험 5).

## 2. 구조

SC-01 셸의 왼쪽 패널(240 px)이 라이브러리다. 아트보드는 그 패널(240 × 약 790 px)과 가져오기 마법사 모달(약 560 px 폭)이다.

```
┌ 라이브러리 ───────────── 접기 ┐
│ [기본 부품 | 내 것]            │  탭 묶음
│ 정렬: 출처 먼저 ▾   [필터 ⏷ 0] │  정렬 선택, 필터 버튼(적용 개수)
├───────────────────────────────┤
│ ⠿ ▢ 냉가스 추력기            │  줄: 썸네일 · 이름
│     추력기 · 8.9 N    [인용]  │  종류 · 값 · 단위 · 배지 열
│ ⠿ ▢ 빔                       │
│     구조 · 0.4 kg 예시 [기본값]│
│ (펼친 줄) 2D 미리보기 · 사양  │  한 번에 한 줄
└───────────────────────────────┘
```

- **줄 구성** [제안]: 2D 썸네일 · 이름 · 종류 글자 · 정렬 기준 값 + 단위 + 값 배지. 기본·질량 정렬은 질량, 크기 정렬은 크기가 값이다(정렬에 쓰는 값은 그 줄에 배지와 함께 보인다). 배지는 오른쪽 열(**값 배지 열**)이다. 긴 배지(`카탈로그 밖 · 사용자 선언`)는 줄을 두 줄로 늘리고 줄이거나 자르지 않는다.
- **끌어 놓기**: 줄 전체와 왼쪽 `⠿`가 시작점이다. 놓는 곳(뷰포트)은 범위 밖이다. 끌기 대안으로 펼친 줄에 `작업대에 추가` 버튼이 있다.
- **값 배지는 누를 수 있다**: 근거 팝오버(`인용` 출처·라이선스, `사용자 선언` 선언한 사람·시각, `추정` 추정 방법, `기본값` 기본값의 출처, `시뮬` 어떤 계산인지). 키보드에서는 줄에서 `→`로 그 줄의 배지로 간다 [제안].
- **마법사**는 "내 것" 탭의 `가져오기`로 열리는 모달(`elevation.3` + 가림막)이다. 위에 단계 표시(읽기 전용: `1/4 단위·축` → `2/4 프록시` → `3/4 질량` → `4/4 출처`), 가운데 질문 하나, 아래 `이전`(secondary) `다음`(primary). 단계를 오가도 입력은 남는다. 파일 고르기는 단계 0(S10)이다.

## 4. 정직성 규칙

- **모든 값은 `값 · 단위 · 배지`다.** 줄, 상세, 마법사 어디서도 배지·단위 없는 수치를 그리지 않는다. 무차원은 단위 자리에 `–`.
- **배지 배정**(화면용 예시. 카탈로그의 실제 배정은 B-02, B-03, B-06 데이터가 정한다 [확인 필요]):
  - 카탈로그가 출처와 함께 가진 사양: `인용`(예: 냉가스 추력기 최대 추력 8.9 N).
  - 시스템이 기본 치수로 넣은 파라메트릭 값: `기본값`.
  - 엔진이 계산한 값(조립체 질량 합, 메시 부피, 프록시 부피, 부피 차이, 파일 크기): `시뮬`.
  - 사용자가 넣은 값: `사용자 선언`. 가져온 에셋의 **질량은 항상 `사용자 선언`**(L-02c)이다. 직접 넣든 밀도 × 프록시 부피로 정하든 같다.
  - 카탈로그 사양 밖으로 사용자가 선언한 값: `카탈로그 밖 · 사용자 선언`(예: 저장한 조립체의 노즐당 추력 8 kN).
  - 에이전트나 규칙이 어림한 제안(단위 짐작, 프록시 종류, 질량): `추정`. **사용자가 적용하거나 고치면 `사용자 선언`으로 바뀌고**, 바뀌는 순간(이전 → 새 값)을 그린다.
- **메시에서 질량을 계산해 사실처럼 쓰지 않는다**(L-02 범위 밖). 질량은 사용자가 정하기 전까지 비어 있고 `다음`은 비활성(이유 툴팁: "질량을 선언해야 합니다")이다 [제안: 건너뛰기 없음].
- **시각 메시는 충돌에 쓰지 않는다**(L-02b). 프록시 단계에 이 문장을 그대로 쓴다.
- **미산출을 숫자나 빈칸으로 두지 않는다.** 메시가 닫혀 있지 않아 부피를 못 구하면 `부피 미산출 · 이유`(`design-system.md` 5.1절의 "미산출 · 이유"와 같은 방식)다. 0, 빈칸, `–`가 아니다.
- **값이 없는 줄.** 질량·크기 값이 없으면 값 자리에 `정의 없음`을 쓰고 정렬에서 맨 뒤에 둔다. 0으로 채우거나 배지 없는 값으로 정렬하지 않는다(L-04).
- **출처 없는 가져온 에셋은 공유가 막힌다**(L-02d). 출처·라이선스가 `모름`이어도 가져오기는 막지 않지만 줄에 `공유 불가 · 출처 모름`(글리프 + 문구, 상태 색 아님)을 붙인다. 저장소에 넣는 에셋은 원장 행이 있어야 한다는 한 줄을 4단계에 둔다 [제안: 문구].
- **선언값은 판정에 그대로 나온다.** 3단계에 읽기 전용 한 줄: "선언한 질량은 판정 가정표에 `사용자 선언`으로 나옵니다. 판정은 선언한 만큼만 맞습니다. L3 실물 검증 없음". 연결은 SC-04 S2 가정 행의 한 예(`가져온 물체 질량 · 값 · kg · [사용자 선언]`, `예시`)를 주석으로만 보인다.
- **에이전트는 판정하지 않고 카탈로그에 없는 사양을 있는 것처럼 쓰지 않는다**(4.4절). 제안 줄은 "제안" + `추정` + 근거 한 줄("파일의 가장 긴 변이 1200이라 mm로 보입니다", `예시`)이다.
- 예시 수치는 `design-system.md` 10절의 값(1.3 t `사용자 선언`, 8.9 N `인용`, 8 kN `카탈로그 밖 · 사용자 선언`)만 그대로 쓴다. 나머지는 모두 `예시`. 실제 부품 사양처럼 보이는 값을 지어내지 않는다.
- 금지 문구: `design-system.md` 9절 전체. 특히 "현실과 동일", "검증됨", "보장", "정확한 질량", 가져온 값을 "측정"이라 부르는 문구.

상시 조작 요소 6개(이름 고정):

| # | 요소 |

## 6. 규칙

- 값 배지는 `design-system.md` 4절 그대로(글리프 + 라벨 + 테두리 모양). 근거 조회는 어느 화면에서도 막지 않는다. 배지를 비활성으로 만드는 상태는 없다.
- 색은 `tokens.json`에 있는 값만. 새 색 토큰 금지.
- 모든 텍스트 대비 4.5:1, 비문자 3:1, 누르는 영역 24×24 px 이상, 포커스 링 2 px `color.focus.ring` + 2 px 간격. `prefers-reduced-motion`이면 줄 펼침·모달 등장은 불투명도 전환만. 가져오기 완료에 축하·흔들림·번쩍임이 없다(`design-system.md` 3.7절).
- 키보드로 모든 행동. 끌어 놓기에는 항상 대안 버튼이 있다. 모달은 포커스를 가두고 `Esc`는 팝오버·모달을 닫는다(마법사는 확인 창을 거친다). 정렬·필터 결과 개수가 바뀌면 스크린리더에 읽어 준다.
- 240 px 폭에서 이름·배지가 잘리면 줄 높이를 늘리고 글자를 줄이지 않는다.

## 7. 이 브리프가 정하지 않는 것

3D 뷰포트 안의 끌어 놓기·스냅·고스트·거부 사유(B-04, B-08, 코드 프로토타입), 3D 미리보기, 카탈로그 부품의 실제 사양값과 배지 배정(B-02, B-03, B-06), glb 파싱·단위 추정·프록시와 부피 계산·볼록 분해 도구 선택(L-02a, L-02b), 원장 형식(P0-05), 조립체 저장 형식(C-03), 인스펙터의 질량 필드(SC-02), 판정 가정표(SC-04), 시작 프로젝트 3개(L-03, SC-10), XR 손목 팔레트(SC-11, XR-03a), 생성 3D(S2), 공유 마켓·검색 서버(범위 밖).
