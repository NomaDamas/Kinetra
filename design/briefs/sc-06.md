## 0. 창업자 지시: 하드 제약 (모든 화면에 적용, 2026-11-10, #33 승인 코멘트)

`docs/process/design-workflow.md`의 "브리프의 첫 조건"이다. 그대로 이 브리프의 첫 조건이다.

```text
첫 조건: 기능은 빠짐없이, 화면은 단순하게, 인지부하는 최소로.
- 이 화면이 맡은 기능은 하나도 빼지 않는다. 빼는 것은 "보이는 양"이지 기능이 아니다.
- 기본 화면에는 주 행동 하나와 지금 필요한 정보만 보인다.
- 나머지 기능은 단계적으로 드러낸다(진행형 공개). 숨은 기능마다 어디서 어떻게 여는지(단추, 접힘, 메뉴, 단축키)를 화면에 그리고 기능 목록과 화면 위치 대응표를 함께 낸다.
```

어긴 아트보드는 승인하지 않는다.

1. **기능을 빼서 단순하게 만들지 않는다.** 3절 표 전 행이 최대 2단계(클릭이나 키 입력 2번)로 닿는다. 정직성 요소(L1 문구, L3 줄, "단순화 모델", 인과 아님 문구, "보는 속도" 문구, 단위·배지)는 줄이지 않는다(V1).
2. **기본 화면(S1)에서 이 화면의 몫(HUD + 타임라인)의 상시 조작 요소는 10개 이하**이고 5.1절에 이름을 못 박았다. 세는 법은 SC-01과 같다: 버튼, 입력, 슬라이더, 전환기(분할 컨트롤은 **하나**), 목록(표식 줄은 **하나**), 누를 수 있는 배지가 각각 1이다. 읽기 전용 글자·단위·구분선은 세지 않는다. 상단바·라이브러리·오른쪽 패널은 SC-01의 몫이라 세지 않는다.
3. **`primary` 버튼은 화면에 정확히 하나, 상단바의 `▶ 1회 실행`이다.** HUD, 타임라인, 리포트 카드 안에는 없다(`취소`, `닫기`는 `secondary`·`ghost`).
4. **한 번에 한 수준만 연다.** 기본은 상태, 표식 이름표, 속도, L1 문구다. 표식 상세는 hover·포커스·누름으로, 리포트 항목 상세는 접힌 머리 뒤에 있고 한 번에 하나만 펼쳐진다(아코디언) [제안].
5. **같은 정보를 두 곳에 반복하지 않는다.** 원인·시점·여유의 자세한 값은 리포트 카드에만 있고 표식 팝오버는 한 줄 요약이다. 반복이 허용되는 것은 L1 문구뿐이다(SC-01 4절).
6. **증거 색은 증거의 강도다.** 표식·리포트·HUD 칩의 색은 이 실행의 증거 단계 L1 색 하나이고 종류는 모양·이름표·줄로 구분한다. 초록 성공·빨강 실패가 없다. `color.status.*`는 시스템 오류와 엔진 연결 끊김에만 쓴다. 전복·파단은 시스템 오류가 아니다.

## 1. 대목표와 핵심 가치

대목표 G0: 모든 작업이 대목표·핵심 가치·계획에 묶여 한 번에 100% 끝나는 루프를 만든다. 이 화면은 G1에서 "상상한 물건이 움직이는 것을 보고, 어디서 왜 어긋났는지 시점과 함께 아는" 자리다. 없으면 X-02b, X-04c, X-09, X-12, J-04d가 참조할 승인된 디자인이 없다.

> **V1 정직한 판정** — 판정은 시뮬과 몬테카를로만 한다. 확률, 가정, 한계를 숨기지 않는다. 1회 미리보기 실행을 판정이라 부르지 않는다.

> **V3 한 번에 100%** — 작은 단위를 증거와 함께 완전히 끝낸다. 부분 완성은 미완성이다.

V1은 모든 상태에 남는 "1회 실행. 판정이 아닙니다", "단순화 모델", "원인을 증명한 것은 아닙니다", 재생 속도가 물리를 바꾸지 않는다는 문구로, V3은 이슈의 상태 전부와 PC-02 상태(X-09 분리 표식, X-12 재생 속도)를 빠짐없이 그리는 것으로 나타난다.

## 2. 구조

```
┌ 상단바(SC-01) ───────────────────── [▶ 1회 실행] 공유 ⋯ ┐
│ 3D 뷰포트(자리 표시만)       ┌ 실행 HUD ┐ 불투명 bg.panel  │
│                             │ ■ 끝남 · 1회 실행. 판정이 아닙니다 │
├ 타임라인 120 px ─────────────────────────────────────────┤
│ ▾ 타임라인 · L1 1회 실행. 판정이 아닙니다 [실패 리포트 · 원인 1건] [판정 카드 열기]  L3 실물 검증 없음 │
│ [▶] [↺] [느리게|1×|빠르게] 1× `기본값`  0 s ─────── 5 s `시뮬` │
│ 보는 속도입니다. 물리 계산은 같습니다   ◇ 분리(눈금 위 줄)       │
│                                       ▲ 전복  ✕ 파단(아래 줄)  │
└──────────────────────────────────────────────────────────┘
오른쪽 패널(실행 모드): 인스펙터. 리포트를 열면 같은 자리에 리포트 카드(320 px)
```

- 타임라인 치수는 SC-01 그대로다(접힘 32 px, 펼침 120 px, 실행 모드에서 자동 펼침). 120 px에 못 담으면 높이를 바꾸지 말고 목록으로 보고한다.
- **HUD**는 뷰포트 왼쪽 위 2D 카드다. 읽기 전용이다: 상태 칩, L1 문구, 속도가 1×가 아니면 속도 칩, 조종 중이면 조종 기록 칩. 실행 중에만 진행 막대와 `취소`가 더해진다. 불투명 `color.bg.panel` 면이다(`design-system.md` 3.6절).
- **상태 칩**(모양 + 글자, 색은 L1 하나): `○ 실행 전`, `● 실행 중`, `⏸ 일시정지`, `■ 끝남`, `⊘ 취소됨`. 칩에 ▲ ✕ ◇를 쓰지 않는다.
- **리포트 카드**는 오른쪽 패널을 인스펙터와 번갈아 쓴다(`닫기`·`Esc`로 인스펙터로 복귀) [제안]. 판정 모드에서는 판정 카드 자리를 쓴다.
- **주 행동**은 상단바 `▶ 1회 실행`. 실행 중에는 비활성 `실행 중…` [제안]. 새 실행이 이전 기록을 대체하는지 [확인 필요].

## 4. 표식과 정직성 규칙

### 4.1 표식 3종

디자인 시스템 6절의 타임라인 표식(▲ 실패, ✕ 파단)에 **의도한 분리 ◇ 변형 하나를 더한다**(PC-02, X-09). 같은 컴포넌트의 변형이고 디자인 시스템 갱신이 필요한지는 [확인 필요]다. 누름 영역 24×24 px. 상태: 기본, hover, 포커스, 선택됨, 묶음(`+n`), 무효.

| 모양 | 이름표(상시) | 뜻 | 원천 | 실패 원인인가 |
|---|---|---|---|---|
| ▲ 채운 삼각형 | `전복` `슬립` `토크 부족` `추진제 고갈` 또는 `분류되지 않음` | 성공 조건이 실패한 실행의 원인과 시점 | J-06 분류 결과 그대로 | 그렇다 |
| ✕ 교차선 | `파단` | 결합이 임계 초과로 풀림(사유 "임계 초과") | X-04b, X-04c | J-06이 원인으로 뽑은 것만. 아니면 팝오버에 "사건으로만 기록" |
| ◇ 윤곽만 있는 마름모 | `분리` | 스케줄한 **의도한 분리**(사유 "의도한 분리") | X-08, X-09 | **아니다.** 리포트 원인 목록에 넣지 않는다 |

- **구분은 세 겹이고 색은 같다**(L1 색). ① 모양 ② hover 없이 보이는 이름표 ③ 줄: 눈금 **위** 줄은 의도한 일(◇), **아래** 줄은 실행이 일으킨 일(▲ ✕). 의도한 분리와 파단을 같은 표식·줄·이름표로 그리지 않는다. 분리 뒤 다른 결합이 파단되면 ◇와 ✕가 따로 남는다. 가까운 시점은 `+n`으로 접고 누르면 목록이 열린다 [제안].
- ▲는 성공 조건이 실패한 실행에서만 생긴다. 성공한 실행의 공중 구간, 스케줄대로 끝난 연소 같은 정상 변화는 표식이 아니다(J-06). `분류되지 않음`은 성공 조건이 처음 실패로 확정된 시점에 둔다 [제안].
- 팝오버는 한 줄 요약이다. ▲ `원인 · 시점 · 임계 대비 여유`. ✕ `파단 · 결합 이름 · 하중/임계 · 시점 · 단순화 모델`. ◇ `분리 · 분리기 이름 · 시점 · 선언 분리 충격량 [N·s] · 실패 원인이 아닙니다 · 단순화 모델`. 값은 단위·배지(`시뮬`, 충격량은 `사용자 선언` 또는 `기본값`).

### 4.2 정직성 규칙

- **1회 실행은 판정이 아니다.** "1회 실행. 판정이 아닙니다"는 모든 상태·속도·접힌 타임라인에 남는다. 이 화면에 `p_success`, CI, 민감도, 판정 코드를 그리지 않는다. 결과는 "이번 실행에서는 …"로만 말한다.
- **원인·시점·여유는 J-06의 분류 결과를 그대로 표시한다**(J-04d). 화면이 다시 계산하거나 원인을 지어내지 않고 `분류되지 않음`도 그대로 보인다. 리포트의 고정 문구: "성공 조건이 실패하기 전에 임계를 넘은 사건입니다. 원인을 증명한 것은 아닙니다."와 "1회 실행의 기록이고 판정이 아닙니다". 에이전트 설명(G-05)은 이 수치만 인용한다.
- **파단은 "단순화 모델"** 표시가 항상 붙는다. 시간 간격 민감(X-10)이면 "시간 간격 민감: 파단 결과가 약한 증거"와 약한 증거 변형(바탕을 비우고 점선 테두리). 풀려 나간 조각은 끝까지 시뮬되어 남는다(X-13): 파단 팝오버에 한 줄.
- **재생 속도는 보는 속도일 뿐이다**(X-12). 물리 시간 간격과 궤적 해시를 바꾸지 않고 실행 요청에 속도가 실리지 않는다. 속도를 바꿔도 눈금, 표식 시점, L1 문구는 그대로다. 정확도를 바꾸는 물리 시간 가속은 컨트롤도 이름도 없다("가속" 금지). 단계 배율은 설정 값이라 `기본값` 배지가 붙고 값은 X-12가 정한다. 이 브리프의 0.25×, 1×, 2×는 `예시`다 [확인 필요]. Halo 프레임 캡처는 이 설정과 무관하다(팝오버 한 줄).
- **표본 하나를 대표 결과처럼 보이지 않는다.** 성공 조건을 충족한 실행의 리포트는 "이번 실행에서는 성공 조건을 충족했습니다. 표본 하나이며 판정이 아닙니다. 실패 원인 0건".
- 설계나 행성을 바꾸면 이전 실행 기록은 **무효**다: `color.evidence.none` + "무효: 이전 설계의 실행입니다. 다시 실행해야 이 설계의 결과가 됩니다" [제안].
- 예시 수치는 `design-system.md` 10절의 값뿐이고 나머지는 `예시`다. 다른 제품의 표식 모양·색·용어·단계 값을 옮기지 않는다(`docs/research/benchmarks/kerbal-space-program.md` 5절).

## 6. 규칙

- 증거 색은 5.2절 그대로다. 표식·리포트·HUD 칩은 L1 색 하나이고 종류는 모양·이름표·줄로 구분한다(1.4.1).
- 대비 4.5:1, 비문자 3:1, 누르는 영역 24×24 px 이상, 포커스 링 2 px `color.focus.ring` + 2 px 간격.
- 키보드로 모든 행동. 속도는 라디오 그룹, 표식 줄은 한 탭 정지 + `←` `→`, 스크러버는 슬라이더(`aria-valuetext` "2.4 초"). `Esc`는 팝오버를 닫고 한 번 더 누르면 리포트를 닫는다. 상태가 바뀌면(실행 중 → 일시정지 → 끝남) 스크린리더에 읽어 준다.
- 재생은 저절로 움직이므로 멈춤(▶/⏸)이 항상 있다(WCAG 2.2.2). `prefers-reduced-motion`이면 HUD·카드 등장은 불투명도 전환만. 결과는 어떤 종류든 같은 전환이고 전복·파단에 연출 효과가 없다(`design-system.md` 3.7절).
- 색은 `tokens.json`의 값만. 새 색 토큰 금지.
- 금지 문구: `design-system.md` 9절 전체. 특히 "현실과 동일", "검증됨", "보장", 1회 실행을 판정·"성공 확인"·"통과"로 부르기, 에이전트가 판정을 선언하는 문구, 파단을 정밀 해석처럼 말하기, "가속"류 이름.
