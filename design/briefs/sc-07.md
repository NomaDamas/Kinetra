## 0. 창업자 지시: 하드 제약 (모든 화면에 적용, 2026-11-10, #33 승인 코멘트)

> 창업자 지시: "있는 기능들은 모두 다 포함되어야 하는데 사용자가 보는 UI/UX는 간단해야 해. 인지부하 없게끔."

```text
첫 조건: 기능은 빠짐없이, 화면은 단순하게, 인지부하는 최소로.
- 이 화면이 맡은 기능은 하나도 빼지 않는다. 빼는 것은 "보이는 양"이지 기능이 아니다.
- 기본 화면에는 주 행동 하나와 지금 필요한 정보만 보인다.
- 나머지 기능은 단계적으로 드러낸다(진행형 공개). 숨은 기능마다 어디서 어떻게 여는지(단추, 접힘, 메뉴, 단축키)를 화면에 그리고 기능 목록과 화면 위치 대응표를 함께 낸다.
```

어긴 아트보드는 승인하지 않는다. 이 화면에서 구체적으로:

1. **기능을 빼서 단순하게 만들지 않는다.** 3절 표의 모든 기능이 최대 2단계 안에서 닿는다. **정직성 요소는 줄이지 않는다**(V1): 세 행성을 나란히 놓아도 "1회 실행. 판정이 아닙니다", 모델 라벨 "근사: 균일 중력(행성별 g 하나)", 가정표, "이 모델이 보지 않는 것", L3 "실물 검증 없음"은 접어도 이름과 개수가 항상 보인다.
2. **기본 화면(S1)의 상시 조작 요소는 10개 이하**이고 5.1절에 이름을 못 박았다. 세는 법(SC-01·SC-04와 같다): 버튼, 입력, 선택 컨트롤, 접기·펼치기 머리, 누를 수 있는 값 배지가 각각 1. 읽기 전용 글자, 단위, 구분선, 행성 이름, 3D 자리 표시는 세지 않는다. 비교 보기 바깥(상단바, 에이전트 바)은 세지 않는다. 한 행의 세 값이 같은 출처 종류면 배지는 행 머리에 한 번만 둔다.
3. **`primary` 버튼은 화면에 하나이고 상단바의 모드 주 행동이다.** 비교 보기 안에 `primary`가 없다. 비교 보기에서는 모드의 주 행동이 세 행성에 같이 적용된다(`▶ 1회 실행`, `판정 실행`). 문구는 SC-01을 따르고 뒤에 `· 3행성`만 붙는다 [제안]. 행성마다 `primary`를 두지 않는다.
4. **한 번에 한 수준만 연다.** 기본은 세 장면, 공통 타임라인, 수치 두 행, 접힌 머리 둘(가정 비교, 이 모델이 보지 않는 것)까지다. 머리는 하나만 열린다(아코디언) [제안].
5. **같은 정보를 두 곳에 반복하지 않는다.** "1회 실행. 판정이 아닙니다"는 비교 보기 머리에 한 번, 장면마다는 칩 `1회 실행 · 판정 아님`(5.1절 좁은 곳 문구)이다. 모델 라벨도 한 줄 한 번이다.
6. **색은 증거의 강도 하나다.** 행성마다 색을 주지 않는다(`design-system.md` 6절 "행성별 색으로 구분하지 않는다"). 지구·화성·달은 **이름 글자와 고정 순서**로만 구분한다. 행성 정체성 색 토큰은 없고 새로 만들지 않는다. 어느 행성이 낫다는 표시(승자 강조, 순위, 초록·빨강, 신호등, 히트맵)가 없다.

## 1. 대목표와 핵심 가치

대목표 G1: 창업자가 세 행성 어디서든 상상한 물건을 만들어 정직한 판정이 붙은 Halo로 내보낸다. 같은 설계를 지구·화성·달에서 돌려 보는 것이 이 제품의 차별점이고(데모 Halo: 로켓 자동차 공중제비 세 행성 비교, 같은 로버가 세 행성에서 경사를 오르는가), 이 화면이 없으면 W-04 구현이 참조할 승인된 디자인이 없다.

> **V1 정직한 판정** — 판정은 시뮬과 몬테카를로만 한다. 확률, 가정, 한계를 숨기지 않는다. 1회 미리보기 실행을 판정이라 부르지 않는다.

> **V3 한 번에 100%** — 작은 단위를 증거와 함께 완전히 끝낸다. 부분 완성은 미완성이다.

V1은 전환 뒤 이전 판정의 **무효 표시**, 나란히 재생이 세 번의 1회 실행일 뿐 판정이 아니라는 문구, 균일 중력 가정의 노출, 순위를 매기지 않는 비교 문구로 나타난다. V2는 "이 설계가 달에서는 어떻게 되는가"를 코드 없이 바로 보는 흐름으로, V5는 행성 상수의 출처 배지(출처를 못 찾은 항목은 `unverified`, W-01)로 나타난다.

## 2. 구조

**전환**: SC-01 상단바의 행성 전환기 `지구 | 화성 | 달`(라디오 그룹, 글자 라벨)을 그대로 쓴다. 이 화면이 더하는 것은 상태(컴파일 중, 비활성 이유, 전환 뒤 안내)와 비교 보기의 열림 경로다.

```
상단바: … 행성[지구|화성|달] │ 모드 │ [무효: 행성 변경] ……… [주 행동] 공유 ⋯
안내 한 줄: 달로 바꿨습니다. 이전 판정은 무효입니다. 다시 판정해야 합니다.  [3행성 비교] [행성 정보] ✕
```

**비교 보기**: 뷰포트 자리를 3분할로 바꾸는 보기다(양쪽 패널은 접힘, 에이전트 바는 그대로) [제안]. 실행·판정 모드에서만 연다.

```
┌ 비교 보기 · 같은 설계 · 같은 시드 · 행성 상수만 다름 ············ [증거 배지] [닫기] ┐
│ 1회 실행. 판정이 아닙니다 · 근사: 균일 중력(행성별 g 하나) · 시드 …(읽기 전용)       │
├──────────────┬──────────────┬──────────────┤
│ 지구 [1회 실행·판정 아님] │ 화성 [같은 칩] │ 달 [같은 칩] │  3D 자리 표시 ×3, 같은 t에 동기
├──────────────┴──────────────┴──────────────┤
│ ▶⏸ ↺ ──●────  t = 2.4 s  [속도 1×]   행성별 표식 레인(지구 / 화성 / 달)        │
├──────────────────────────────────────────────┤
│ 행              지구        화성        달                                       │
│ 추력 대 중량비 [행 배지]  값 단위   값 단위   값 단위   L0 해석 계산                 │
│ 이번 실행 …  [행 배지]  값 단위   값 단위   값 단위   "이번 실행에서는"             │
│ 판정            판정 없음   판정 없음   판정 없음  (판정 실행 뒤 열마다 요약)       │
├──────────────────────────────────────────────┤
│ ▸ 가정 비교 · 행성마다 다른 가정 n개   ▸ 이 모델이 보지 않는 것 · n개              │
│ L3 실물 검증 없음 (실측 0건)                                                       │
└──────────────────────────────────────────────┘
```

- 세 칸의 순서는 **지구, 화성, 달 고정**(전환기와 같은 순서)이고 현재 행성은 글자 "현재"로만 표시한다.
- 세 칸은 같은 설계, 같은 제어 스케줄, 같은 시드로 돈다. 설계는 행성 사이에 그대로이고 **자동으로 고치지 않는다**(W-04 범위 밖). 이 문장은 머리에 읽기 전용 글자로 있다.
- 장면은 같은 시뮬 시각 `t`에 동기한다 [제안]. 한 칸이 먼저 끝나면(전복 등) 마지막 프레임에서 멈추고 "이 실행은 t = … s에서 끝났습니다"가 붙는다(`예시`).
- 추력 대 중량비의 행 배지는 입력 중 가장 약한 배지를 따른다(B-14, X-07). 예: 노즐당 추력 8 kN이 `카탈로그 밖 · 사용자 선언`이면 행 배지는 `사용자 선언`.

## 4. 정직성 규칙

- **나란히 재생은 세 번의 1회 실행이다.** 각 칸에 `1회 실행 · 판정 아님` 칩, 머리에 "1회 실행. 판정이 아닙니다"가 접히지 않고 남는다. 한 장면을 "대표 결과"나 "된다/안 된다"로 쓰지 않는다("이번 실행에서는 …").
- **전환하면 이전 판정은 무효다.** `color.evidence.none` + "무효: 행성 변경". 이전 확률을 큰 글자로 남기지 않고 작은 글씨 "이전 판정 · 지구 기준 · 무효"만 둔다. 현재 판정처럼 보이면 안 된다.
- **비교 열의 판정은 그 행성에 묶인다** [제안]. 설계나 가정이 바뀌면 세 열이 모두 무효다. 행성 전환이 비교 열의 판정까지 무효로 만드는지는 W-04a·b가 정한다 [확인 필요].
- **판정 열 4종**은 `design-system.md` 5.1절 표 그대로다. `FEASIBLE_FOUND`만 `p_success` + 95% CI + 표본 수 + 민감도 1위. `INFEASIBLE_NECESSARY_CONDITION`(어긴 필요조건과 여유), `NOT_FOUND_IN_BUDGET`(약한 증거 변형: 바탕 비움 + 점선 + "약한 증거", 쓴 탐색 예산), 모델 밖(`color.evidence.none`, 모델이 다루지 않는 현상)은 "확률 미산출 · 이유", "민감도 미산출 · 이유". 빈칸, `0%`, `–`로 두지 않는다. 둘을 "불가능"으로 쓰지 않는다.
- **비교 문구는 숫자와 구간만 나란히 놓는다.** 순위, "더 높음", "가장 안전", 승자 강조 없음. 신뢰구간이 겹치는지는 사실로만 쓴다("신뢰구간이 겹칩니다"). 표본 수나 시드가 열마다 다르면 머리에 "표본 수가 다릅니다" 한 줄 [제안].
- **균일 중력 가정을 숨기지 않는다**(W-06). 세 행성 모두 "근사: 균일 중력(행성별 g 하나)"가 가정표와 머리에 항상 있고, "이 모델이 보지 않는 것"에 "높이에 따른 중력 변화, 중력 구배"가 자동으로 들어간다. 라벨은 표시일 뿐 g 값을 바꾸지 않는다.
- **행성 상수는 읽기 전용**이다(C-02: 행성 상수 변경 시도는 거부된다). 편집 입력이 없다. 값은 `인용`, 출처를 못 찾은 항목은 `unverified`(W-01). 이 브리프는 실제 상수 값을 정하지 않는다.
- **추력 대 중량비(L0)**는 "해석 계산"이고 1보다 크다고 "뜬다"고 쓰지 않는다. 추력기가 없으면 그 행을 표시하지 않는다(0이나 가짜 값 금지, B-14).
- **성공·실패를 색으로 말하지 않는다.** 전복·슬립·파단은 시스템 오류가 아니다: 표식은 그 실행의 증거 단계 색 + 모양(▲, ✕) + 글자이고 `color.status.*`를 쓰지 않는다. 파단은 "단순화 모델".
- **재생 속도는 보는 속도다.** 속도가 1×가 아니어도 L1 문구와 표식 시점은 그대로다.
- 판정은 시뮬과 몬테카를로만 한다. 에이전트가 판정을 선언하는 문구("에이전트가 달에서 가능하다고 판정했습니다")는 없다.
- **수치는 `design-system.md` 10절의 값만 쓰고 나머지는 `예시` 꼬리표.** 쓸 수 있는 값: 차체 질량 1.3 t `사용자 선언`, 노즐당 추력 8 kN `카탈로그 밖 · 사용자 선언`, `p_success` 15.2% [12.3, 18.6] n = 500 `시뮬`(한 열에만, 어느 행성의 값인지 10절에 없으므로 `예시` 꼬리표 [확인 필요]). 행성 상수와 다른 열의 확률·시간·추력 대 중량비는 모두 `예시`다.

## 6. 규칙

- 증거 단계 색은 5.2절 그대로다. 행성이 달라도 같은 단계면 같은 색. 판정 열의 구분은 코드, 문구, 모양, 숫자로.
- 모든 텍스트 대비 4.5:1, 비문자 3:1, 누르는 영역 24×24 px 이상, 포커스 링 2 px `color.focus.ring` + 2 px 간격. `prefers-reduced-motion`이면 전환은 불투명도만. 판정 결과는 어떤 코드든 같은 전환(축하·흔들림 없음). 5초 넘게 저절로 움직이는 재생에는 일시정지 수단이 있다.
- 키보드로 모든 행동. 행성 전환기는 라디오 그룹(화살표), 머리는 Enter/Space, `Esc`는 팝오버·비교 보기를 닫는다. 단축키는 툴팁에 적는다 [제안].
- 스크린리더: 행성이 바뀌면 "달로 전환. 이전 판정은 무효입니다", 증거 단계가 바뀌면 문구를 읽는다. 세 장면은 이름과 `1회 실행 · 판정 아님`을 함께 읽는다.
- 색은 `tokens.json`에 있는 값만. 새 색 토큰, 행성별 색 금지. 너비 1280 미만의 세 칸 배치는 정하지 않는다 [확인 필요].
- 금지 문구: `design-system.md` 9절 전체. 특히 "현실과 동일", "검증됨", "보장", 1회 실행을 판정이라 부르기, "달에서는 된다/안 된다", "뜬다", 에이전트의 판정 선언, `NOT_FOUND_IN_BUDGET`·모델 밖을 "불가능"이라 쓰기, 확률을 성공/실패로 부르기.

## 7. 이 브리프가 정하지 않는 것

행성 데이터 값과 출처(W-01), 행성별 3D 장면(코드 프로토타입), 재컴파일·실행·몬테카를로의 계산과 표본 수·예산(J-01), 행성별 설계 자동 조정(범위 밖), 판정 카드 내부(SC-04), 실행 HUD·타임라인 전체·실패 리포트 카드(SC-06), 조립 모드의 추력 대 중량비 표시(SC-15, B-14), 비교를 Halo에 담는 것(SC-08), 공유 페이지(SC-09), XR(SC-11), 상단바 더보기 메뉴의 항목 추가(SC-01 변경 여부).
