## 자기 점검

수치는 `measure.html`을 헤드리스 Chrome 157로 열어 잰 것이다(`source/tools/measure.sh`, 임시 `--user-data-dir`은 `/tmp/kin-sc05-chrome.*`, 실행마다 지웠고 남은 것 0개. 사용자 Chrome 프로필과 실행 중인 Chrome은 건드리지 않았다). 마지막에 이 폴더의 `source/`로 다시 재서 같은 결과를 얻었다. 측정 환경에 Pretendard와 JetBrains Mono가 없어 시스템 글꼴로 쟀다. 캔버스 페이지 자체는 열지 않았다.

세는 법: 누를 수 있는 것에 `data-ctl`, primary에 `data-primary`. 같은 `data-ctl` 이름은 한 조작이다(목록, 탭 묶음, 값 배지 열은 각 1. SC-01 #9 · #10과 같다). 펼친 줄 · 팝오버 · 메뉴 · 카드 안은 따로 센다(`+n`). 가림막 뒤 셸과 상단바 조각은 세지 않는다. 표시 없는 버튼 · 입력은 0건이다.

## 브리프에서 벗어난 곳과 확인 필요

1. **마법사의 값 배지.** 5.3절의 단계별 수에는 값 배지가 없지만, 0절 2의 세는 법은 "누를 수 있는 값 배지"를 1로 세고 디자인 시스템 4절은 배지를 늘 누를 수 있게 한다. 배지를 빼면 정직성 요소를 줄이게 되므로(0절 1) 그대로 두고, S1의 #6처럼 단계 안의 배지 전체를 한 묶음(1)으로 셌다. 그래서 각 단계는 "5.3절 수 + 1"이다 [확인 필요: 5.3절에 값 배지 묶음을 넣을지].
2. **기본 정렬의 줄 값.** 2절은 "기본 · 질량 정렬은 질량"이라 하고, 5.1절 S1과 2절 그림은 냉가스 추력기 줄에 8.9 N `인용`을 둔다. S1을 따라 기본 정렬에서는 부품의 대표 사양(추력기는 최대 추력, 나머지는 질량)을 보였고, 이름 · 질량 정렬에서는 모든 줄이 질량이다 [확인 필요].
3. **조립체 질량 합 1.3 t.** 10절의 1.3 t는 차체 질량 `사용자 선언`이다. S7은 조립체 "질량 합 1.3 t"를 요구하고 4절은 질량 합을 `시뮬`로 정한다. 그래서 `시뮬` + `예시`로 그렸다(S7, S8, S15, S21) [확인 필요].
4. **이름 바꾸기 · 삭제의 `⋯`.** 모든 줄에 늘 보이면 S7의 7 · 8개를 넘는다. 고른(포커스 · 누른) 줄에만 `⋯`가 나타나고 목록의 일부로 셌다. 키 `F2` `Delete` `Shift F10`과 패널 아래 키 줄로 입구를 보였다. 줄을 고르는 것은 단계로 세지 않았다 [확인 필요]. 삭제 규칙("이미 놓은 부품은 그대로입니다")은 브리프대로 [확인 필요].
5. **단위 제안의 기록 시점.** 단위가 `추정`인 채로 `다음`을 누르면 그 단위를 `사용자 선언`으로 기록한다고 발밑 줄에 적었다. 프록시도 같다 [제안]. 질량은 브리프대로 직접 정하기 전에는 `다음`이 비활성이다.
6. **내 것의 출처 먼저 순서.** 사용자 선언 → 시뮬, 같은 출처 안에서 최근 것 먼저 [제안]. 그래서 새로 가져온 줄이 맨 위에 온다(S15). 전체 순서는 인용 → 기본값 → 사용자 선언 → 시뮬 → 추정 → 정의 없음.
7. **필터 버튼 글자.** 기본은 "필터 0", 적용 뒤는 "필터 적용 2"로 개수 알약 안 글자만 바꿨다.
8. **엔진 오프라인에서 파일 읽기와 1/4 단계.** 브리프대로 [확인 필요]로 두고 2/4만 막았다.
9. **볼록 분해 도구.** 이름 · 버전 · 라이선스를 빈 칸 틀로 그렸다 [확인 필요: L-02b].
10. **라이선스 목록**(CC0 · CC BY · 직접 제작 · 모름)과 원장 문구는 브리프의 [제안] 그대로.
