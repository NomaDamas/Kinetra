## 쓰는 법

```python
from kinetra_engine.compiler import build_body_tree, compile_drives, to_mjcf, DriveRuntime
tree = build_body_tree(project)
drives = compile_drives(tree)                 # Drives, 아니면 CompileError
model = mujoco.MjModel.from_xml_string(to_mjcf(tree, drives=drives))
runtime = DriveRuntime(model, drives)         # 실행 하나: 배터리 잔량을 쥔다
runtime.apply(data, {"drive": 1.0}, dt)       # 매 mj_step 앞: data.ctrl을 쓰고 에너지를 꺼낸다
```

힌지와 슬라이더 자체(축, 결합점, 한계, 좌표 0 = 저장된 자세)는 X-01a의 바디 트리가 이미 MJCF로 낸다(`body-tree.md`). 이 잎은 거기에 스프링·댐퍼와 모터를 더한다.

## 스프링-댐퍼 → 슬라이더의 `stiffness`·`damping`

- 역할 `spring_damper`인 부품의 인스턴스는 **자기 스냅 포인트에 걸린 슬라이더 하나**를 따라 작용한다. 그 슬라이더의 MJCF `joint`에 인스턴스 값(없으면 부품 기본값)의 `stiffness`[N/m]와 `damping`[N·s/m]을 그대로 적는다. 스프링 힘 0점은 결합 좌표 0(저장된 자세, MJCF `springref` 0)이다.
- 컴파일 오류(`CompileError`, 인스턴스·결합·부품 id): 움직이는 결합이 없음(어디에도 작용하지 않는다), 둘 이상(두 번 작용한다), 그 하나가 힌지(N/m은 회전 강성이 아니다), 한 슬라이더의 양끝이 둘 다 스프링-댐퍼.
- 스프링이 없는 힌지·슬라이더에는 강성도 감쇠도 없다.

## 모터 → `<motor>`와 토크-속도 제한

- 모터 액추에이터(`kind: motor`)는 역할 `motor`인 부품의 인스턴스에 있고 **힌지**를 구동한다. MJCF는 `<motor joint gear="1" ctrlrange="±T0">`이고 `ctrl`은 결합 토크[N·m]다. `DriveRuntime`이 매 단계 명령과 결합 속도로 `ctrl`을 쓴다. 역할 없는 부품(곡선 없음)이나 슬라이더(곡선은 N·m 대 rad/s)는 컴파일 오류다.
- **명령의 뜻.** 곡선은 명령 1, 정격 전압에서의 토크 한계다. 명령 $u\in[-1,1]$은 정격 전압의 비율과 방향(PWM 듀티)이다. 직류 모터는 전압이 $a=|u|$배면 토크-속도 선이 두 축 모두 $a$배가 되므로 토크는 $\tau = u\,T(s/a)$, $s$는 명령 방향의 결합 속도, $T$는 부품 곡선(`motor_torque_limit`)이다. 직선 곡선이면 정확히 $T_0(u-\omega/\omega_0)$다.
  - 명령 $u$의 무부하 속도는 $|u|\omega_0$다. 그 너머는 토크 0(곡선이 0으로 끝난다. 제동 사분면은 모델에 없다).
  - 반대로 끌려 돌면($s<0$) 정지 토크 $T_0$(곡선의 첫 점, 바깥으로 연장하지 않는다).
  - 명령 0은 토크 0(관성으로 돈다).
- 축 방향: 양의 명령은 결합 좌표를 양으로 민다. `b`쪽에서 만난 결합(축이 뒤집힌 결합)도 좌표가 프로젝트 결합의 것이라 같다.

## 배터리 소모 (`Actuator.supply`)

- 직류 모터의 전류는 토크에 선형이고 데이터시트가 양끝을 준다: $I = I_0 + (I_s - I_0)\,|\tau|/T_0$(사양 `no_load_current`, `stall_current` [A], 곡선의 정지 토크). 그래서 계량하는 모터의 부품에는 두 전류 사양이 있어야 한다(없으면 컴파일 오류).
- 명령 $u$에서 배터리가 내는 전력은 $P = |u|\,V\,I$(V는 정격 전압, PWM 평균). 매 단계 $P\,dt$를 배터리 인스턴스 하나당 하나인 `Supply`에서 꺼낸다(`parts-battery-tank.md`). 덜 받으면(`satisfied < 1`) 그 단계의 토크에 `satisfied`를 곱하고, 빈 배터리는 아무것도 구동하지 않는다. 한 배터리를 나눠 쓰는 모터는 액추에이터 id 순으로 꺼낸다. 되돌려주지 않는다(회생 없음).
- 37D 모터면 무부하에서 $12\times0.2 = 2.4$ W, 정지에서 $12\times5.5 = 66$ W다(데이터시트의 정격 전압 전류).

## 시험 (DoD 증거)

모든 기대값은 부품이 인용한 데이터시트 값과 교과서 식으로 손으로 적었다. MuJoCo 4.0.0이 컴파일된 MJCF를 돌린다. 시험은 리그의 루트를 월드에 고정(MJCF의 자유 관절을 지움)하고 필요한 중력을 모델에 직접 넣는다(행성 `<option>`은 W-03a). 고정한 루트는 MuJoCo가 자식과 충돌시키므로 지면이 없는 리그에서는 접촉을 끈다. 리그의 결합 스냅 포인트는 저장된 자세에서 만나고, 조립체는 지면(z = 0)에 닿는다.

| 시험 | 기대(손계산) | 측정 |
|---|---|---|
| 무부하 속도, 명령 1, 0.5, -1, -0.25 | $u\times200$ rpm $= u\times20.944$ rad/s | 상대 1e-6 안 |
| 정지 토크, 힌지 한계에 밀어붙임, 명령 1, 0.5 | $u\times210$ kg·mm $= u\times2.0594$ N·m, 한계의 구속력이 같은 크기 반대 | 상대 1e-4 안 |
| 토크-속도 곡선(속도 0, $\omega_0/2$, $\omega_0$, $3\omega_0$, 역회전, 명령 0.5와 음수) | 위 식 | 상대 1e-12 |
| 배터리: 무부하 1 s, 정지 1 s | 2.4 J, 66 J | 상대 1e-6, 1e-4 |
| 배터리: 셀의 1e-4(4.212 J)로 정지 | 63.8 ms 뒤 비고 토크 0 | 꺼낸 에너지 상대 1e-12 |
| 스프링 0.5 kg, $k=5990$ N/m, 감쇠 0 (RK4, 10 µs) | $T = 2\pi\sqrt{m/k} = 57.4052$ ms | 상대 약 1e-11 |
| 같은 스프링, 감쇠 20 N·s/m | $T_d = 58.3883$ ms, 봉우리 비 0.31106 | 상대 약 6e-7, 1e-3 안 |
| B-03a 휠 30° 경사, 지구·화성·달(`load_body` 중력) | $a = g\sin\theta/(1+k)$, 컴파일된 $k = I_{yy}/(mR^2) = 0.462518$ | -0.12 %, -0.045 %, -0.020 % (허용 0.2 %), $v=\omega R$ 0.13 % 안 |

**구름 시험의 경사.** 휠은 지면 z = 0에 서 있고, 경사 30°는 행성 중력을 휠 축 둘레로 30° 돌린 $g(\sin\theta, 0, -\cos\theta)$로 준다. 평면의 좌표계에서 보면 수직 중력 아래 30° 기운 평면과 같은 문제다(조립체가 지면에 닿아 있다는 배치 규칙을 지키려는 선택). 지면과 트레드 마찰은 MuJoCo 기본값 1이다. 접촉 매개변수와 마찰 합성은 아직 컴파일하지 않는다.

## 한계 (숨기지 않는다)

- **구름 오차는 MuJoCo의 소프트 접촉에서 온다.** 지구에서 가속도가 손계산보다 0.12 % 작고 접촉점이 $v$의 0.13 % 미끄러진다. 기본 접촉 매개변수의 값이고 이 PR은 그 매개변수를 정하지 않았다.
- **회전자 관성, 기어 백래시와 효율 곡선이 없다.** 곡선이 출력축 토크이고 기어 손실은 그 안에 들어 있다고 본다.
- **전류 모델은 데이터시트 두 점을 이은 직선이다.** 끌려 도는 구간($s<0$)은 정지 전류를 쓴다(실제로는 역기전력으로 더 크다). PWM은 평균으로만 본다.
- **배터리 전압은 쓰지 않는다.** 토크 곡선은 모터 정격 전압의 것이고 배터리 `nominal_voltage`가 달라도(4S 팩 14.4 V 대 모터 12 V) 곡선을 바꾸지 않는다.
- **비틀림 스프링이 없다.** 스프링-댐퍼 부품은 축 방향(N/m)뿐이라 힌지에 걸 수 없다.
- 연속 부하 상한(`continuous_torque_limit`)으로 토크를 자르지 않는다(가열 모델이 없다).
