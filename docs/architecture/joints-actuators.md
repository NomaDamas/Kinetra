## 쓰는 법

```python
from kinetra_engine.compiler import build_body_tree, compile_drives, to_mjcf, DriveRuntime
tree = build_body_tree(project)
drives = compile_drives(tree)                 # Drives, 아니면 CompileError
model = mujoco.MjModel.from_xml_string(to_mjcf(tree, drives=drives))
runtime = DriveRuntime(model, drives)         # 실행 하나: 배터리 잔량을 쥔다
runtime.apply(data, {"drive": 1.0}, dt)       # 매 mj_step 앞: data.ctrl을 쓰고 에너지를 꺼낸다
```

힌지와 슬라이더 자체(축, 결합점, 한계, 좌표 0 = 저장된 자세)는 X-01a의 바디 트리가 이미 MJCF로 낸다(`body-tree.md`). 이 잎은 거기에 스프링·댐퍼와 모터를 더한다.

## 스프링-댐퍼 → 슬라이더의 `stiffness`·`damping`

- 역할 `spring_damper`인 부품의 인스턴스는 **자기 스냅 포인트에 걸린 슬라이더 하나**를 따라 작용한다. 그 슬라이더의 MJCF `joint`에 인스턴스 값(없으면 부품 기본값)의 `stiffness`[N/m]와 `damping`[N·s/m]을 그대로 적는다. 스프링 힘 0점은 결합 좌표 0(저장된 자세, MJCF `springref` 0)이다.
- 컴파일 오류(`CompileError` 코드 `spring_joint`, 인스턴스·부품·결합 id, `body-tree.md`의 표): 움직이는 결합이 없음(어디에도 작용하지 않는다), 둘 이상(두 번 작용한다), 그 하나가 힌지(N/m은 회전 강성이 아니다), 한 슬라이더의 양끝이 둘 다 스프링-댐퍼.
- 스프링이 없는 힌지·슬라이더에는 강성도 감쇠도 없다.

## 모터 → `<motor>`와 토크-속도 제한

- 모터 액추에이터(`kind: motor`)는 역할 `motor`인 부품의 인스턴스에 있고 **힌지**를 구동한다. 슬라이더(곡선은 N·m 대 rad/s)는 컴파일 오류 `motor_joint`다. 역할 없는 부품(곡선 없음)은 `build_body_tree`가 먼저 `no_curve`로 거부한다(X-01d).
- **명령의 뜻.** 곡선은 명령 1, 정격 전압에서의 토크다. 명령 $u\in[-1,1]$은 정격 전압의 비율과 방향(PWM 듀티, $a=|u|$)이다. 직류 모터의 토크는 전압과 속도에 선형이다: $\tau = u\,T_0 - (T_0/\omega_0)\,\omega$($T_0$ 정지 토크, $\omega_0$ 무부하 속도, 곡선의 두 끝). 둘째 항이 역기전력이고 명령과 무관하다. 곡선의 범위 안($0 \le s < a\omega_0$, $s$는 명령 방향의 결합 속도)에서 토크는 곡선 $u\,T(s/a)$이고, 범위 밖은 곡선이 말하지 않으므로 이 직선이다(`MotorDrive.torque`). 라이브러리의 직선 곡선이면 둘은 하나다.
  - 명령 $u$의 무부하 속도는 $|u|\omega_0$다. 그 너머에서는 **제동한다**(역기전력, 직선의 연장).
  - 반대로 끌려 돌면($s<0$) 직선대로 정지 토크보다 크다.
  - 명령 0은 0 V(단자 단락)이고 $-(T_0/\omega_0)\,\omega$로 제동한다.
- **역기전력은 결합의 감쇠다(#546).** MJCF는 모터가 구동하는 힌지에 `damping` $= T_0/\omega_0$(그 힌지의 모터 합)을 적고, MuJoCo의 Euler 적분기는 결합 감쇠를 암시적으로 푼다($(M + hD)\,\ddot q = f$). 액추에이터는 `<motor joint gear="1" ctrllimited="false">`이고 `ctrl`은 나머지 $\tau + (T_0/\omega_0)\,\omega$(`MotorDrive.ctrl`)를 `DriveRuntime`이 매 단계 쓴다. 직선 곡선이면 `ctrl` $= u\,T_0$ 상수라 속도에 따르는 항이 명시적으로 남지 않는다. MuJoCo가 `ctrl`을 자르지 않게 했다(자르면 곡선이 준 토크가 바뀐다).
  - 고른 이유: 이전처럼 단계 시작 속도로 토크를 명시적으로 주면, 회전축 둘레 관성이 작은 몸체(자유 루트의 모터 몸체, 3e-5 kg·m²)에 정지 토크 한 단계가 약 137 rad/s를 줬다(무부하 20.9 rad/s, #546). 속도로 토크를 포화시키는 방법은 그 단계의 과속을 막지 못하고, 시간 간격을 줄이는 방법은 모든 모델의 비용을 바꾼다. `<general>` 액추에이터의 속도 바이어스는 `implicitfast` 적분기가 있어야 암시적이라 모든 모델의 적분을 바꾼다. 결합 감쇠는 적분기를 바꾸지 않고 같은 효과를 낸다.
- 축 방향: 양의 명령은 결합 좌표를 양으로 민다. `b`쪽에서 만난 결합(축이 뒤집힌 결합)도 좌표가 프로젝트 결합의 것이라 같다.

## 배터리 소모 (`Actuator.supply`)

- 직류 모터의 전류는 토크에 선형이고 데이터시트가 양끝을 준다: $I = I_0 + (I_s - I_0)\,\tau_d/T_0$, $\tau_d$는 명령 방향의 토크(0 아래는 0: 제동은 전류를 더하지 않는다)(사양 `no_load_current`, `stall_current` [A], 곡선의 정지 토크). 그래서 계량하는 모터의 부품에는 두 전류 사양이 있어야 한다(없으면 컴파일 오류 `no_current`).
- 명령 $u$에서 배터리가 내는 전력은 $P = |u|\,V\,I$(V는 정격 전압, PWM 평균). 매 단계 $P\,dt$를 배터리 인스턴스 하나당 하나인 `Supply`에서 꺼낸다(`parts-battery-tank.md`). 덜 받으면(`satisfied < 1`) 그 단계의 구동 몫(`ctrl`)에 `satisfied`를 곱하고, 빈 배터리는 구동하지 않는다(역기전력 감쇠는 남는다: 0 V). 한 배터리를 나눠 쓰는 모터는 액추에이터 id 순으로 꺼낸다. 되돌려주지 않는다(회생 없음).
- 37D 모터면 무부하에서 $12\times0.2 = 2.4$ W, 정지에서 $12\times5.5 = 66$ W다(데이터시트의 정격 전압 전류).

## 시험 (DoD 증거)

모든 기대값은 부품이 인용한 데이터시트 값과 교과서 식으로 손으로 적었다. MuJoCo 4.0.0이 컴파일된 MJCF를 돌린다. 시험은 리그의 루트를 월드에 고정(MJCF의 자유 관절을 지움)하고 MJCF `<option>`의 행성 중력(W-03a)을 시험에 필요한 값으로 덮어쓴다(모터·스프링 리그는 0, 구름은 `load_body` 중력을 30° 돌린 것). 고정한 루트는 MuJoCo가 자식과 충돌시키므로 지면이 없는 리그에서는 접촉을 끈다. 리그의 결합 스냅 포인트는 저장된 자세에서 만나고, 조립체는 지면(z = 0)에 닿는다.

## 한계 (숨기지 않는다)

- **구름 오차는 MuJoCo의 소프트 접촉에서 온다.** 지구에서 가속도가 손계산보다 0.12 % 작고 접촉점이 $v$의 0.13 % 미끄러진다. 기본 접촉 매개변수의 값이고 이 PR은 그 매개변수를 정하지 않았다.
- **회전자 관성, 기어 백래시와 효율 곡선이 없다.** 곡선이 출력축 토크이고 기어 손실은 그 안에 들어 있다고 본다.
- **전류 모델은 데이터시트 두 점을 이은 직선이다.** 전류는 명령 방향의 토크로 정하고 제동 토크는 전류를 더하지 않는다(무부하 전류만, 회생 없음). 끌려 도는 구간은 직선대로 정지 전류보다 크다. PWM은 평균으로만 본다.
- **곡선 밖은 직류 모터의 직선이다.** 데이터시트가 말하는 것은 곡선의 범위(정지~무부하)뿐이고, 제동과 끌려 도는 구간의 토크는 그 직선을 연장한 모델이다(직류 모터의 물리이지 인용 값이 아니다).
- **배터리 전압은 쓰지 않는다.** 토크 곡선은 모터 정격 전압의 것이고 배터리 `nominal_voltage`가 달라도(4S 팩 14.4 V 대 모터 12 V) 곡선을 바꾸지 않는다.
- **비틀림 스프링이 없다.** 스프링-댐퍼 부품은 축 방향(N/m)뿐이라 힌지에 걸 수 없다.
- 연속 부하 상한(`continuous_torque_limit`)으로 토크를 자르지 않는다(가열 모델이 없다).
