# 리뷰 루브릭과 머지 루프

## 루프

이슈 선택 → 브랜치 → DoD만 구현 → 자가 검증(테스트, 증거) → PR(템플릿) → CI → **GPT-6.1 Sol high 리뷰** → **omp 트리아지**(지적마다 수용·기각·이월, 근거 기록) → omp 계획 부합 점검(빈 곳 보강, DoD 밖 코드 제거) → 창업자 승인(해당 시) → squash 머지 → 이슈 닫기 → 다음.

- 리뷰어 모델: OpenRouter `openai/gpt-6.1-sol`, reasoning `high`.
- 리뷰는 최대 2회. 그 뒤에도 남은 차단 지적은 창업자에게 올린다.

## 루브릭 (항목마다 pass / concern / block, 근거는 `파일:줄`, 최대 10건, 심각도 순)

1. **계획 부합** — 대목표와 핵심 가치가 변경과 실제로 이어지는가. DoD 밖 코드가 있는가. 금지 사항을 어겼는가: AI가 판정을 선언, 물리 부품에 AI 메시, "현실과 동일" 문구, 판정 없는 영상에 판정처럼 보이는 문구, 에이전트 경로로 행성 상수·물성 변경, 독점 제품에서 나온 코드·에셋.
2. **정확성** — 단위, 좌표계, 결정론, 경계 조건.
3. **테스트** — DoD마다 단언이 있는가. 단언을 약하게 바꿨는가. 건너뛴 테스트가 늘었는가.
4. **정직성 라벨** — 새 수치의 출처 또는 값 배지(`시뮬` `인용` `기본값` `사용자 선언` `추정`). 약한 증거를 강하게 말하지 않는가.
5. **라이선스** — 에셋 원장 행, 표기 문구, 새 의존성의 라이선스.
6. **보안** — 키 노출, 입력 검증, 개인정보.
7. **디자인 부합** — 화면 변경이면 Claude Design 승인본과 일치하는가, 증거 단계·배지가 빠지지 않았는가.

리뷰어는 범위를 넓힐 권한이 없다. DoD 밖 제안은 `defer`로만 남기고, omp가 필요하면 새 이슈로 등록한다.

## 충돌 시 우선순위

법·라이선스·보안 > 핵심 가치(`docs/plan/values.md`) > 계획(`docs/plan/studio-plan.md`) > 이슈 DoD > 리뷰어 선호.

- 리뷰어가 계획의 사실 오류(물리, 라이선스, 보안)를 근거와 함께 보이면 머지를 멈추고 `type:plan-change` 이슈를 열어 창업자가 정한다.
- 판단이 갈리면 계획대로 머지하고 반대 의견을 이슈에 남긴다.

## 창업자 승인 대상

계획·핵심 가치·Go 기준 변경(`plan-change`), 단계 Go 판정, 엔진 결정, 디자인 승인본, legacy 삭제, REA 허용 목록 변경, 대외 공개(Halo 영상), CC0가 아닌 에셋과 비용이 드는 의존성·지출, 리뷰 2회 뒤에도 남은 차단 지적. 나머지는 omp가 머지하고 주간 보고한다.
