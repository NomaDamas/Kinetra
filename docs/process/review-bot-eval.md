## 한계 (정직성)

- 봇은 PR 본문, 연결 이슈, 계획 발췌, diff(생성물·바이너리·에셋 제외)만 본다. **CI 결과와 PNG 같은 에셋 내용은 보지 못한다.** #389에서 봇은 "PNG 본문은 제공되지 않았다"고 스스로 밝혔고, 원장 누락은 diff에 `assets/LEDGER.csv`가 없다는 사실로 추론했다. 실제 원장 대조는 `assets.yml`(`scripts/check_assets.py`)의 몫이다. 실제로 #389의 `assets / ledger` 체크는 실패했다([런](https://github.com/NomaDamas/Kinetra/actions/runs/42798352672)). #387, #388의 CI는 전부 초록이었다(문서와 스크립트 파일은 기존 CI가 못 잡는 결함이다). 봇은 CI를 대신하지 않고, CI가 못 보는 쪽을 본다.
- 결함이 한 PR에 하나씩 단순하게 심겨 있다. 감춘 결함, 여러 파일에 걸친 논리 오류, 대형 diff에서의 재현율은 이 시험으로 알 수 없다.
- 시험 PR 본문의 결함 은폐 문장은 내가 썼다. 실제 사람이 쓴 PR의 은폐 방식과 다를 수 있다.
- PR당 대표 실행 1회만 평가했으므로 오탐률·재현율의 수치는 내지 않는다. "3건 중 3건 지적"은 이 표본의 결과이고 일반 성능이 아니다.
