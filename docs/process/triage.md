# 트리아지 (P0-07)

리뷰(Sol 봇, 사람, 에이전트)가 낸 **모든** 지적을 머지 전에 수용·기각·이월 중 하나로 처리하고 근거를 남긴다. 처리하지 않은 지적이 있으면 머지하지 않는다(`merge-checklist.md` 7번). 루프는 `review-rubric.md`, 우선순위는 그 문서의 "충돌 시 우선순위"를 따른다.

## 절차

1. 지적마다 **코드와 증거를 직접 확인**한다. 리뷰어의 요약을 믿고 판정하지 않는다.
2. 아래 표로 PR 코멘트 하나에 모은다. 리뷰 회차마다 표를 따로 둔다(1회차, 2회차).
3. 판정은 셋뿐이다.
   - **수용**: 이 PR에서 고친다. 조치 칸에 커밋 해시를 적는다. 고친 뒤 CI를 다시 돌린다.
   - **기각**: 고치지 않는다. 근거를 적는다(계획·DoD·측정 근거 인용). 근거 없는 기각은 없다.
   - **이월**: DoD 밖의 타당한 지적이다. 이 PR에서는 고치지 않고 **새 이슈를 등록**해 번호를 적는다(`done-definition.md` 8번). 이슈 없는 이월은 기각과 같고 근거가 필요하다.
4. 표가 끝나면 리뷰와 별개로 DoD 증거를 직접 재현하고, 빈 곳을 메우고, DoD가 요구하지 않는 코드를 지운다(계획 부합 점검).
5. 리뷰는 최대 2회다. 2회차 뒤에도 `block`이 남으면 머지하지 않고 `needs-founder` 라벨로 올린다.

리뷰어에게는 범위를 넓힐 권한이 없다. DoD 밖 제안은 이월로만 남긴다.

## 양식

PR 코멘트에 그대로 복사한다.

```markdown
### 트리아지 — 리뷰 1회차 (<리뷰어>, <날짜>)

| # | 루브릭 항목 | 심각도 | 지적 (`파일:줄`) | 판정 | 근거 (직접 확인한 것) | 조치 |
|---|---|---|---|---|---|---|
| 1 | 정확성 | block | <지적 요약> | 수용 | <재현 명령과 결과> | <커밋 해시> |
| 2 | 계획 부합 | concern | <지적 요약> | 기각 | <계획·DoD 인용: 절 번호> | — |
| 3 | 테스트 | concern | <지적 요약> | 이월 | DoD 밖: <이유> | 새 이슈 #<번호> |

- 수용 <n> · 기각 <n> · 이월 <n> (합계가 리뷰어 지적 수와 같다)
- 남은 `block`: 없음 | <번호와 이유 → 창업자>
- 계획 부합 점검: <DoD 밖 코드 제거 여부, 빈 곳 보강 여부>
- 창업자 승인 대상: 아니오 | 예(<해당 항목>, 요청 링크)
```

### 판정 기준 요약

| 판정 | 조건 | 반드시 남기는 것 |
|---|---|---|
| 수용 | 지적이 맞고 DoD 안이다 | 커밋 해시, 다시 돈 CI |
| 기각 | 지적이 틀렸거나, 계획·DoD와 충돌하거나, 근거가 없다 | 반박 근거(계획 절, DoD 항목, 실행 결과) |
| 이월 | 지적이 맞지만 DoD 밖이다 | 새 이슈 번호 |

## 계획과 리뷰어가 부딪칠 때

- 범위를 넓히자는 제안: 기각하거나 이월한다.
- 리뷰어가 계획의 **사실 오류**(물리, 라이선스, 보안)를 근거와 함께 보였다: 머지를 멈추고 `type:plan-change` 이슈를 열어 창업자가 정한다. 코드가 계획에서 조용히 벗어나지 않는다.
- 판단이 갈린다: 계획대로 머지하고 반대 의견을 이슈에 남긴다(표의 기각 근거에도 적는다).
- 우선순위: 법·라이선스·보안 > 핵심 가치(`values.md`) > 계획(`studio-plan.md`) > 이슈 DoD > 리뷰어 선호.

## 창업자 승인 대상

원본은 `review-rubric.md`의 "창업자 승인 대상"이다. 여기 목록이 다르면 루브릭이 이긴다. 해당하면 `needs-founder` 라벨을 달고 승인 기록(링크)이 있어야 머지한다. 나머지는 omp가 머지하고 주간 보고한다.

| 창업자가 정한다 | omp가 머지하고 주간 보고한다 |
|---|---|
| 계획·핵심 가치·Go 기준 변경(`plan-change`) | 내부 구현, 테스트, 인프라 |
| 단계 Go 판정 | DoD 안의 UI 변경 |
| 엔진 결정(`docs/decisions/engine.md`) | 문서 정리 |
| 디자인 승인본 | CC0 에셋 |
| legacy 삭제 | 필수 검사 추가 등 보호 규칙을 **강화**하는 변경 |
| REA 허용 목록 변경 | |
| 대외 공개(Halo 영상) | |
| CC0가 아닌 에셋, 비용이 드는 의존성·지출 | |
| 리뷰 2회 뒤에도 남은 차단 지적 | |
| 보호 규칙을 **약화**하는 변경(필수 검사 제거, 관리자 예외, squash 외 머지 허용) | |

마지막 행은 이 문서(P0-07)가 더한 항목이다. 루브릭 원문에 없으므로 루브릭 쪽 반영은 창업자가 정한다.

## 주간 보고

매주 금요일 시연에서 그 주 머지한 PR의 트리아지 표를 모아 보고한다: PR 수, 지적 수, 수용·기각·이월 비율, 새로 등록한 이월 이슈, `needs-founder` 대기 목록.
