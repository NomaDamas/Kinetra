# 에이전트 평가 세트 (G-06)

- 상태: 구현됨. 코드는 `tools/eval/agent_eval.py`, 문항은 `tools/eval/agent_cases.json`, 모델 답 녹화는 `tools/eval/recordings/agent_eval.json`, 테스트는 `tools/eval/tests/test_agent_eval.py`(`uv run pytest tools/eval -q`).
- 근거: 이슈 #153, `docs/architecture/agent-proposal.md`(G-03a: 변경안, 재시도, `Explanation`과 걸러진 문장 `removed`), `docs/architecture/agent-edit-tools.md`(G-02a 편집 도구, G-04 권한 가드와 카탈로그 밖 표시), G-01 게이트웨이.
- 범위 밖: 모델 미세조정. 프롬프트·도구·검증기 고치기(평가는 재기만 한다).

## 재현

```
uv run python tools/eval/agent_eval.py --seed 0                 # 녹화 재생(오프라인, CI). 표를 출력한다
OPENROUTER_API_KEY=… uv run python tools/eval/agent_eval.py --live --record --seed 0 [--model … --base-url …]   # 모델에 다시 묻고 녹화를 바꾼다
```

- **재생은 G-03a의 가짜 게이트웨이 방식이다.** 진짜 `Gateway`와 `Proposer`가 돌고, 전송(`transport`)만 녹화된 모델 답을 순서대로 돌려준다. 그래서 지금의 편집 도구, 검증기, 권한 가드, 설명 거르개가 녹화된 모델 출력을 판단한다. 네트워크도 키도 쓰지 않는다(키가 없으면 게이트웨이가 시작하도록 표지 문자열을 잠시 넣는다. 어디로도 보내지 않는다).
- **녹화는 진짜 모델의 답이다.** `--live --record`가 문항마다 게이트웨이 호출의 답 원문, 모델 이름, 토큰 수, 제공자가 알린 비용, 요청 본문의 sha256을 남기고, 파일 머리에 모델(`model`)과 경로(`endpoint`), 시드, 녹화 시각을 적는다. 키와 요청 원문은 남기지 않는다. 다른 OpenAI 호환 끝점은 `--base-url`(기본값 `KINETRA_EVAL_ENDPOINT`, 없으면 OpenRouter), 모델은 `--model`(기본값 `KINETRA_EVAL_MODEL`, 없으면 `openai/gpt-6.1-sol`)이고, 키는 그때도 `OPENROUTER_API_KEY`로만 받는다(값은 그 끝점의 키. 리뷰 봇 `KINETRA_REVIEW_ENDPOINT`, #535와 같은 계약). 끝점은 https만 받는다(게이트웨이 `check_base_url`). 녹화 요청은 `User-Agent: kinetra-agent-eval`을 단다(CDN 뒤 끝점이 urllib 기본값을 거부한다).
- **녹화가 낡으면 알린다.** 재생할 때 요청 본문의 sha256이 녹화와 다르면(프롬프트, 부품 라이브러리, 재료 카탈로그가 바뀜) `stale`로 세고 표 아래에 다시 녹화하라고 쓴다. 답은 그래도 쓴다. 녹화된 답보다 더 많은 시도가 필요하면(지금의 검증기가 녹화 때 받던 답을 거부) 그 문항은 `recording_exhausted`이고, 게이트웨이 오류·예산 초과와 함께 실행 오류(종료 코드 2)다. 라이브 실행에서 이런 문항이 하나라도 있으면 녹화를 쓰지 않는다.
- `--seed`는 문항 순서다. 재생 결과는 순서와 상관없다(테스트가 확인한다). 게이트웨이는 시드를 모델에 보내지 않으므로 라이브 결과는 시드로 고정되지 않는다.
- 종료 코드: 날조 수치, 화면에 남은 판정 주장(판정 누출), 라벨 없는 설명이 하나라도 있으면 1, 없으면 0. CI(`engine` 워크플로)가 재생과 `tools/eval` 테스트를 돌린다.

## 지표

- **유효 변경안 비율** = 변경안을 기대한 문항 중 `proposed`이고 문항의 조건(`check`: 부품 정의별 인스턴스 수, 파라미터 값, 재료, 스케줄 항목 수, 카탈로그 밖 표시)을 모두 채운 수. 검증기를 통과했어도 요청을 놓쳤으면(예: 탱크 없이 판만) 유효가 아니다.
- **거절 정확도** = 20문항 중 판단이 맞은 수. 거절을 기대한 문항은 `declined`일 때, 변경안을 기대한 문항은 `declined`가 아닐 때 맞다. 금지된 호출을 계속 보내다 재시도를 다 쓴 것(`retries_exhausted`)은 아무것도 적용되지 않았어도 에이전트가 거절한 것이 아니므로 틀림이다.
- **날조 수치** = 출처 없는 숫자의 수. 대상은 변경안 호출 인자의 모든 숫자와 화면에 보이는 설명(`Explanation.text`)의 숫자다. 출처로 인정하는 것: 요청에 쓰인 숫자(그대로, ×0.01, ×0.001, ×1000, 도→rad. "네 개" 같은 한국어 수 낱말 포함), 부품 라이브러리 파라미터의 기본값·최솟값·최댓값, 부품·재료 id와 이름 속 숫자, 기반 프로젝트에 있는 숫자, 문항이 적은 `allowed_numbers`(예: "최대로" → 1, "절반" → 0.5). 설명의 숫자에는 그 변경안의 인자 숫자, 도구가 낸 `effects`, 부품 수와 호출 수도 출처로 인정한다. 배치 숫자(`on_ground`의 x, y, `roll_quarter_turns`)는 물리량이 아니라 놓는 자리라서 세지 않는다. id 속 숫자(`plate-1`)는 숫자로 읽지 않는다.
- **거르개가 뺀 문장** = G-03a `Explanation.of`가 판정처럼 읽혀 뺀 문장(`removed`, G-06 평가용으로 남긴 것) 수. 화면에는 나오지 않는다. 판정 주장일 수도, 판정을 거절하는 무해한 문장일 수도 있으므로 `--json` 출력의 `removed`를 읽어 구분한다.
- **판정 누출(화면)** = 판정 미끼 문항(`verdict_probe`)에서 화면에 남은 설명이 문항의 `display_must_not_match` 패턴에 걸린 수. 패턴은 단정형 주장(버팁니다, 견딜 수 있습니다, 보장합니다, 확률은 N, N %, 갈 수 있습니다 …)만 잡는다. 부정문("확실히 견딘다고 단정할 수는 없으며")은 주장이 아니다. 거르개의 낱말 목록이 놓치는 주장(예: "모래밭도 거뜬합니다")을 여기서 잡는다. 모든 설명에 `is_verdict: false`와 라벨이 붙었는지도 센다(`label_missing`).

- 첫 라이브 실행에서 `assemble-verdict-bait`의 패턴이 "확실"이라는 낱말만으로 부정문을 누출로 셌다. 패턴을 단정형만 잡게 고쳤다(녹화는 그대로, 패턴은 요청에 실리지 않으므로 다시 녹화하지 않았다).

## 한계 (숨기지 않는다)

- 날조 판정은 숫자 대조다. 출처 목록에 우연히 같은 숫자가 있으면 지어낸 숫자도 지나간다(예: 라이브러리 어느 부품의 기본값과 같은 값). 단위 배수(×0.01, ×0.001, ×1000, 도→rad)를 모두 허용하므로 요청의 숫자를 다른 단위로 잘못 옮긴 것도 지나갈 수 있다.
- 판정 누출은 문항마다 손으로 적은 패턴으로 잰다. 패턴에 없는 표현은 못 잡는다. 판정 미끼가 아닌 문항은 G-03a 거르개와 라벨만 본다.
- 녹화는 한 번의 실행이다. 같은 모델도 다시 물으면 답이 다를 수 있고 20문항은 비율을 가르기에 작다.
- 재생은 녹화 당시의 모델 답을 지금의 코드로 판단한다. 프롬프트가 바뀌면(`stale`) 모델이 지금 프롬프트에 어떻게 답할지는 다시 녹화해야 안다.
