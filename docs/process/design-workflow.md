# 디자인 절차서: 브리프 → `/design` → 리뷰 → 내보내기 → 커밋 (D0-01a)

화면 구현 이슈가 참조할 승인된 디자인을 만드는 단계별 절차다. 근거는 `docs/plan/studio-plan.md` 7절, 실행 기록은 `docs/decisions/design-pty.md`, 규격의 예는 `design/briefs/design-system.md`와 `design/exports/design-system/`이다.

- **대목표·핵심 가치.** G0 / V3 한 번에 100%. 이 절차가 없으면 화면 구현 이슈가 참조할 승인된 디자인을 누가 어떻게 만드는지 정해지지 않아 UI 작업 전체가 시작되지 못한다.
- 같은 결과를 두 경로로 만든다. **경로 A: 창업자가 직접.** **경로 B: omp가 PTY로.** 어느 쪽이든 입력(브리프)과 산출물(`design/exports/<화면>/`)과 승인(창업자)은 같다.

## 사실 (2026-11-10 관찰)

- `/design`, `/design-login`, `/design-sync`는 **대화형 `claude`에만** 있다. 헤드리스 `claude -p`에는 없다(`design-pty.md` 환경 절).
- claude.ai/design 독립 사이트는 2026-12-14에 닫힌다. 처음부터 Claude Code(`/design`)와 claude.ai Artifacts 경로를 표준으로 쓴다(`studio-plan.md` 7절).
- 디자인 사용량은 구현 작업과 같은 플랜 한도에 합산된다. 디자인 작업은 주 단위로 묶는다 [추정].
- 값(색, 크기 등)은 승인 전까지 모두 **[제안]**이고 값 배지로는 `기본값`이다.

## 역할

| 단계 | 경로 A (창업자) | 경로 B (omp, PTY) |
|---|---|---|
| 1. 브리프 | omp가 `design/briefs/<화면>.md`를 쓴다 | 같음 |
| 2. 붙여 넣기와 실행 | 창업자가 `/design`에 붙여 넣는다 | omp가 expect로 대화형 `claude`를 띄워 같은 프롬프트를 보낸다 |
| 3. 리뷰 | 창업자 | omp가 자가 점검과 체크리스트로 1차 리뷰, **최종 리뷰는 창업자** |
| 4. 내보내기 | 창업자 (HTML·zip 또는 Handoff) | omp가 Claude Design의 출력에서 회수 |
| 5. 커밋 | omp가 받은 파일을 PR로 커밋 | omp |
| 6. 승인 | **창업자** | **창업자** (omp가 대신하지 않는다) |

승인은 `docs/process/review-rubric.md`의 창업자 승인 대상이다. 승인 코멘트가 이슈나 PR에 달리기 전에는 승인본이라 부르지 않고, 내보낸 폴더의 `README.md` 맨 위에 `상태: 창업자 승인 대기`라고 쓴다.

## 경로 A: 창업자가 직접

1. **브리프를 고른다.** `design/briefs/<화면>.md`가 있는지 본다. 없으면 omp에게 요청한다(브리프는 omp가 쓴다). 브리프에는 아래 "브리프의 첫 조건"이 들어 있어야 한다.
2. **`/design`을 연다.** 터미널에서 `claude`를 실행(대화형)하고 `/design`을 친다. 저장소를 읽을 수 없는 곳(claude.ai Artifacts의 Design)이면 브리프 전문을 이어 붙인다. 시작 전에 상태 막대의 `Weekly … % left`를 본다.
3. **프롬프트를 붙여 넣는다.** 브리프의 "`/design`에 붙여 넣을 프롬프트" 블록(디자인 시스템 브리프는 11절)을 그대로 붙여 넣는다. 블록 안의 규칙을 줄이거나 바꾸지 않는다.
4. **결과를 리뷰한다.** 아래 "화면 리뷰 체크리스트"를 위에서부터 훑는다. 하나라도 `아니오`면 같은 대화에서 고치게 한다. 고친 항목과 이유를 적어 두게 한다(브리프 11절의 "바꾼 토큰과 이유").
5. **내보낸다.** 두 가지 중 하나다 [제안]:
   - 독립 HTML 또는 zip으로 내보내기 → 받은 파일을 omp에게 준다.
   - "Handoff to Claude Code"로 Claude Code 세션에 넘기기 → 그 세션이 파일을 저장소 안 `design/exports/<화면>/`에 쓰게 한다.
   내보내기 메뉴와 단추의 정확한 이름은 Claude Design이 바꿀 수 있다 [확인 필요]. 이름이 다르면 이 줄을 고친다.
6. **커밋한다.** 파일은 `design/exports/<화면>/`에 둔다. 폴더 구성은 아래 "내보낸 폴더". 창업자가 파일을 건네면 omp가 PR로 커밋한다(`design/exports/design-system/` 반입이 선례다). 원본 산출물 URL을 폴더 `README.md`에 적는다.
7. **승인한다.** 창업자가 해당 이슈나 PR에 승인 코멘트를 단다. omp는 `README.md`의 상태를 `창업자 승인됨(<코멘트 링크>)`으로 바꾸는 PR을 낸다.
8. **`/design-sync`(토큰이 저장소에 들어온 뒤).** `/design-sync`는 저장소의 디자인 시스템 컴포넌트를 claude.ai/design으로 보낸다. `/design-login`으로 claude.ai 계정 인증이 필요하다. 계정 인증이 들어가므로 omp가 대신하지 않는다. 처음 한 번 실제로 돌려 본 뒤 `design-pty.md`와 이 문서를 고친다.

## 경로 B: omp가 PTY로

자세한 실행 기록과 문제 5가지는 `docs/decisions/design-pty.md`다. 판정은 **가능(조건부)**이다. 표준 운영 절차 요약:

1. **신뢰 폴더.** 새 폴더를 만들지 않고 신뢰 대화상자를 이미 통과한 폴더(`/tmp/kin-design-probe`)를 재사용한다. 새 폴더면 `trust this folder`를 기다렸다가 아래 화살표와 Enter로 "Yes, I trust this folder"를 고른다. 브리프를 그 폴더의 `design/briefs/`에 복사해 둔다.
2. **완료 표식으로 끝을 안다.** 고정 `timeout`으로 끊지 않는다. 실행 전에 이전 `./design/exports/<이름>/DONE.json`을 지우고, 실행 id를 프롬프트에 넣어 "모든 내보내기와 자가 점검이 끝난 맨 마지막에 그 id를 담은 `DONE.json`을 쓴다"고 시킨다. expect 밖 별도 셸이 `DONE.json`의 id와 적힌 파일 존재를 폴링한다. 상한 시간에 닿으면 끊지 않고 상태를 창업자 이슈에 보고한다.
3. **내보내기 위치를 처음부터 쓴다.** "독립 HTML과 토큰 파일을 `./design/exports/<이름>/`에, 원본 `*.dc.html`과 `canvas.json`은 `source/`에 둔다". 없으면 Claude Code scratchpad에서 회수하고 회수 경로를 PR 본문에 적는다.
4. **임시 브라우저 프로필.** 프롬프트에 "브라우저 측정은 `/tmp` 아래 임시 `--user-data-dir`를 쓴 헤드리스 Chrome 또는 Chromium으로만 하고 사용자의 Chrome 프로필과 실행 중인 Chrome은 건드리지 않는다"를 넣는다.
5. **한도를 먼저 본다.** `Weekly … % left`를 읽어 로그에 남기고, 끝난 뒤 사용 포인트를 PR 본문에 적는다. 시작을 막는 문턱은 창업자가 정한다.
6. **끝난 뒤 검증한다.** 내보낸 `index.html`을 임시 프로필의 헤드리스 Chrome으로 열어 스크린샷을 찍고 브리프의 자가 점검과 아래 체크리스트를 대조한다.
7. **창업자에게 올린다.** 승인, `/design-sync`·`/design-login`, 한도 문턱은 창업자 몫이다.

**omp 경로의 시연: 디자인 시스템 v0.** 이 절차를 처음부터 끝까지 한 번 돌린 것이 디자인 시스템 v0다. omp가 PTY로 `/design`을 실행해 산출물(https://claude.ai/artifact/74qVFnKdAiuXfXJTkHSPKR)을 만들고, 회수해 `design/exports/design-system/`에 커밋했다(PR #396, 2026-11-10 병합). 창업자가 같은 날 이슈 #33에 승인 코멘트를 달았다. 다만 `design-pty.md` 시도 기록은 이 실행이 고정 시간 제한으로 끊겼고 내보내기가 저절로 일어나지 않아 scratchpad에서 회수했음을 보여 준다. 위 2~3번 단계가 그 문제를 고치려는 것이며 완료 표식(`DONE.json`) 방식은 아직 한 번도 처음부터 끝까지 시험하지 않았다.

## 브리프의 첫 조건 (창업자 지시, 2026-11-10)

창업자 지시(#33 코멘트): "있는 기능들은 모두 다 포함되어야 하는데 사용자가 보는 UI/UX는 간단해야 해. 인지부하 없게끔." 줄여 **기능은 모두, 화면은 단순, 인지부하 최소**다. 모든 화면 브리프와 `/design` 프롬프트의 **첫 조건**으로 아래를 그대로 넣는다.

```text
첫 조건: 기능은 빠짐없이, 화면은 단순하게, 인지부하는 최소로.
- 이 화면이 맡은 기능은 하나도 빼지 않는다. 빼는 것은 "보이는 양"이지 기능이 아니다.
- 기본 화면에는 주 행동 하나와 지금 필요한 정보만 보인다.
- 나머지 기능은 단계적으로 드러낸다(진행형 공개). 숨은 기능마다 어디서 어떻게 여는지(단추, 접힘, 메뉴, 단축키)를 화면에 그리고 기능 목록과 화면 위치 대응표를 함께 낸다.
```

## 화면 리뷰 체크리스트 (화면마다 필수)

화면 디자인을 승인하기 전에 위에서부터 모두 채운다. **1번은 모든 화면에서 필수이고 생략할 수 없다.** 1번이 `아니오`면 나머지가 맞아도 승인하지 않는다. 결과는 창업자 승인 코멘트나 폴더 `README.md`에 항목 번호와 함께 적는다.

1. **창업자 지시: 기능은 모두, 화면은 단순, 인지부하 최소.** 아래 네 가지를 모두 확인한다.
   1. 이슈·브리프가 정한 기능이 하나도 빠지지 않았다(기능 목록 ↔ 화면 위치 대응표에 빈 칸이 없다).
   2. 기본 화면에 주 행동이 하나이고(강조색 `primary` 버튼 한 개) 지금 필요한 정보만 보인다.
   3. 나머지 기능은 진행형 공개로 닿는다. 숨은 기능마다 여는 방법이 그려져 있다.
   4. 한눈에 읽힌다: 한 화면에 선택지, 수치, 경고를 한꺼번에 늘어놓지 않았다. 처음 보는 사람이 첫 행동을 물어보지 않고 고를 수 있다.
2. **상태 목록.** 브리프의 상태(빈 화면, 로딩, 오류, 엔진 오프라인, 해당 화면의 판정 4종)가 모두 그려져 있다.
3. **정직성 표시.** 증거 단계(L0~L3)와 값 배지 5종이 빠지지 않았다. 모든 수치에 단위와 배지가 있다. L1을 판정이라 부르지 않는다. 증거 색이 성공·실패를 뜻하지 않는다.
4. **금지 문구.** "현실과 동일", "검증됨", "보장", 에이전트가 판정을 선언하는 문구가 없다(`design/briefs/design-system.md` 9절).
5. **토큰.** 색, 간격, 글꼴이 디자인 시스템 토큰이다. 새 값이 있으면 목록으로 보고돼 있다.
6. **접근성.** 글자 대비 4.5:1, 비문자 3:1, 보이는 포커스 링, 키보드 조작, 누르는 영역 24×24 px 이상, 움직임 줄이기 대응.
7. **출처.** 산출물 URL과 만든 방법(경로 A 또는 B), 회수 경로, 사용한 한도가 폴더 `README.md`와 PR 본문에 있다.

## 내보낸 폴더

`design/exports/<화면>/` 하나가 승인 단위다. 본보기는 `design/exports/design-system/`이다.

| 파일 | 내용 |
|---|---|
| `README.md` | 맨 위 `상태: 창업자 승인 대기` 또는 `창업자 승인됨(링크)`. 산출물 URL, 만든 경로(A/B), 파일 표, 고친 곳, 알려진 불일치, 체크리스트 결과 |
| `index.html` | 독립 실행 HTML 한 파일. 구현 대조(D0-04)의 기준 렌더다 |
| `preview.png` | `index.html`을 임시 프로필 헤드리스 Chrome으로 찍은 스크린샷 |
| `source/` | Claude Design 원본(`*.dc.html`, `canvas.json` 등). 있을 때만 |
| `tokens.*` | 토큰 파일. 디자인 시스템 폴더에만 있다 |
| `DONE.json` | 경로 B의 완료 표식(실행 id, 파일 목록). 있을 때만 |

내보낸 파일은 고치지 않고 그대로 커밋한다. 고쳐야 하면 고친 곳과 이유를 `README.md`에 전/후로 적는다(`design-system` 폴더의 "고친 정직성 문구" 절이 본보기).

## 승인 뒤: 구현과 대조

화면 구현 PR은 본문 "디자인 승인본" 칸에 `design/exports/<화면>/` 경로를 쓴다(`.github/pull_request_template.md`). 구현을 승인본과 자동으로 비교하는 절차는 D0-04(#40)가 이 문서에 덧붙인다.
