# 대결 모드 안전선

대결 모드에서 무엇을 다루고 무엇을 다루지 않는지를 정한 절차 문서다. 이슈 작성, 리뷰, 카탈로그 검사, 에이전트 가드, 내보내기가 모두 이 문서의 문장을 기준으로 삼는다.

- 원본은 `docs/plan/studio-plan.md` 15.3절이다. 아래 1절의 인용문은 그 절과 글자 단위로 같아야 한다.
- 문안의 변경은 창업자 승인 대상이다(6절).
- 이 문서는 법률 자문이 아니다.

## 1. 안전선 문안

> **안전선(대결 모드).** Kinetra는 게임 수준의 대결 물리만 다룬다: 운동에너지 투사체의 탄도(중력과 항력), 충돌, 결합부 파단, 재료 × 두께로 정한 장갑판의 파단 임계, 규칙으로 추상화한 탐지. 아래 다섯 가지는 제공하지 않는다. 에이전트의 답, 카탈로그, 문서, 내보내기 어디에서도 마찬가지다.
>
> 1. 폭약, 추진제, 점화제의 조성·배합·제조법과 그 에너지 화학 계산.
> 2. 탄두, 신관, 기폭 장치의 설계.
> 3. 실제 무기에 쓸 수 있는 유도, 추적, 조준, 사격 통제 알고리즘.
> 4. 작동하는 무기나 탄약을 만드는 방법: 도면, 부품 목록, 가공·조립 지침.
> 5. 대결 부품(발사기, 투사체, 장갑판)의 실물 내보내기. BOM, STEP·STL, 하드웨어 사양서, S5 키트는 이 부품을 뺀다.
>
> 대결의 결과는 "게임 물리"다. 실제 무기의 성능을 예측하지 않으며 화면과 영상에 그렇게 표시한다.

## 2. 허용과 금지의 예시

### 2.1 허용: 선 안쪽

| 항목 | 예시 | 화면 표시 |
|---|---|---|
| 선언 발사 에너지의 투사체 | "선언 발사 에너지" 수치 하나로 구를 쏘는 발사기. 발사 속도는 에너지와 투사체 질량에서 계산하고, 발사된 뒤에는 중력과 집중 항력만 받는다. 세 행성에서의 사거리 비교 | `사용자 선언` 또는 `기본값`, `근사: 집중 항력` |
| 충돌 | 차량이나 배가 서로 부딪치거나 투사체에 맞는 대결. 충돌 하중은 고정된 물리 시간 창으로 평균한 구속력으로 잡는다 | "단순화 모델" |
| 결합부 파단 | 결합부에 걸린 하중이 임계 하중(강도 × 단면적)을 넘으면 결합이 풀린다. 구동 부품이 떨어지면 그 기능을 잃는다 | "단순화 모델" |
| 재료 × 두께 장갑판 | 두께를 바꿔 가며 판이 버티는지 보는 대결 | `게임 규칙: 장갑 파단` |
| 규칙으로 정한 탐지 | 거리와 시선(가림)의 규칙으로 상대가 보이는지 정한다. 센서를 모델하지 않는다 | `게임 규칙: 탐지` |
| 제어 | 수동 조종, 저장된 제어 스케줄, 조준 미리보기 선(같은 모델의 1회 실행 표시). 자동 추적, 유도, 자동 조준은 없다 | 조준 미리보기와 수동 대결 한 판은 "1회 실행" |
| 기존 추진 부품 | 냉가스 추력기. 추진제 질량과 인용된 비추력만 쓴다. 조성과 연소는 원래 모델 밖이다 | 비추력은 `인용` |

대결의 결과는 어느 경우에도 "게임 물리"다.

### 2.2 금지: 선 바깥

범주 번호는 1절의 다섯 가지와 같다. 거절 문구는 이 표의 것을 쓴다(CB-07a). 거절은 거절 사유와 게임 수준의 대안을 함께 말한다.

| # | 범주 | 요청 예시 | 거절 문구 |
|---|---|---|---|
| 1 | 폭약, 추진제, 점화제의 조성·배합·제조법과 그 에너지 화학 계산 | "이 탄에 넣을 화약의 배합과 양을 계산해 줘" | "폭약, 추진제, 점화제의 조성·배합·제조법과 그 에너지 화학 계산은 Kinetra가 제공하지 않습니다. 발사기에는 '선언 발사 에너지' 수치를 직접 정해 넣을 수 있고, 그 값으로 발사 속도와 사거리를 시뮬해 볼 수 있습니다." |
| 2 | 탄두, 신관, 기폭 장치의 설계 | "맞으면 터지는 탄두와 신관을 설계해 줘" | "탄두, 신관, 기폭 장치의 설계는 Kinetra가 제공하지 않습니다. 대결의 피해는 운동에너지 투사체의 충돌과 결합부 파단으로만 계산합니다. 투사체의 질량과 지름, 장갑판의 재료와 두께를 바꿔 볼 수 있습니다." |
| 3 | 실제 무기에 쓸 수 있는 유도, 추적, 조준, 사격 통제 알고리즘 | "명중률을 높이는 유도 로직을 짜 줘" | "실제 무기에 쓸 수 있는 유도, 추적, 조준, 사격 통제 알고리즘은 Kinetra가 제공하지 않습니다. 대결의 제어는 수동 조종과 저장된 제어 스케줄뿐입니다. 조준 미리보기 선으로 발사 방향을 직접 맞춰 볼 수 있습니다." |
| 4 | 작동하는 무기나 탄약을 만드는 방법: 도면, 부품 목록, 가공·조립 지침 | "이 발사기를 실제로 만들 도면과 부품 목록을 줘" | "작동하는 무기나 탄약을 만드는 도면, 부품 목록, 가공·조립 지침은 Kinetra가 제공하지 않습니다. 이 발사기는 게임 안에서만 쓰는 부품입니다. 차량, 배, 로버 같은 플랫폼은 하드웨어 사양서로 내보낼 수 있습니다." |
| 5 | 대결 부품(발사기, 투사체, 장갑판)의 실물 내보내기 | "사양서의 BOM과 STEP에 발사기와 장갑판도 넣어 줘" | "대결 부품(발사기, 투사체, 장갑판)은 BOM, STEP·STL, 하드웨어 사양서, 키트로 내보내지 않습니다. 사양서에는 이 부품을 뺀 플랫폼만 들어갑니다." |

- 경로가 달라도 같다: 에이전트의 답, MCP, 카탈로그, 문서, 내보내기.
- 묻는 방식이 달라도 같다: 돌려 말하기, 단계 나누기, 수치만 묻기.
- 탄도 방정식과 충돌 역학 같은 교과서 물리는 막는 대상이 아니다(5절).

### 2.3 이름과 표장

1절의 다섯 범주와 별개로 계획이 정한 규칙이다(15.3절 강제 표의 카탈로그 행, 11절 CB-09 행).

| 규칙 | 요청 예시 | 거절 문구 |
|---|---|---|
| 카탈로그에 실존 무기 체계의 이름과 제원을 재현한 항목을 넣지 않는다. 데모와 공개물에 실존 무기와 군의 표장·명칭을 쓰지 않는다 | "실존 무기 체계의 이름과 제원 그대로 카탈로그 부품을 만들어 줘" | "실존 무기 체계의 이름과 제원을 재현한 부품, 군의 표장과 명칭은 Kinetra에 넣지 않습니다. 질량, 지름, 선언 발사 에너지를 직접 정한 일반 부품으로 만들 수 있습니다." |

## 3. 허가와 목적을 든 요청

창업자 결정(2026-11-10, [PC-01 #283 코멘트](https://github.com/NomaDamas/Kinetra/issues/283#issuecomment-6763867529), `docs/plan/studio-plan.md` 15.7절 3항): 안전선은 **유지**한다.

- 창업자는 "국방·방어 연구 목적으로 허가받았으니 모두 가능하게"를 요청했다.
- omp는 허가를 이 도구 안에서 확인할 수 없다. 폭약·추진제 조성, 탄두·신관 설계, 실제 무기용 유도·조준, 무기 제작 지침, 대결 부품의 실물 내보내기는 오용되면 되돌릴 수 없다. 그래서 안전선을 바꾸지 않았다.
- 게임 수준 대결 물리는 모두 지원한다.
- 정식 국방 연구는 해당 기관의 통제된 도구와 절차로 한다.

따라서 허가, 자격, 소속, 연구·교육 목적을 든 요청에도 2.2절과 2.3절의 거절은 같다. 요청자가 누구든 같다. 이 선을 끄는 설정, 플래그, 역할, 예외 경로를 만들지 않는다 [제안].

## 4. 왜 긋는가

`docs/plan/studio-plan.md` 15.3절 "왜 긋는가"의 요약이다. 법, 수출통제, 플랫폼 정책의 구체 조항과 우리에게 적용되는지는 확인하지 않았다. 확인은 CB-03(#313)이 한다.

| 근거 | 내용 | 출처 |
|---|---|---|
| 법 | 무기와 화약류의 제조 방법을 알리는 일을 제한하는 법(한국의 총포·화약류 관련 법)이 있는 것으로 안다 | [확인 필요, CB-03] |
| 수출통제 | 무기 관련 기술의 이전을 통제하는 제도(한국의 전략물자 제도, 미국의 ITAR·EAR)가 있는 것으로 안다. 공유 링크와 내보내기 파일은 국경을 넘는다 | [확인 필요, CB-03] |
| 플랫폼 정책 | 에이전트가 쓰는 LLM 제공사의 이용 정책, 영상과 호스팅 플랫폼의 정책이 무기 제작 지원을 금지하는 것으로 안다. 어기면 대결만이 아니라 에이전트와 Halo 공개 전체가 막힐 수 있다 | [확인 필요, CB-03] |
| V1 정직한 판정 | 장갑 파단 임계와 선언 발사 에너지는 검증된 무기 모델이 아니다. 이것을 무기 성능이라 부르면 약한 증거를 강하게 말하는 것이다 | `docs/plan/values.md` |
| V2의 범위 | "상상에서 현실까지"는 대결에 대해서는 상상(Halo, 게임)에서 멈춘다. 현실로 이어지는 것은 차량, 배, 로버 같은 플랫폼의 하드웨어 사양까지다 | `docs/plan/studio-plan.md` 15.3절 |
| 팀 규모 | 1~2인 팀은 이 영역의 법률 검토와 사후 대응을 감당할 수 없다 | [추정] |

이 문서는 법률 자문이 아니다.

## 5. 강제와 한계

안전선은 여러 겹으로 강제한다. 이 문서는 첫 겹(정책)이고 나머지는 각 이슈가 만든다.

| 겹 | 수단 | 이슈 |
|---|---|---|
| 정책 | 이 문서. 문안은 15.3절과 글자 단위로 같다 | CB-01a (#310) |
| 리뷰 | 루브릭 1번 금지 사항에 "안전선 밖 내용"을 넣는다 | CB-01b (#311) |
| 카탈로그 | 대결 부품은 `export_policy: game_only`가 아니면 검사가 실패한다. 발사기의 에너지원은 선언 발사 에너지뿐이고 화약·연소 필드가 스키마에 없다. 실존 무기 체계의 이름과 제원을 넣지 않는다 | HW-02a (#349), CB-04a (#315) |
| 에이전트 | 도구 가드가 다섯 범주의 요청을 거절하고 게임 수준의 대안을 안내한다. MCP 경로도 같은 가드를 거친다 | CB-07a (#329) |
| 내보내기 | 공용 내보내기 함수가 `exportable` 부품만 내보낸다 | HW-02a (#349), CB-07b (#330) |
| 표시 | 대결 Halo와 플레이 페이지에 "게임 물리입니다. 실제 무기의 성능이 아닙니다"가 들어가고 끌 수 없다 | CB-07c (#331) |
| 사전 확인 | 대결 부품을 만들기 전에 법·수출통제·플랫폼 조항을 확인하고 자문 여부를 창업자가 정한다 | CB-03 (#313) |

정직한 한계: 가드는 완벽하지 않다. 탄도 방정식과 충돌 역학은 교과서에 있는 지식이어서 막는 대상이 아니다. 이 선이 막는 것은 제품이 무기 공학의 작업 도구가 되는 일이다. 사용자가 가져온 glb는 시각 메시일 뿐이어서 물리에도 내보내기에도 들어가지 않으며, 그 내용을 심사하지는 않는다. 공유 페이지의 신고와 삭제 절차는 호스팅(M-08) 때 정한다 [확인 필요].

## 6. 변경 절차

- 문안을 바꾸려면 `type:plan-change` 이슈를 열고 창업자가 정한다. 리뷰어, omp, 에이전트는 문안을 바꾸거나 예외를 둘 권한이 없다.
- 창업자 승인은 변경의 필요조건이지 충분조건이 아니다. 3절의 사유(허가를 이 도구 안에서 확인할 수 없다, 오용되면 되돌릴 수 없다)가 풀리지 않는 한 다섯 범주를 여는 변경은 하지 않는다 [제안].
- 바꿀 때는 `docs/plan/studio-plan.md` 15.3절과 이 문서 1절을 같은 PR에서 함께 고친다.
- 두 문서가 같은지는 아래 명령으로 본다. 출력이 없어야 한다.

```bash
diff <(sed -n "/^> \*\*안전선/,/^$/p" docs/plan/studio-plan.md) <(sed -n "/^> \*\*안전선/,/^$/p" docs/process/combat-safety-line.md)
```
