# "100% 완료"의 정의

하나라도 빠지면 머지하지 않는다. 원본은 `docs/plan/issues.yaml`의 `done_definition`이고 이 문서와 글자 단위로 같다.

1. 이슈 DoD 체크박스가 모두 증거와 함께 닫혔다.
2. 테스트가 있고 CI가 초록이다. 단언을 약하게 고치지 않았다.
3. 화면·시각 변경은 스크린샷이나 영상, 엔진 변경은 재현 명령과 시드가 붙었다.
4. 문서(README, docs/, 스키마)가 코드와 맞는다.
5. 에셋·의존성은 원장과 라이선스 기록이 있다.
6. TODO, 스텁, 목, 가짜 대체 경로가 없다.
7. 새 수치에는 출처나 값 배지가 있다.
8. DoD 밖에서 발견한 일은 고치지 않고 새 이슈로 남겼다.

## 쪼개기 규칙

- 잎 이슈 하나 = PR 하나. 하루(M)를 넘는 단위는 등록하지 않고 쪼갠다.
- 쪼개는 목적은 한 번에 100% 끝내는 것이다. 조각은 끝났는데 합치면 안 도는 일을 막기 위해 부모 이슈의 DoD에는 통합 시연을 둔다.
- 이슈와 PR 본문은 **대목표 → 핵심 가치 → "이것이 없으면 대목표의 무엇이 막히는가"** 를 먼저 쓰고 그다음에 세부를 쓴다(국소 최적화 방지).
