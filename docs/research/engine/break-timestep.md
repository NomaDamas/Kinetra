# 파단의 시간 간격 불변 기준: 측정 (X-10, #453)

대목표 G1 — 창업자가 세 행성 어디서든 상상한 물건을 만들어 정직한 판정이 붙은 Halo로 내보낸다. 핵심 가치 V1(정직한 판정), V3(한 번에 100%). 이 기록이 없으면 결합이 풀린 것이 구조 문제인지 수치 불안정인지 가릴 수 없다.

근거: `docs/research/benchmarks/kerbal-space-program.md` B1, B2, B3, F7 / 4.2절 ②, 7절 6번. 계획 변경 PC-02(창업자 결정 2026-11-11, #422). 구현은 `docs/architecture/break-threshold.md` "시간 간격 불변 기준(X-10)" 절.

값 배지: 이 문서의 하중·퍼센트·틱은 모두 `시뮬`(아래 머신에서 이 저장소 코드를 돌린 값)이다. 창 길이 0.02 s는 `기본값`(우리가 고른 값)이다.

## 1. 결론

1. **원래 기준 장면 3종과 임계를 유지한 고정 16 낮은 스텝 구현은 실제 `break` 이벤트 하중 차이 ≤ 10 % 기준을 충족한다.** 공개 0.002/0.001/0.0005 s의 실제 h는 0.000125/0.0000625/0.00003125 s다. 최대 차이는 낙하 `weld-tip` 3.510 %, 경사로 `seat` 1.198 %, 추력기 `w` 0.000271 %다(2.5절). 전체 틱 해제였던 이전 측정의 45.9 %·19.8 % 실패는 2.1~2.4절에 이력으로 남긴다. 임계 변경, 교차 보간, xfail로 통과시키지 않았다.
2. **측정한 모델 조건의 경계는 셋이고, 파단 틱의 임계 초과도 약한 증거로 표시한다** (3·4절). 실행이 이 조건에 걸리면 `run_ended.labels`에 "시간 간격 민감: 파단 결과가 약한 증거"가 이유와 함께 붙는다.
   - 속도: 지면에 부딪히는 블록이 **512 m/s까지 통과(6.7 %), 1024 m/s에서 실패(10.5 %)**. 코드 경계 `SPEED_LIMIT_M_S = 512`.
   - 질량비(가장 무거운 바디 / 가장 가벼운 바디): 슬라이더 끝에 부딪히는 수레 위 블록이 **4096까지 통과(4.0 %), 32768에서 실패(184 %)**. 코드 경계 `MASS_RATIO_LIMIT = 4096`.
   - 강성: 슬라이더 스프링의 $\omega\,\Delta t$($\omega=\sqrt{k/\mu}$, $\mu$는 두 쪽의 축약 질량)가 **0.776까지 통과(0.25 %), 0.896에서 실패(11.9 %)**. 코드 경계 `SPRING_LIMIT = 0.776`. 라이브러리 스프링 범위의 최대 강성 100 000 N/m(`part-spring-damper.md`)이면 축약 질량 약 0.66 kg 아래에서 이 경계를 넘는다(계산).
3. **이 장면들에서는 한 스텝의 순간 힘도 시간 간격에 따라 크게 흔들리지 않았다**(최대·최소 차이 3.0 % 이하, 2.2절). MuJoCo의 부드러운 접촉(기본 `solref` 시간 상수 0.02 s, `CONTACT_PARAMETERS`)이 충돌 충격량을 여러 스텝에 나눠 주기 때문으로 본다 [추정]. 창 평균은 그 위에 고정된 물리 시간의 충격량이라는 정의를 준다. 창이 없을 때 깨지는 경우를 이 기록에서 찾지는 못했다.

### 2.3 왜 실패하는가: 충격 상승 초입의 임계 초과

`break` 하중은 창 평균이 임계를 처음 넘은 틱의 값이고, 충격 동안 창 평균은 한 스텝에 그 스텝의 충격량 ÷ 창만큼 오른다. 그래서 임계를 넘어선 정도가 시간 간격에 따라 달라진다. 원래 낙하·경사로에서는 풀리는 결합과 시각이 가장 큰 시간 간격 한 스텝(0.002 s) 안에서 같았지만, 이벤트에 실린 하중은 45.9 %·19.8 % 달랐다. 이 차이는 풀림 여부가 아니라 샘플링한 하중 값의 차이다. 임계를 올리면 상대 초과분이 작아져 통과할 수 있으나 그것은 원래 조건의 개선이 아니라 측정 장면 변경이다.

실행은 이 조건을 `TimestepSensitivity.observe_breaks`로 검사한다. 이벤트 하중이 임계보다 10 %(`BREAK_LOAD_SPREAD_LIMIT`, [제안]) 넘게 크면 약한 증거 라벨에 `파단 하중 초과 <결합>`을 붙인다. 비교한 모든 실행의 모든 이벤트가 각 임계의 1.0~1.1배 안이면 `(최대 − 최소) / 최소 ≤ 10 %`가 보장된다. 원래 낙하는 세 시간 간격 모두, 경사로는 0.002 s에서 이 라벨이 붙는다. 경사로 0.001·0.0005 s의 초과분은 각각 약 1.8 %·7.6 %라 라벨이 없지만, 세 실행을 함께 본 19.8 % 실패를 없애지 않는다. **한 실행의 라벨 유무는 시간 간격별 비교 자체를 대신하지 않는다.**

### 2.4 채택하지 않은 회피와 필요한 결정

- **임계 교차 보간을 실제 해제 하중으로 쓰는 방법은 채택하지 않는다.** 직전 하중과 첫 초과 하중을 선형 보간해 임계 교차 `load`를 만들면 그 값은 정의상 임계와 같아서 10 % 검사가 항등식이 된다. 실제 해제 상태와 하중을 바꾸지 않으면서 수치만 통과시키는 셈이다. `BreakEvent.load`와 판정의 `measured.load_n`은 실제 해제 틱의 창 평균 하중으로 유지한다.
- **임의의 공통 관측 시각으로 비교 대상을 바꾸지 않는다.** 충격 하중이 오르는 동안에는 각 실행의 해제 시각이 다르고, 이른 실행에서는 해제 뒤 같은 결합의 하중을 더는 측정할 수 없다. 영이나 마지막 값을 늘려 비교하거나, 모두 임계 아래였던 충격 전 한 점만 골라 통과시키는 것은 원래 파단 하중 기준의 증거가 아니다. 비파단 변형의 최댓값 비교는 별도 참고 측정으로만 둔다.
- 따라서 **전체 틱 해제 모델은 원래 DoD의 실제 파단 하중 10 % 기준을 충족하지 못했다.** 기준 완화 대신 2.5절의 고정 서브스텝을 구현하고 원래 장면·임계로 다시 측정했다.

### 2.5 고정 낮은 스텝 구현과 실제 해제 하중
전체 틱 해제의 위 실패를 그대로 완료라고 하지 않고, 파단 실행은 공개 틱 Δ마다 실행 시작에 정한 16개의 같은 낮은 스텝으로 적분한다. 실제 h는 Δ/16이므로 원래 0.002/0.001/0.0005 s 요청도 0.000125/0.0000625/0.00003125 s로 1:1/2:1/4를 유지한다. 모터·추력·배터리·추진제·항력과 창 평균·해제를 모두 h에서 처리하고, 해제는 실제 교차 낮은 스텝의 `BreakWatch` 하중으로 즉시 한다. 공개 프레임과 궤적 해시는 완료한 공개 틱에서만 만든다. `platform.compute.timestep_s=h`, `substeps_per_tick=16`, `run_started.timestep_s=Δ`로 기록한다. 낮은 스텝 도중 실패하면 마지막으로 완료한 공개 틱의 모델·상태·공급·이벤트로 되돌린다.
16의 사전 근거인 0.0005 s의 32 % 초과를 선형으로 4로 나눈 8 %는 **추정이지 상한이 아니었다.** 따라서 원래 세 장면·원래 임계의 실제 해제 하중을 같은 머신에서 다시 측정했다. `test_break_timestep_scenes_break_loads_agree_within_ten_percent`의 세 인자는 xfail 없이 통과했고, 같은 `SCENES`·`TIMESTEPS`·`run`·`broken` 헬퍼로 읽은 실제 `BreakEvent.load`는 다음과 같다.

| 장면 | 결합 | Δ=0.002 s | Δ=0.001 s | Δ=0.0005 s | (최대 − 최소) / 최소 |
|---|---|---:|---:|---:|---:|
| 낙하 | `pin` | 36.495015 N | 36.481315 N | 36.484405 N | 0.037555 % |
| 낙하 | `weld-mid` | 59.149833 N | 58.965494 N | 58.939054 N | 0.357621 % |
| 낙하 | `weld-tip` | 20.655222 N | 20.541938 N | 19.954735 N | 3.510382 % |
| 경사로 | `seat` | 49.795752 N | 49.309773 N | 49.206473 N | 1.197562 % |
| 추력기 | `w` | 6.501610 N | 6.501592 N | 6.501609 N | 0.000271 % |

모든 결합이 세 요청에서 같은 집합으로 풀리고 실제 하중 차이가 10 % 이하다. 아래 속도·질량비·강성 경계는 낮은 스텝 이전 측정이다. 생산 실행의 스프링 경고에는 더 큰 공개 Δ를 써 보수성을 유지하고, 세 경계를 새 h의 수렴 증거로 쓰지 않는다.

## 3. 못 지키는 조건

모두 엔진을 직접 스텝해 쟀다(`BreakWatch`, 0.02 s 창). 시간 간격 0.002, 0.001, 0.0005 s의 창 평균 하중 최댓값의 (최대 − 최소) / 최소. 경계 양쪽 한 쌍은 테스트가 고정한다(`test_break_timestep_speed_bound`, `_mass_ratio_bound`, `_spring_bound`).

0.896 위에서는 통과와 실패가 섞인다(1.00에서 1.35 %). 코드 경계는 마지막 연속 통과 값 0.776이다.

## 4. 실행의 표시

`TimestepSensitivity`(`compiler/breaks.py`)가 임계가 있는 결합이 하나라도 있는 실행에서 질량비, 스프링, 속도를 실행 시작과 매 스텝(풀릴 결합이 남아 있는 동안) 그때의 모델로 본다(해제 뒤 다시 컴파일한 모델, 추진제가 줄어드는 질량 포함). 파단이 있으면 해제 전에 `observe_breaks`가 임계 초과분도 검사한다. 하나라도 걸리면 `run_ended.labels`에 `시간 간격 민감: 파단 결과가 약한 증거 (이유; docs/research/engine/break-timestep.md)`가 붙는다. 원래 낙하의 세 시간 간격과 경사로의 0.002 s 실행은 `파단 하중 초과`로 붙고, 나머지 기준 실행은 붙지 않는다(테스트).

## 5. 하지 않은 것과 열린 질문

- **CB-02(고속 충돌 스파이크, #312)는 [확인 필요]이다.** 이 기록을 쓴 날 이슈가 열려 있고 결과가 없다(`docs/decisions/engine.md` "CB-02 미실행"). 위 속도 측정은 지면과 슬라이더 끝 멈춤만이고 얇은 두 바디 사이의 충돌(터널링)은 재지 않았다. CB-05b는 S2에서 이 창 평균(0.02 s, `BREAK_LOAD_WINDOW`)을 다시 쓴다.
- 시간 간격을 실행 중에 바꾸는 옵션은 두지 않는다(이슈 범위 밖). 실행은 0.002 s 이하의 시간 간격 하나로 처음부터 끝까지 돈다.
- 경계 값은 위 장치들에서 잰 것이다. 다른 형상(긴 사슬, 회전 결합의 스프링, 접촉이 많은 장면)에서는 재지 않았다. 경계 안이라고 기준을 보장하지 않는다.
- FEM, 피로, 고속 투사체(CB-05a)는 범위 밖이다.
